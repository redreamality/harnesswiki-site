                Primitive：重连投影

                Theme：组合与互操作 · 成熟度：Proposed Abstraction

                重连投影由控制平面的 projector 或 replay buffer 拥有，把已有事件归约为客户端可重新消费的有界状态，使新连接能从 snapshot/cursor 过渡到在线流。这里的 replay 是状态投影，不是重新执行历史 Action。

                领域模型与契约

                契约面 最小语义
                输入 有序领域事件、可选 durable snapshot、目标客户端版本与起始 cursor
                状态 replay window、projector/schema 版本、最后覆盖位置、去重键、截断与压缩统计
                输出 snapshot 或压缩事件序列、覆盖范围、next cursor，以及 replay-to-live 切换点
                所有者 control-plane projector、sync reducer 或按 Session 分配的 replay buffer
                主要消费者 重连客户端、late subscriber、多设备同步器与只读观察端

                不变量

                • 输出必须声明覆盖的起止位置；窗口不完整时要返回显式 truncation/gap，而不是伪装成完整历史。
                • 同一 projector 版本处理同一有序输入应得到等价状态；重放不能依赖当前 wall-clock 或再次调用外部工具。
                • replay 与 live stream 的交接点必须避免不可见缺口；重复 delivery 则要有稳定 event id 或幂等归约规则。
                • chunk 合并、tool lifecycle 折叠和 transient signal 丢弃不能改变已完成 Action、审批或 Turn 的终态。
                • 旧客户端遇到影响安全或终态的未知事件时必须降级或拒绝，不能一律忽略。
                • projector 写坏派生状态时可以重建；它不得回写并篡改权威 耐久 Transcript。

                明确边界

                • 在线事件流强调当前运行的低延迟增量；重连投影强调一条新订阅怎样取得足够的过去状态。
                • 耐久 Transcript可以是 projector 的输入，但 bounded replay buffer 也可能只保存在 live control plane 中；二者耐久性不能互推。
                • 上下文压缩降低模型下一次请求的表示成本；replay compaction 降低客户端重连成本，不改变模型 token。
                • 遥测导出的 reducer 可以聚合指标，却不负责重建客户端交互状态。
                • Environment action replay 会再次执行命令或工具，需要 checkpoint、幂等性与隔离世界；它不属于本 Primitive。

                显露差异的 Situation

                Replay window 已截断，但完整 Transcript 仍存在

                客户端必须看到 history_truncated、最早可用 cursor 与完整 Transcript 是否另有入口。它可以显示 retained projection 后继续在线订阅，但不能把“当前画面足够使用”描述为“已经取得完整 Session 历史”。

                旧客户端遇到新 terminal event

                若旧 projector 把未知 terminal event 当作可忽略 UI 装饰，运行会永久停在 active。协议需要 required/ignorable 或 schema capability；无法安全归约时应请求 snapshot、升级或拒绝继续。

                各 Harness 的实现

                OpenCode

                • 状态 / 事实类型：alternative + documented
                • 研究锚点：OpenCode 画像

                OpenCode SyncEvent 采用单 writer 事件溯源：mutation 前记录事件，以全序 seq 上传，其他设备下载 log 后在本地 replay Session 投影。同步设计固定锚点 Event envelope、storage mutation 与 bus compatibility 的分工在同一固定说明中给出。事件形态固定锚点 这验证了 deterministic state projection；目标是设备同步，不是重新执行工具副作用。

                Qwen Code

                • 状态 / 事实类型：implemented + implemented/documented/observed
                • 研究锚点：Qwen Code 画像

                Qwen daemon 在每个 turn_complete/turn_error 边界压缩 replay journal：合并连续 text/thought chunk，把 tool lifecycle 折叠成最终状态并丢弃 transient signal。Compaction engine 固定源码 每个 live Session 的默认窗口为 4 MiB；超限时首项成为带 retained/truncated 计数的 history_truncated，并另行说明完整 Transcript 是否可取。Daemon lifecycle 固定说明 该 compaction 从 O(streaming tokens) 降到 O(turns)，但不减少模型 Context。

                模块级行为实测在 b4f5079dc0cc89ce1448785898ab72b358399c95 的 EventBus 中让订阅者于 cursor 2 断开；离线产生的事件 3–6 在相同 epoch 重连后按序回放，并以 replay_complete{replayedCount:4} 交接。该 observed 只覆盖事件仍在内存 ring 的路径，没有验证 ring eviction、HTTP/SSE 重连或 daemon 重启。

                Claude Code

                • 状态 / 事实类型：unknown + documented
                • 谱系计数：terminal、Desktop、IDE、web 与 mobile 是一个 Claude Code Family 的不同客户端。

                固定发布记录证明 Remote Control 能在 worker 重启后恢复 Conversation history，并让新 attachment 重新看到既有 Session。恢复与重新附着但公开材料没有 event cursor、窗口完整性、snapshot + tail、schema capability 或 live handoff 契约，因此不能把“恢复历史”升级为可核验的 Replay Projection，状态保持 unknown。

                Proposed Interface

                不同实现可以用事件 log、snapshot 或两者组合，但消费者至少需要一个小而完整的 Interface：

                project 隐藏 chunk 合并、tool folding、snapshot 选择和去重细节；Interface 仍必须暴露完整性与版本失败，不能用一个可空 events 数组吞掉这些语义。

                限制、反例与未决问题

                • 把当前数据库表 dump 给客户端是 snapshot transfer；只有它声明事件覆盖位置并能无缝接上 live stream，才构成重连投影。
                • Codex rollout trace 的 offline reducer 生成诊断语义图，消费者和保真目标不同，不应据此声称 app-server 具有断线 replay cursor。
                • replay buffer 可以在进程重启后丢失；若产品仍宣称跨重启恢复，就必须另接耐久 Transcript 或 snapshot store。
                • projector schema migration、snapshot 与 event 的原子切换、多个 projection 版本并存，以及 backpressure 下的窗口驱逐仍无共同契约。
                • Qwen 与 Gemini 的继承机制不能算两份独立证据；本页只把 Qwen 分化出的 daemon replay 作为一个 Implementation。
