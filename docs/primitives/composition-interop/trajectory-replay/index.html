                  协调指南：运行记录与回放边界

                  Theme：组合与互操作 · 本页协调五个独立 Primitive，不定义第六种统一记录

                  Harness 会把同一次运行表达成多种记录。它们可以共享 Session、Turn、Action 等 identity，也可以互相派生，但各自拥有不同的 producer、owner、consumer 与保真目标。“都含事件”不意味着能够互换，“可以 replay”也不意味着可以重新执行副作用。

                  五类记录及所有权

                  记录 Producer Owner 主要 Consumer 保留与保真目标
                  耐久 Transcript Session 接受的消息、Action/Observation 与生命周期事实 Session persistence layer resume、fork、Context builder、审计 跨进程保留可恢复事实，暴露缺口与 schema 失败
                  在线事件流 live Agent、模型流、工具运行时、control plane live runner/control plane 当前 UI、IDE、SDK host、controller 低延迟和细粒度；临时信号可以不是耐久事实
                  重连投影 projector 对 event/snapshot 的归约 replay buffer/sync projector reconnecting client、late subscriber、多设备同步器 有界地重建客户端状态，必须声明 cursor 与截断
                  遥测导出 instrumentation 与 signal adapter observability provider/exporter operator、OTel collector、分析后端 可采样、聚合和脱敏，追求诊断而非恢复完整性
                  评测 Trajectory evaluation recorder/adapter evaluation pipeline/dataset writer evaluator、trainer、reviewer 保留 task、Action/Observation、anchor 与 outcome 的可比较样本

                  所有者是能决定记录何时成立、何时丢弃以及怎样报告失败的 Module。producer 只发出候选事实，consumer 也不能反过来修改 source-of-truth。

                  派生关系，不是替代关系

                  flowchart LR
    Loop["Agent / Tool Runtime"] -->|append accepted facts| Durable["耐久 Transcript"]
    Loop -->|publish incremental state| Live["在线事件流"]
    Durable -.->|snapshot / ordered facts| Projector["Replay Projector"]
    Live -.->|bounded journal| Projector
    Projector --> Replay["重连投影"]
    Loop -.->|instrument| Exporter["Telemetry Exporter"]
    Durable -.->|selected facts| Exporter
    Exporter --> Telemetry["遥测记录"]
    Durable -.->|adapt Action / Observation| Recorder["Evaluation Adapter"]
    Loop -.->|task + environment anchor| Recorder
    Recorder --> Evaluation["评测 Trajectory"]

                  虚线表示可选派生，并非每个 Harness 都必须走同一管道：telemetry 可以直接从 runtime instrumentation 产生；replay buffer 可以只活在 control plane；evaluation recorder 也可以在 Step 结束时直接写样本。无论路径怎样，派生记录都应保留 source identity 和转换版本。

                  协调不变量

                  • 一个事实只能由其 owner 确认。UI 收到 tool_completed 不能替 Session store 确认 durable append，collector 收到 span 也不能替 evaluator 确认 task passed。
                  • 派生记录必须引用 source run 与覆盖范围；转换、压缩、sampling 或 redaction 后不得冒充原记录。
                  • 下游失败不能倒写上游事实。telemetry export 或 dataset finalize 失败，不会把已执行 Action 变成未执行。
                  • 上游缺口必须向依赖它的下游传播。Observation 未持久化时，replay/evaluation adapter 不能合成成功终态。
                  • 投影 replay 与行动 replay 必须使用不同命令和结果类型；前者只归约状态，后者创建新 Run 并产生新副作用。

                  关联键

                  五种记录不需要共享同一 envelope，但跨记录关联至少要能表达以下 identity：

                  Key 谁分配或确认 作用 缺失后果
                  Session identity Session owner/control plane 连接持续交互、Transcript、projection 与样本 不同对话可能被误合并
                  Run/Turn/Step identity runtime topology 确定一次推进和模型决策边界 cancel、cost 与 terminal 无法归属
                  event id / seq / cursor 各记录 owner 排序、去重、声明覆盖位置 重连产生缺口或重复状态
                  parent / causation id producer + durable owner 表达分支、并行和派生因果 wall-clock 排序伪造路径
                  Action/tool-call identity tool runtime 连接 accepted Action、增量与 Observation 失败或副作用无法审计
                  artifact/content reference artifact owner 引用大输出、附件、diff 与脱敏替身 display text 与真实 payload 脱节
                  schema/producer version record owner 选择 decoder、projector 与 migration 未知事件可能被静默误读
                  environment anchor execution/evaluation owner 解释工作区、镜像、工具与外部状态 行动重放和结果比较失去语义

                  不要求把这些 key 全塞进每条 token chunk。可以通过父对象继承，但导出或拆分记录时必须物化足够上下文，使页面和 artifact 自包含。

                  保真度不能排成单一高低

                  记录 允许损失 不能损失
                  耐久 Transcript display-only progress、可重建 cache 恢复所需事实、顺序/分支、必需 schema
                  在线事件流 是否跨连接保留由别的 Primitive 决定 当前运行的 correlation、控制请求与 terminal 语义
                  重连投影 token chunk 合并、transient signal、窗口外细节 完整性标记、最终 tool/Turn 状态、replay-to-live 交接点
                  遥测导出 sampling、aggregation、content redaction signal schema、单位、correlation 与丢弃/export 状态
                  评测 Trajectory UI 增量、与 task 无关的显示细节 task/run anchor、Action/Observation、outcome 与 adapter version

                  因此“Transcript 最完整”也不是普遍真理：它可能足以恢复模型历史，却不含 telemetry 的 runtime metric，也不含 evaluator 事后产生的 score。保真度必须相对 consumer 说明。

                  两个端到端 Situation

                  工具运行时客户端断线并重连

                  sequenceDiagram
    participant H as Harness Runtime
    participant D as Durable Transcript
    participant L as Live Stream
    participant P as Replay Projector
    actor C as Client

    H->>D: append Action accepted
    H-->>L: tool/start + correlation
    L-->>C: incremental updates
    C-xL: disconnect
    H->>D: append Observation + terminal
    H-->>L: tool/terminal
    P->>D: read facts after covered cursor
    P->>L: read retained live journal（可选）
    C->>P: reconnect(afterCursor, clientSchema)
    P-->>C: snapshot/events + completeness + liveHandoff
    L-->>C: subsequent live events

                  如果只有 live event 而没有 durable result，projector 必须声明窗口和不确定性；如果 durable result 完整但 replay window 截断，客户端可以得到正确终态，却仍不能声称拿到了全部 token 增量。telemetry export 失败不应阻塞这条恢复路径。

                  从 fork 后的 Session 生成 benchmark 样本

                  adapter 先选择明确 branch leaf 与 source Session，再关联 task、Harness/model/tool 配置和 workspace/environment anchor。它只导出该路径上的 Action/Observation，并把 evaluator score 作为派生结果。原分支、fork 分支和行动重放产生的新 Run 必须使用不同 identity；否则同一个 Action 看似同时拥有多个 Observation。

                  失败传播

                  起点 本地处理 必须传播给谁 不应影响什么
                  durable append 失败 标记 Session 不可恢复或中止需要耐久保证的推进 replay/evaluation consumer、当前控制端 不得补造已写入事实
                  live delivery/backpressure 丢弃可丢更新、淘汰订阅或终止连接，并留下可观察 gap 当前 client、replay handoff 已确认的 Session/Action 事实
                  replay window 截断 返回 truncation 与覆盖范围，必要时指向完整 Transcript reconnecting client 正在运行的 Agent
                  telemetry queue/export 失败 按策略 buffer/drop/retry 并记录 exporter health operator 业务 Action terminal 与 evaluator outcome
                  evaluation finalize 失败 保留 source run，重试 adapter 或标记 partial sample benchmark runner/reviewer 原 Transcript 与工作区结果
                  未知必需 schema 拒绝 decode/project，或显式迁移 对应 consumer 与 operator 原始耐久 bytes/artifact

                  DeepSeek Harness 的固定行为实测给出两个具体终态：未闭合的 durable tool call 被合成为 TOOL_OUTCOME_UNKNOWN，原 Turn 以 interrupted 闭合且工具不重放；更高日志版本或未知 required event 则拒绝投影并保留 raw log 路径。完整事件序列与 snapshot golden 这说明“补一个未知 Observation 后继续”与“schema 无法解释而拒绝”是两种不同的恢复决策。

                  Replay 词汇表

                  所谓 replay 实际动作 是否重新产生副作用 所属页面
                  Transcript rebuild 从耐久事实重建模型可见历史 否 耐久 Transcript
                  Client/state projection replay 对 event/snapshot 运行 projector 否 重连投影
                  Diagnostic reduction 从 logs/traces/raw bundle 生成诊断视图 否 遥测导出或实现专有诊断工具
                  Environment action replay 在新或已验证环境再次执行 Action 是 执行环境与工作区事务
                  Evaluation rerun 用同一 task/config 启动新 Run 并重新评分 是 评测 Trajectory的 consumer

                  “支持 replay”必须至少选择表中的一行，并说明环境与输出 identity；一个布尔字段无法表达这些差异。

                  反例与未决问题

                  • 同时写 UI event、OTel span 和 .traj 文件的一个函数不意味着三者应共享 owner；这往往只是在调用点耦合了三个独立失败域。
                  • content-addressed payload 可以减少复制，但不能替代各记录自己的 redaction、retention 与访问控制。
                  • durable seq、SSE event id、trace id 和 evaluation step index 是否需要一一对应，目前证据不足；通常稳定映射比强制同值更实际。
                  • 跨 schema migration、分布式 clock、并行子 Agent 因果图、数据删除传播与 artifact garbage collection 尚无统一 Interface。
                  • 行动重放默认应使用新或已验证的 Execution World；哪些 Tool 可声明幂等，仍需具体 tool schema 与外部资源契约。
