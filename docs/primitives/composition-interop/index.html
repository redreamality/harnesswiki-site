                  组合与互操作

                  导航：首页 · 机制地图 · 领域模型

                  组合与互操作研究 Harness 内核怎样被扩展、被外部客户端控制，并把产物或运行记录交给父 Actor、用户、恢复、重连、诊断与评测系统。多个机制都可能传递“结果”或“事件”，但生产者、所有者、消费者、耐久性与允许的信息损失不同。

                  flowchart TB
    Extension["扩展与生命周期"] -->|进程内 hook / capability| Core["Harness Core"]
    Client["CLI / IDE / Host"] -->|command / event| Plane["控制平面"]
    Plane --> Core
    Core -->|append facts| Durable["耐久 Transcript"]
    Core -->|publish updates| Live["在线事件流"]
    Live -.->|compact / buffer| Replay["重连投影"]
    Durable -.->|project| Replay
    Core -.->|logs / metrics / spans| Telemetry["遥测导出"]
    Durable -.->|adapt actions / observations| Evaluation["评测 Trajectory"]
    Core -->|seal / publish| Artifact["产物交付"]
    Artifact --> Consumer["父 Actor / 用户 / CI / evaluator"]
    MCP["MCP / capability provider"] -->|tool schema / result| Core

                  Primitive

                  页面 独立状态或契约
                  扩展与生命周期 包发现、依赖、hook 顺序、取消与卸载副作用
                  控制平面与互操作协议 command、event、session addressing、cancel 与协议版本
                  耐久 Transcript Session 事实的 append、顺序/分支、schema 与读取失败
                  在线事件流 当前订阅、correlation、背压、增量与 terminal event
                  重连投影 replay window、cursor、压缩、截断与 replay-to-live 交接
                  遥测导出 signals、exporter、sampling、redaction、batch 与 retry
                  评测 Trajectory task/run anchor、Action/Observation、outcome 与 adapter schema
                  产物交付 artifact identity、provenance、locator、完整性、权限与 retention

                  协调指南

                  • 运行记录与回放边界解释五类记录怎样派生、共享 identity 并传播失败；它不是把五个 Primitive 重新包装成一个大 Primitive，也不计入 Primitive 数量。

                  选择正确的记录

                  需求 权威页面 不能顺带推断
                  把 Patch、报告或文件交给外部消费者 产物交付 最终文本声明等于稳定 Artifact
                  崩溃后重建模型历史 耐久 Transcript 工作区与进程也已恢复
                  给当前 UI 推送工具进度 在线事件流 断线后一定可补发
                  新客户端接上已有运行 重连投影 已取得完整 Session 历史
                  观察延迟、错误与成本 遥测导出 记录足以 resume 或评分
                  产出 benchmark/training 样本 评测 Trajectory Action 可确定性重执行

                  协议分层

                  • MCP 等能力协议回答“内核可以调用什么”。
                  • App Server、RPC、ACP 或 HTTP/SSE 控制面回答“客户端如何驱动内核”。
                  • Transcript、event、projection、telemetry 与 evaluation schema 分别回答“哪类运行事实由谁保存并交给谁”。

                  这些层都可能使用 request/response、JSONL 或事件流，但不能仅凭传输形式相似就视为同一 Primitive。
