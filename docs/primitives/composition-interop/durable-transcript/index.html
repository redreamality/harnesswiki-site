                Primitive：耐久 Transcript

                Theme：组合与互操作 · 成熟度：Accepted Primitive

                共识 Family：DeepSeek、Pi、OpenHands

                耐久 Transcript 是 Session 持久化层拥有的、跨进程仍可读取的交互事实源。它让 resume、fork 与 Context 构建器能够从同一组事实重建历史；它不是当前连接看到的在线事件，也不承诺恢复工作区或重新执行 Action。

                为什么独立成 Primitive

                把“保存聊天”当作一个布尔能力，会掩盖三个不同问题：哪些事实进入记录、怎样表达顺序或分支、读取者遇到缺口或未知类型时怎样失败。耐久 Transcript 对这些问题拥有独立的状态与失败模式。

                契约面 最小语义
                输入 已被 Session 接受的用户消息、模型输出、Action/Observation、生命周期边界与必要配置事实
                状态 Session identity、schema/version、有序位置、parent/branch、写入确认、payload/redaction 引用
                输出 可枚举的耐久条目、活动路径、模型可见历史投影、resume/fork 的继续点
                所有者 Session 持久化层；只有它决定一次 append 何时成为耐久事实
                主要消费者 resume/fork 协调器、Context 构建器、Transcript 导出器与审计工具

                不变量

                • 已返回“耐久写入成功”的条目必须在进程重启后仍可按同一 Session identity 读取。
                • 顺序、parent 或 source 引用必须足以区分因果路径；仅按 wall-clock 排序不能可靠表达并发和分支。
                • 模型可见投影必须能追溯到耐久条目；summary、compaction 与 display-only 条目不得伪装成原始消息。
                • 未知且必需的事件类型不能静默跳过；读取者应拒绝、迁移或显式降级。
                • fork 只能建立新的后续路径，不能覆盖原分支已经确认的事实。
                • Action 已执行但 Observation 未写入时，记录必须保留可检测的缺口；不得补造一个成功结果。

                明确边界

                • 在线事件流服务当前连接，可以包含 token chunk、进度和临时信号；除非 append 被确认，否则不能据此声称可恢复。
                • 重连投影可以从在线事件或耐久事实派生，并允许有界压缩；它不是完整 Transcript 的别名。
                • 遥测导出允许采样、聚合和字段脱敏，不应反过来成为 Session 的权威历史。
                • 评测 Trajectory把 Action/Observation 映射为评测样本；标准化派生不能改写原始运行事实。
                • 状态持久化与恢复还要协调工作区、配置和 live runtime。拥有耐久 Transcript 只覆盖其中一个恢复域。

                显露差异的 Situation

                工具已经修改文件，进程在 Observation 写入前崩溃

                重启后 Transcript 可能以已接受的 Action 结束，而工作区已经包含副作用。读取者应把它标为不确定终态，并交给恢复协调器重新观察；直接重执行命令可能重复删除、提交或发送外部请求。

                从历史节点 fork 新分支

                读取者需要明确 source Session、历史边界和新 branch/Session identity。Pi 可以在同一 JSONL 树内切换活动叶子，也可以创建新 Session；其他实现可能复制前缀。两种方式都不能自动推断工作区也已分叉。

                各 Harness 的实现

                DeepSeek Harness

                • 状态 / 事实类型：implemented + documented
                • 研究锚点：DeepSeek Harness 画像

                DeepSeek 把 append-only SessionEvent log 定义为模型历史的事实源，fork、resume、transcript、telemetry 与持久化都由此派生；live agent/* 事件属于另一事件域。架构说明固定了这一所有权。其持久化目录进一步规定 monotonic seq、JSON-serializable payload、surface/log-only 区分，以及未知必需事件必须拒绝重建而非静默跳过。目录范围 · 事件 envelope

                Pi

                • 状态 / 事实类型：implemented + documented
                • 研究锚点：Pi 画像

                Pi 把 Session 存为 JSONL；header 固定版本与 cwd，后续 entry 以 id/parentId 组成树，因此在一个文件内保留分支而不覆盖旧路径。文件格式与版本 buildSessionContext() 从活动叶子回溯，并应用 compaction checkpoint、branch summary 与消息过滤生成模型历史。树到 Context 的投影 这证明可审计历史与模型可见投影是两个对象；它不证明旧工具可以安全重执行。

                OpenHands runtime

                • 状态 / 事实类型：implemented + implemented
                • 研究锚点：OpenHands 画像

                OpenHands SDK 的 EventLog 按事件持久化 JSON，以 parent_id 表达事件树并维护 active branch。EventLog 固定源码 ConversationState.create 从持久化状态重建，并检查 agent/tool 兼容性。恢复固定源码 其 Action rerun 另有非幂等风险，因此不能把耐久事件树提升为 Execution World checkpoint。

                Loopal

                • 状态 / 事实类型：implemented + implemented
                • 谱系计数：Hub、Agent 与前端消费同一 Loopal Family 的 Session/Turn 记录，只计一次。

                Loopal 用 session.json 保存 Session metadata，并把 TurnStarted/StepAppended/StepUpdated/TurnEnded/Cleared/Rewound 逐条 append 到 turns.jsonl；关键写入可 flush + sync_data。Session create/load/update · Turn append/load 与 durabilityload 还会截断未换行的 torn tail，但不会恢复文件系统或后台进程。

                Claude Code

                • 状态 / 事实类型：implemented + documented
                • 谱系计数：本地与 Remote Control attachment 读取同一 Claude Code Family 的 Session history。

                固定发布记录说明 bridge worker 重启后会恢复 Conversation history，并区分“重新附着已有 Session”与“原 server Session 已删除后创建替代者”。Session history 恢复边界这证明耐久历史参与 resume；格式、transaction boundary、branch lineage 与迁移保证未公开。

                Antigravity CLI

                • 状态 / 事实类型：implemented + documented
                • 谱系计数：CLI 与 GUI 共用 engine，导入/恢复 Conversation 不形成第二个 Harness。

                Antigravity CLI 的固定发布记录声明 SQLite .db 将作为 Conversation 格式，并让 /resume 扫描 .db 与 .db-wal。SQLite Conversation 与恢复扫描这能确认耐久 Transcript 的产品契约；schema、写入原子性、branch lineage 与版本迁移仍未知。

                MiniMax Code

                • 状态 / 事实类型：implemented + documented
                • 谱系计数：桌面、Remote Control 与 IM 访问同一 MiniMax Code Family 的 Session history。

                官方更新日志记录历史可搜索、归档并 resume。官方更新日志（桌面 v3.0.65，快照 2026-08-19）这足以确认持久历史的可观察消费路径；存储 schema、原子性、branch lineage 与 crash-repair 保证没有公开。

                Stakpak Agent

                • 状态 / 事实类型：alternative + implemented
                • 谱系计数：服务端 Checkpoint、本地 messages.json 与 SecretManager map 属于一个 Stakpak Agent Family 的持久状态面。

                async mode 从 Session/Checkpoint 读取 messages 与 metadata，并在完成路径写入本地 messages、checkpoint id 和 secret map。远端恢复输入 · 本地 snapshot这些是可供后续读取的恢复材料，但没有 append acknowledgement、序列号、branch、schema/version migration 或 torn-tail repair；pause manifest 也不与远端 Checkpoint 原子提交，Warden state 和原工具进程不在记录内，因此保持 alternative。

                实现差异

                Harness 排序/分支 模型历史怎样产生 明确不覆盖的域
                DeepSeek monotonic seq + source refs 从 surface event 投影 live Agent、工作区
                Pi id/parentId 树 + active leaf 从路径、checkpoint 与 summary 投影 工具副作用、进程
                OpenHands parent_id + active branch 从 ConversationState/EventLog 重建 通用工作区 checkpoint

                设计策略与取舍

                可以把 Transcript 想成实验记录本：关键不只是“有没有保存”，还要看谁有权落笔、怎样标出先后与分支、半页写坏后能否辨认，以及后来的人能否知道哪些内容只是摘要。下面按这些策略路线合并同一 Family；上方每个实现的独有细节仍然保留。

                路线 代表 Harness（Family 去重） 权威记录与顺序 获得什么 牺牲什么与典型失败点 适用条件
                Schema 化事件事实源 DeepSeek Harness monotonic seq、事件类型、source ref 与 surface/log-only 一起写入 append-only log 多个消费者可从同一事实派生 Context、transcript 和 telemetry；未知必需事件可拒绝重建 projector、schema migration 和兼容规则复杂；seq 缺口或 Observation 缺失必须保留不确定状态 事件种类多、需要长期演化，并由多个 projection 消费同一事实源
                Crash-hardened append journal Loopal Session metadata 之外逐条 append Turn event；关键写入 flush + sync，加载时修剪 torn tail 格式直接、便于本地检查；进程中断留下的半条记录有明确修复办法 metadata 与 journal 可能不一致；重复 append、多 writer 和语义迁移仍需另建协议 单 owner 的本地 daemon/Hub，需要简单、可运维的长期日志
                Parent-linked 事件树 Pi、OpenHands entry/event 带 parent，active leaf/branch 指定当前路径 fork 不必复制或改写旧历史；模型 Context 与可审计全树可以分开 活动分支选择、孤儿节点、摘要血缘和垃圾回收更复杂；树仍不能证明工作区也分叉 产品把回退、fork、比较分支作为一等交互
                数据库 Conversation Antigravity CLI SQLite Conversation；公开契约只确认数据库与 WAL 参与扫描 事务存储和产品级查询能力可由数据库承载，用户不必管理日志文件 schema、branch、迁移和 crash repair 没有公开时，外部工具无法验证其保证；发现 .db-wal 不等于恢复完成 单一产品拥有写入器、查询器和升级流程，外部只消费稳定产品 API
                托管历史服务 Claude Code、MiniMax Code 产品服务保存并按 Session 搜索、归档、恢复或重新附着 多设备和远程入口可以共享历史，存储细节对用户透明 服务删除、版本变化或未公开格式会限制可移植性；“重新附着”失败时可能只能创建替代 Session 重点是跨设备连续使用，而不是让第三方直接重放底层事件
                Checkpoint / snapshot bundle Stakpak Agent 远端 Checkpoint 加本地 messages、checkpoint id 与 secret map 能把恢复所需的多类材料打包，并接回 pending decision 多文件与远端写入不是同一原子事务；缺 seq、branch 和 torn-tail 契约时，材料可能彼此不一致 已有 Checkpoint 服务，且调用方愿意在恢复时重新验证工作区、工具和活体 Run

                路线选择取决于下一位读取者要做什么。只需让用户继续对话时，数据库或托管历史可以隐藏大量内部复杂度；需要 fork 和解释“当前历史来自哪条路径”时，parent-linked tree 更直接；需要多个投影共享可演化的语义时，Schema 化事件源更强；只需单 owner 本地修复时，append journal 更简单。Checkpoint bundle 适合跨服务拼装恢复材料，但必须把每一块的版本和写入状态分别返回。

                无论采用哪条路线，最低限度都应区分 accepted、durably appended 与 projected into model context。三者若被压成一个“已保存”，工具副作用发生后恰好崩溃时，恢复端就无法判断应重新观察、拒绝重试，还是安全地继续。

                限制、反例与未决问题

                • 只保存最终 assistant 文本但丢失 tool call/result 的文件是聊天导出，不足以成为可恢复的耐久 Transcript。
                • append-only 不等于存储永不损坏；截断写、重复 seq、payload 丢失和 schema migration 仍需检测策略。
                • Transcript 可以引用大 payload 或附件，但 content-addressing、垃圾回收和字段级删除尚无共同契约。
                • 多 writer 的冲突语义、加密与保留期限在当前样本中不足以提出统一 Interface。
