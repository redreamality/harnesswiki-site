                  Primitive：产物交付

                  Theme：组合与互操作 · 成熟度：Proposed Abstraction · 并行委派 Situation

                  产物交付把 Harness 内部产生的文件、Patch、commit、结构化结果或报告变成外部消费者能够稳定寻址和检查的 Artifact。交付可以复制内容，也可以发布一个仍受生命周期约束的引用；最终回复中声称“已经完成”本身不是 Artifact。

                  领域模型

                  要素 契约
                  输入 producer identity、原始内容或 workspace object、目标 consumer 与交付格式
                  状态 artifact identity、版本、media/schema、storage address、完整性、可见性与 retention
                  输出 可解析的内容或带 provenance 的 ArtifactRef
                  所有者 在消费窗口结束前维持地址、权限和内容一致性的发布方
                  终态 sealed/published、rejected、revoked、expired 或 unreachable 
                  classDiagram
    class Producer {
      harness/session/actor identity
    }
    class Artifact {
      artifact identity
      media type or schema
      content or content address
      integrity
    }
    class ArtifactRef {
      locator
      version
      access scope
      retention
    }
    class Consumer {
      parent actor
      user/client
      evaluator/CI
    }
    Producer --> Artifact
    Artifact --> ArtifactRef
    ArtifactRef --> Consumer

                  Artifact 与 Observation 的差别是消费边界：Observation 为下一 Step 解释某次 Action，Artifact 则需要被父 Agent、用户、CI 或另一个客户端在生产动作之外检查。两者可以引用同一底层内容，但身份和保留契约不能省略。

                  不变量

                  • Artifact identity 必须绑定具体 producer、Session/transaction 和版本；裸路径在 worktree 被删除或复用后不再是稳定引用。
                  • 发布成功与内容验证成功是两个状态；交付 Patch 不证明测试通过，交付报告也不证明其声明为真。
                  • inline 内容被截断时必须显式标记并提供完整来源，不能让 display preview 冒充完整 Artifact。
                  • 清理临时 workspace 前，应先封存内容或把仍有效的 workspace/branch lease 交给 consumer。
                  • 权限和 secret 清理必须作用于 Artifact 内容及附件，而不只是最终文本。
                  • 同一 Artifact 的重试交付应保持 identity 或声明生成新版本，避免消费者把重复传输当成两个结果。

                  显露差异的 Situation

                  隔离 worktree 中的子 Agent 完成修改

                  父 Agent 无法直接假设自己看见子工作树。交付必须明确返回结构化报告、Patch、commit，或仍有效的 worktree path/branch；若临时工作树随后被删除，只有聊天摘要不构成代码交付。

                  远端运行产生大文件，事件通道只能发送小消息

                  Harness 应返回带大小、类型、完整性与 retention 的 ArtifactRef。客户端需要区分预览、完整下载、过期和权限拒绝，而不是把截断的 tool output 当作文件本身。

                  生命周期

                  stateDiagram-v2
    [*] --> Draft
    Draft --> Sealing: producer declares output
    Sealing --> Published: identity and locator assigned
    Sealing --> Rejected: schema, integrity or policy failure
    Published --> Consumed: consumer acknowledges usable artifact
    Published --> Revoked: access withdrawn
    Published --> Expired: retention elapsed
    Published --> Unreachable: backing workspace disappeared
    Rejected --> Draft: producer repairs output
    Consumed --> [*]
    Revoked --> [*]
    Expired --> [*]
    Unreachable --> [*]

                  Published 只表示 consumer 有一个契约化入口；是否接受内容由 consumer 的验证或合并流程决定。

                  各 Harness 的实现

                  Qwen Code workflow/subagent

                  • 状态 / 事实类型：implemented + implemented
                  • 研究锚点：Qwen Code 画像

                  Qwen workflow 的 agent({schema}) 要求子 Agent 调用 structured_output 并通过 JSON Schema；两次提醒后仍未交付会成为 terminal error。使用 isolation:'worktree' 时，无变更的临时 worktree 自动删除，有变更则把 path 与 branch 随结果返回。这把结构化内容交付与 workspace Artifact 引用分成两个字段。Workflow 交付契约 · 结果投影

                  aider

                  • 状态 / 事实类型：implemented + implemented
                  • 研究锚点：aider 画像

                  aider 默认把 AI 编辑封存为 Git commit，并记录 last_aider_commit_hash 与本会话 commit 集；界面可用 commit hash 取得 diff，/undo 只承认当前会话拥有且仍满足安全条件的最后一个 commit。这里的 Artifact 是用户仓库中的 commit/diff，不是聊天中的完成声明。自动 commit 与 identity · 受限撤销

                  mini-SWE-agent

                  • 状态 / 事实类型：alternative + implemented
                  • 研究锚点：mini-SWE-agent 画像

                  mini-SWE-agent 把终态 submission、exit_status、模型统计和完整 messages 序列化为版本化 JSON，并在配置了 output_path 时持续写入文件。SWE-bench runner 另把 submission 写入 preds.json 供 evaluator 消费。它以评测文件交付结果，而不是在核心循环中发布通用 Artifact service。序列化与保存 · SWE-bench 输出

                  Claude Code

                  • 状态 / 事实类型：implemented + documented
                  • 谱系计数：Desktop、VS Code、phone 与 web 是同一 Claude Code Family 的 producer/consumer attachment。

                  固定发布记录明确修复 Remote Control Session 中“发送给用户的文件”上传，使 Desktop 或 VS Code host 产生的文件可在 phone/web 打开。Remote Control 文件交付这证明有独立于聊天文本的 Artifact delivery；artifact identity、完整性、重试和 retention protocol 未公开。

                  Antigravity CLI

                  • 状态 / 事实类型：implemented + documented
                  • 谱系计数：CLI Artifact viewer 与 GUI/共享 engine 属于一个 Antigravity Family。

                  Antigravity CLI 的 Artifact view 可打开外部编辑器，并在存在未发送评论时先确认，reload 还会保留未改内容上的评论。Artifact 编辑与 review state固定版本也允许在 pending question 或 tool permission confirmation 期间单独打开 Artifact Review panel。review 与审批状态分离这支撑产物审查面，但未公开通用传输协议。

                  MiniMax Code

                  • 状态 / 事实类型：implemented + documented
                  • 谱系计数：文件结果、Office 预览与 Browser preview 都属于同一 MiniMax Code Family 的交付面。

                  官方更新日志记录文件结果可定位代码行，并提供 Office preview 与 Browser preview。官方更新日志（桌面 v3.0.65，快照 2026-08-19）这些 documented 行为证明用户可消费独立产物；artifact id、byte integrity、transfer retry、retention 与 acceptance state machine 未公开。

                  Browser Use

                  • 状态 / 事实类型：alternative + implemented
                  • 谱系计数：done result 与受管 filesystem attachments 属于一个 browser-use Family 的终态交付面，只计一次。
                  • 适用边界：它是跨域 Corpus Harness，只支撑浏览器任务文本、结构化结果与文件附件，不支撑 coding-specific patch bundle、提交或远端 artifact manifest。

                  browser-use 的 done action 返回最终文本、is_done、success 与可选 attachments，受管 sandbox 文件可随结果交付；这些字段同时进入最后一个 ActionResult。done 与附件实现和result 模型证明独立于聊天文本的有限文件交付，但没有全局 artifact identity、完整性、重试、retention 或 acceptance protocol，因此保持 alternative。

                  设计策略与取舍

                  Artifact 可以是结构化结果、Git commit、评测文件、远程附件或带评论的审查对象。共同点只是“它能被聊天之外的消费者再次引用”，交付保证则差异很大。

                  交付路线 代表 Harness Artifact identity 消费方式 主要收益 主要代价与未闭合点
                  Schema result + workspace reference Qwen Code structured output 与 worktree path/branch 分开 parent workflow 按 schema 解析，并决定是否处理有变更的 worktree 内容契约和文件效果不混淆，缺失结构化结果可直接失败 path 不是跨主机 artifact id；worktree retention、打包和合并仍需另行负责
                  Git commit/diff aider commit hash 与 Session-owned commit set 用户查看 diff、继续开发或受限 undo 完整性、版本与仓库工具天然可用 只适合 Git 工作区；自动 commit 会改变用户历史，ownership 条件必须严格
                  评测输出文件 mini-SWE-agent versioned JSON / preds.json 中的 task record batch evaluator 读取 submission、status、trajectory 格式简单，适合大批量实验和失败分析 不是通用 artifact service；文件重写、并发 writer 和长期 retention 由 runner 负责
                  跨入口文件传输 Claude Code 产品 Session 中可发送给用户的文件 phone/web 打开 Desktop/VS Code host 产生的文件 控制端无需直接访问执行机文件系统 artifact id、hash、retry、过期与权限协议未公开，不能由“能打开”推断完整性闭环
                  带 review state 的 Artifact Antigravity CLI 可在 viewer/editor 中打开的产物及未发送评论 用户审阅、评论、reload，并与审批面并行使用 产物讨论不必塞进聊天，review 状态可独立保留 通用传输、accept/reject 终态和评论绑定 revision 的细节未公开
                  产品预览面 MiniMax Code 文件结果、Office/Browser preview 对象 用户定位代码行或预览内容 多格式消费友好 identity、byte integrity、retention 和 acceptance state 未公开
                  结果附件 browser-use 最终 ActionResult 中的 attachments 消费者随 done result 取得受管文件 跨域任务能交付下载或生成文件 没有全局 manifest、重试或 coding-specific patch/commit 语义

                  最低交付闭环应包含 artifact id、类型、producer、content hash 或 revision、存储位置、访问 scope、retention 和消费/验收状态。聊天里出现一个路径只在同一机器和同一时刻有意义；跨客户端或远端 world 时，路径必须转换为受控引用或实际传输对象。

                  选择 artifact 形式应贴近下游消费者：代码评审优先 commit/diff，自动编排优先 schema，benchmark 优先版本化记录，跨设备用户交付需要带完整性和权限的文件对象。多个形式可以同时存在，但必须说明谁是 canonical result；否则文本说成功、commit 指向旧 revision、附件又来自另一 worktree 时，消费者无法判断应信哪一个。

                  边界与未决问题

                  • 工作区事务决定变更的 baseline、ownership、merge 和 rollback；本页只研究结果怎样离开 producer 边界。
                  • 工具输出保留保存 Action 输出供模型继续推理；只有形成稳定外部消费契约时才进入 Artifact delivery。
                  • 耐久 Transcript保存运行事实，评测 Trajectory为 evaluator 派生样本；它们可以作为 Artifact，但不会穷尽代码、报告和二进制交付。
                  • 内容寻址、跨 Harness media type、远端 lease、撤销传播与大 Artifact 的分块完整性仍没有共同契约，因此保持 Proposed Abstraction。
