                Primitive：遥测导出

                Theme：组合与互操作 · 成熟度：Proposed Abstraction

                遥测导出由 observability exporter 拥有，把 Harness 的运行信号转换为 logs、metrics 与 traces，交给 operator 或 OpenTelemetry collector 诊断延迟、成本、错误和容量。它允许采样与聚合，因此不能充当 Session 的权威历史。

                领域模型与契约

                契约面 最小语义
                输入 模型请求、tool/Action 生命周期、token/成本、错误、压缩与 runtime 资源信号
                状态 enablement、export target/protocol、resource attributes、sampling、batch queue、redaction 与 retry policy
                输出 带稳定名称和 correlation attributes 的 log record、metric point 与 trace span
                所有者 observability provider/exporter；它决定哪些信号被记录、聚合、丢弃或外发
                主要消费者 operator、SRE、开发者、OTel collector 与受控分析后端

                不变量

                • 遥测开关、目标与敏感字段策略必须可见；配置未允许的 prompt、tool payload、文件内容或 credential 不能因“调试方便”自动外发。
                • session、turn、model request 与 tool call 应使用稳定 correlation attributes；仅靠 message 文本无法可靠连接 span。
                • sampling、aggregation、queue overflow 和 export failure 必须与业务运行结果分开。遥测发送失败通常不应把已完成 Action 改成失败，但应可诊断。
                • exporter retry 不得重复计数非幂等 metric；logs/traces 的重复 delivery 也要有可识别 identity 或后端去重语义。
                • 字段名称、单位与 cardinality 必须受 schema 约束；把 Session id、路径或完整 prompt 直接用作 metric label 会造成泄露和基数爆炸。
                • exporter 不得成为 Agent Loop 的控制依赖；collector 不可用时，Harness 仍应按明确的 drop/buffer/fail-open policy 推进。

                明确边界

                • 耐久 Transcript追求 Session 事实完整性；telemetry 可以采样、聚合和脱敏，不能用于精确 resume。
                • 在线事件流服务当前交互客户端；operator-facing span 不需要复制每个 token chunk，UI event 也不应默认外发。
                • 评测 Trajectory需要 task、Action/Observation 与 outcome 的样本契约；有 trace 只说明可观察，不说明可评测或可重放。
                • 重连投影重建客户端状态；metric rollup 或 trace reducer 的 replay 不具备相同保真目标。
                • 本地 diagnostic bundle 可以比 telemetry 更完整。只要它不经过 exporter、sampling 与 observability schema，就应作为独立诊断产物描述。

                显露差异的 Situation

                定位一次运行的延迟和成本

                operator 需要从 Session/Turn 进入 model span，再关联 tool span、retry、token 与错误；仅记录总耗时无法判断瓶颈在模型、工具还是队列。高基数的单次运行属性适合 trace/log，聚合 metric 应使用受控维度。

                向第三方 collector 导出包含用户内容的事件

                Harness 必须在构造 record 前应用字段级策略，并明确 prompt/tool payload 默认值、endpoint、认证 header 和 TLS。只在 UI 隐藏文本没有作用，因为 exporter 可能已拿到原始 payload；禁用一个 log 字段也不代表 trace event 或 resource attribute 已同步脱敏。

                各 Harness 的实现

                Gemini CLI

                • 状态 / 事实类型：implemented + documented
                • 研究锚点：Gemini CLI 画像

                Gemini CLI 内建 OpenTelemetry，可选择 local 或 Google Cloud target、OTLP endpoint/protocol、文件输出和外部 collector；telemetry 默认关闭，prompt 是否进入 log 由独立设置控制。配置固定锚点 文档枚举 Session、tool、API、token、文件、压缩、agent 等 logs/metrics/traces，并加入 session.id 等关联属性。事件与属性固定锚点 详细 GenAI trace attributes 需要显式开启，说明 signal 级别的 opt-in 与总开关并非同一状态。

                Codex CLI

                • 状态 / 事实类型：implemented + implemented
                • 研究锚点：Codex CLI 画像

                Codex 在固定源码中从 Config 构造 OTel provider，分别选择普通、trace 与 metrics exporter；支持 OTLP HTTP/JSON 或 binary、OTLP gRPC、headers、TLS、service/environment attributes 与 W3C tracestate。Provider 固定源码 配置模型把 log_user_prompt、三个 exporter、span attributes 与 tracestate 分开，且默认 prompt logging 为 false。配置固定源码 这证明 exporter seam 已实现，但并不证明所有安装都启用相同 signals 或后端。

                Proposed Interface

                两个实现都把 signal production 与 exporter adapter 分开，支持一个较深的配置 Interface：

                调用者不应逐事件选择 transport；provider 在内部处理 protocol、TLS、batch、retry 和 shutdown flush。Interface 仍需显式暴露 content policy 与 signal-specific enablement，不能压成 telemetry: true。

                限制、反例与未决问题

                • 一个 console.log 调试行没有 schema、correlation 或 export lifecycle，不是遥测导出 Implementation。
                • OpenTelemetry 统一了传输和语义约定的一部分，但不会自动决定 prompt 是否敏感、怎样脱敏或保留多久。
                • trace 里出现 tool input/output 不能推断拥有完整 评测 Trajectory；sampling 可能移除关键 Action，environment anchor 也可能不存在。
                • shutdown flush 的时限、离线 spool、collector backpressure、跨子 Agent trace propagation 和用户数据删除尚无共同契约。
                • 当前证据不足以统一每种 event/span 名称，页面因此保持 Proposed Abstraction，不把 OTel SDK 类型直接当作 Harness 公共 Interface。
