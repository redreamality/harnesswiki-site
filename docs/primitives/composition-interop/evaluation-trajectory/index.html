                Primitive：评测 Trajectory

                Theme：组合与互操作 · 成熟度：Proposed Abstraction

                评测 Trajectory 由 evaluation recorder 或 adapter 拥有，把一次任务中的决策、Action、Observation、运行配置与 outcome 组织成可比较样本，交给 evaluator、trainer 或 reviewer。它可以从运行事实派生，但不能把为评分方便而标准化的内容写回原 Session。

                领域模型与契约

                契约面 最小语义
                输入 task instance、按因果排列的模型响应/Action/Observation、environment anchor、terminal result 与可选 score
                状态 trajectory/schema 版本、run identity、step/action identity、artifact refs、redaction、adapter 与 evaluator 版本
                输出 不可歧义的样本 envelope、step 序列、最终 submission/outcome、成本统计与评测 metadata
                所有者 evaluation recorder 或从原始运行事实派生样本的 adapter
                主要消费者 benchmark runner、evaluator、trainer、reviewer 与离线分析器

                不变量

                • 每个 Observation 必须能关联到产生它的 Action；并行或缺失结果不能靠数组相邻位置猜测。
                • task input、Harness/model/tool 配置和 environment identity 必须版本化；只有聊天文本无法解释为何同一 Action 得到不同结果。
                • “Harness 正常结束”与“任务通过评测”是两个终态。exit status、submission 与 evaluator score 不得合并成一个 success 布尔值。
                • adapter 可以重命名字段、脱敏或生成派生 metric，但不得改写原始 Action/Observation 事实；转换规则及版本必须留下。
                • Action replay 产生的是新 Run 与新 Observation，不能覆盖原 trajectory；外部 I/O、时间和工作区漂移必须视为 nondeterminism。
                • 不允许保存的 prompt、secret、文件内容和附件必须在发布数据集前按字段或 artifact 处理，不能只清理 display text。

                明确边界

                • 耐久 Transcript为 resume/fork 保留 Session 事实；它可能比评测 schema 更完整，也可能没有 task outcome 或 environment anchor。
                • 遥测导出面向运营诊断并允许 sampling；缺一段 span 的 trace 仍可能有用，却不能成为完整 trajectory。
                • 在线事件流包含 token chunk 和 transient progress；评测 recorder 通常在 Action/Observation 或 Step 边界归一化，而非复制所有 UI 增量。
                • 重连投影服务客户端状态。其“replay”不执行 Action；评测工具若行动重放，必须在新的 执行环境 中记录新结果。
                • chain-of-thought 不是本 Primitive 的前提。可观察的模型响应、Action、Observation、状态转移和 outcome 已能支撑多数 benchmark；不可公开的隐藏推理不应被假定存在。

                显露差异的 Situation

                批量运行 SWE-bench，进程中途重启

                runner 需要区分完整 trajectory、空文件、缺 exit status 的部分记录和已评分结果。只有完整且版本兼容的样本才能安全跳过；部分记录应重跑或显式标记，不能因为文件存在就算完成。

                把一次交互运行发布为训练或评测数据

                Session 里可能含用户路径、secret、无关对话和大附件。adapter 应从权威记录派生一个带 schema/version、environment anchor 与 redaction metadata 的样本，并保留 source run 引用；不可逆裁剪后的公开数据不能替代内部审计记录。

                各 Harness 的实现

                Gemini CLI

                • 状态 / 事实类型：implemented + implemented（Trajectory 事件） / unknown（通用 benchmark outcome）
                • 研究锚点：Gemini CLI 画像

                Gemini 的 AgentProtocol 直接扩展 Trajectory，既能订阅未来事件，也能读取已有 events。事件公共字段包含唯一 id、subagent thread、activity stream、timestamp 与 discriminated type，从而为多 stream/subagent 的因果分组提供结构基础。AgentProtocol 固定源码 该 Interface 验证了结构化 Agent trajectory，但固定材料没有提供通用 task score/submission envelope；评测 adapter 仍需在其上派生。

                mini-SWE-agent

                • 状态 / 事实类型：implemented + implemented
                • 研究锚点：mini-SWE-agent 画像
                • 谱系计数：与 SWE-agent 家族的共同 Action/Observation 记录只计一份设计证据

                mini-SWE-agent 的 messages 同时构成模型历史与线性 trajectory：模型响应追加后执行 Action，再追加 Observation；每个 Step 的 finally 保存当前记录。序列化结果包含 model stats、agent config/type、版本、exit status、submission、messages、environment/model metadata 与 trajectory_format。DefaultAgent 固定源码 这适合任务级导出与失败分析，但线性 messages 本身不能表达并行因果。

                SWE-agent

                • 状态 / 事实类型：implemented + implemented
                • 谱系计数：作为 mini-SWE-agent 的同家族差异证据，不额外增加独立实现票数

                SWE-agent 将 TrajectoryStep 明确定义为 action、observation、response、state、thought、execution time、query 与 extra info，并把 trajectory 放入 AgentRunResult。类型固定源码 Batch runner 检查现有 .traj 的 exit_status，空文件、无法解析或无终态的记录会重跑而不是误判完成。批处理固定源码 run replay 从历史提取 Action，在配置兼容的新 environment 中执行并生成新 trajectory，明确展示了“记录”与“行动重放消费者”的分离。回放固定源码 · Action 提取与校验

                Browser Use

                • 状态 / 事实类型：implemented + implemented
                • 谱系计数：Agent history、serialization 与可选 judge projection 属于一个 browser-use Family，只计一次。
                • 适用边界：它是跨域 Corpus Harness，只支撑通用评测记录与浏览器任务轨迹，不支撑 coding-specific patch、Git baseline 或构建结果。

                browser-use history 为每步保存 model output、action results、browser state、耗时、usage 与可选 judgement，并可序列化后重新加载；browser state 另保留 URL、交互元素与 screenshot path。history/result 模型和action history serialization 测试证明任务级 trajectory；它没有证明环境确定性、Action 幂等或跨浏览器重放。

                设计策略与取舍

                评测 trajectory 可以是模型历史、类型化 Step、并行事件图或带环境快照的领域记录。保存字段越多，不代表越容易重放；还要看 causal identity、版本和 Execution World 是否兼容。

                记录路线 代表 Harness 因果结构 环境与结果 主要收益 主要代价与失败点
                多 stream 结构化事件 Gemini CLI event id、subagent thread、activity stream、timestamp 与 discriminated type 记录 AgentProtocol 事件，通用 benchmark outcome 需另派生 能表达并行 actor 和多活动流，适合在线观察与后处理 事件多且需要 join/correlation 规则；有事件流不等于已有统一 score/submission envelope
                线性 messages = trajectory mini-SWE-agent 模型响应、Action、Observation 顺序追加 同时保存 submission、exit status、stats、config 与 environment metadata 实现简单，模型历史和评测导出天然一致 无法精确表达并行因果；为模型裁剪历史也可能影响评测保真度
                类型化 Step + replay consumer SWE-agent Family action/observation/response/state/thought 等字段形成 Step batch runner 检查 terminal，replay 在兼容新环境重新执行 Action 失败分析和批处理恢复更稳，记录与重放职责分离 schema 与配置兼容性必须版本化；重放产生新事实，不能覆盖原 trajectory
                领域状态 + 可选 judge browser-use 每步 action/result 与 browser state 关联 URL、元素、截图、usage、耗时和 judgement 能分析环境漂移与网页终态，跨域证据丰富 screenshot/path 未必长期可用；浏览器与网站非确定性使 action replay 不能保证同结果

                共同的最低字段包括 task/run identity、step/event identity、parent/stream、Action、Observation、timestamp、terminal reason、producer/schema version 和环境摘要。Thought 或完整 prompt 是否保存则要权衡隐私、成本和可复现性，不能默认越多越好。

                线性单 Agent 评测可以从 messages 起步；出现并行 tool/child 后需要显式 stream 与 parent id；要比较成功率时再增加独立 outcome/evaluator；要执行重放时必须额外冻结 Action schema、environment compatibility 和 side-effect policy。重放永远产生一条新 trajectory，原记录只作为输入证据。

                Proposed Interface

                目前两类形态尚未收敛：Gemini 是通用 typed event trajectory，SWE-agent 家族是 benchmark-oriented step/result envelope。候选 Interface 应保留二者交集，而不是强制一种消息 schema：

                runAnchor 至少包含 Harness/model/tool/environment/schema identity；derive 必须生成新 artifact 并保留 source reference。是否保存 hidden thought、怎样表示并行 graph、score schema 如何扩展，仍属于 adapter/profile 决策。

                限制、反例与未决问题

                • 只有 prompt 与 final answer 的数据集是问答样本，不足以研究 Harness 的 Action/Observation 行为。
                • 保存所有 OTel spans 仍可能缺 task input、submission、环境版本或被 sampling；不能自动升级为评测 Trajectory。
                • SWE-agent 的 action replay 会再次产生副作用；它证明存在消费者，不证明任意 trajectory 都可确定性重放。
                • Gemini 与 Qwen 同源的 inherited Agent/Context 机制不能机械算两票；本页没有用 Qwen 增加成熟度。
                • 多 Agent DAG、artifact content addressing、跨 Harness tool schema、partial trajectory 评分和公开数据删除仍无共同契约，因此保持 Proposed Abstraction。
