                  Primitive：状态持久化与恢复

                  Theme：控制与连续性 · 成熟度：Proposed Abstraction · 外部客户端恢复 Situation

                  状态持久化与恢复定义运行事实怎样跨进程保留、从哪个身份继续，以及恢复时如何检测 Session、工具和 Execution World 已经漂移；它不是“保存聊天记录”的同义词。

                  恢复域

                  flowchart TB
    subgraph Durable["可能持久化的域"]
        H["消息 / 事件历史"]
        C["Context summary / active branch"]
        W["工作树 / untracked 文件"]
        P["pending approval / jobs"]
        E["进程、cwd、环境变量"]
        K["工具与模型配置"]
    end
    Durable --> R["Recovery attempt"]
    R --> V["identity + compatibility + drift validation"]
    V -->|valid| S["resumed Session / new Turn"]
    V -->|partial| D["degraded recovery + explicit gaps"]
    V -->|invalid| F["refuse or fork"]

                  不同实现通常只覆盖其中几个域。Wiki 使用 Checkpoint coverage 精确描述可恢复集合，不把“有 session 文件”升级为完整快照。

                  领域对象

                  对象 含义
                  Durable fact 重启后仍能读取的消息、事件、配置或 workspace snapshot
                  Recovery identity Session id、event cursor、branch leaf、checkpoint id 等继续点
                  Projection 从 durable facts 构造当前消息历史、Context Snapshot 或 UI 状态
                  Compatibility guard 模型、工具 schema、插件、工作区或版本是否仍能解释旧事实
                  Drift 持久历史记录的世界与当前文件、进程、远端资源不一致
                  Recovery outcome exact、partial、forked、refused，及其未恢复域

                  不变量

                  • 原始事件与模型可见投影应可区分；压缩、裁剪或 summary 不应伪装成完整历史。
                  • 恢复必须选择明确身份。只把旧文本重新发给新 Session 不是原 Session resume。
                  • 已执行 Action 可能不幂等；重放事件用于重建状态，不等于重新执行所有 Action。
                  • 工作树、Session 和 terminal 是不同恢复域，时间点不一致时必须暴露 drift。
                  • 工具或 agent 配置不兼容时，静默继续可能使历史中的 tool result 无法解释；应拒绝、迁移或降级。

                  显露差异的 Situation

                  进程崩溃前文件已修改，但 Observation 尚未持久化

                  恢复后工作树显示效果，Session 却认为 Action 仍在运行。Harness 需要重观测、标记不确定终态或要求用户确认，不能盲目重放。

                  从旧事件节点创建分支

                  分支可能只改变 active history，也可能创建新 Session 和新 worktree。应分别记录事件血缘、workspace identity 与后续合并责任。

                  恢复时序

                  sequenceDiagram
    actor C as Client
    participant S as Session Store
    participant R as Recovery Coordinator
    participant W as Execution World
    participant H as Harness Core

    C->>R: resume(sessionId / checkpoint / cursor)
    R->>S: 读取 durable facts 与 active branch
    S-->>R: events + summaries + configuration refs
    R->>W: 读取当前 workspace / runtime identity
    W-->>R: current state
    R->>R: 校验 schema、tool、agent 与 drift
    alt 可精确恢复
        R->>H: rebuild projection and continue point
        H-->>C: resumed + current terminal state
    else 只能部分恢复
        R-->>C: explicit gaps + fork/degraded options
    else 不兼容
        R-->>C: refuse with reason
    end

                  各 Harness 的实现

                  DeepSeek Harness

                  • 状态 / 事实类型：implemented + documented/observed
                  • 研究锚点：见 DeepSeek Harness 画像

                  DeepSeek 把 append-only SessionEvent log 作为耐久事实，模型可见历史由事件投影；resume、fork、transcript 与 telemetry 因而共享同一事件来源。live Agent 与 durable Session 分开，恢复是从日志重建新的运行投影，不是假设旧进程仍存在。固定行为锚点的 assembled-app snapshot 进一步观察到：只有 durable tool/call、缺少 result 时，恢复会追加 TOOL_OUTCOME_UNKNOWN，闭合旧 Step/Turn 后才开始新 Turn，不会把未知副作用改写为失败或盲目重放；更高日志版本和未知 required event 则 fail closed。输入、事件序列与 golden

                  Qwen Code

                  • 状态 / 事实类型：implemented + documented/observed
                  • 研究锚点：见 Qwen Code 画像

                  Qwen 的 JSONL active chain 与 Session worktree sidecar 是不同恢复域。固定模块探针观察到：sidecar 结构有效但 worktree 目录已经不存在时，restore helper 返回 session=null 与 contextMessage=null 并删除 stale sidecar；Session 可以在不带旧 worktree context 的情况下继续，但目录、文件和旧进程都没有恢复。compression record 另把四条 durable records 投影为 summary、ack 和 checkpoint 后 tail，说明耐久输入仍在不等于下一次模型可见历史仍含原文。探针、断言与限制

                  Pi

                  • 状态 / 事实类型：implemented + documented
                  • 研究锚点：见 Pi 画像

                  Pi 的单个 JSONL Session 文件用 id/parentId 保存树形历史，active leaf 决定当前分支；compaction entry 与 branch summary 参与当前路径的 Context projection，但原 entry 仍保留。更外层 runtime 可在新建、恢复、fork 或 import 时替换 active AgentSession 并重建 cwd-bound 资源。

                  aider

                  • 状态 / 事实类型：alternative + implemented
                  • 研究锚点：见 aider 画像

                  aider 在显式启用 restore 时读取 Markdown chat history，把记录拆回 done_messages 并启动摘要；只有当前消息为空才采用这条路径。历史装载与投影 它没有恢复原 Session identity、工具调用终态、cwd、进程或工作区 checkpoint，因此只是消息面的替代恢复，而不是完整运行恢复。

                  Gemini CLI

                  • 状态 / 事实类型：implemented + documented/implemented
                  • 研究锚点：见 Gemini CLI 画像

                  Gemini CLI 按 project hash 自动保存 conversation、tool execution、usage 与 reasoning summary，并可按 index 或 UUID resume。Session 保存与恢复 可选 checkpoint 另把 shadow Git snapshot、conversation 和即将执行的 tool call 分开保存。Checkpoint 覆盖域 Rewind 可以只回 conversation 或只回 AI 文件编辑，明确不撤销手工修改与 Shell 副作用。Rewind 边界 因此 Session 与部分 workspace 可恢复，旧进程和外部效果不在保证内。

                  Cline

                  • 状态 / 事实类型：implemented + implemented
                  • 研究锚点：见 Cline 画像

                  Cline Session 保存 SQLite metadata 与 manifest/messages artifacts，Agent runtime 还暴露 restore(messages) 与 snapshot()。Git checkpoint 单独覆盖工作区；restore coordinator可分别恢复工作树或裁剪消息，说明“对话恢复”和“文件恢复”不是一个布尔能力。

                  OpenHands runtime

                  • 状态 / 事实类型：implemented + implemented（事件） / unknown（通用工作树 checkpoint）
                  • 研究锚点：见 OpenHands 画像

                  OpenHands EventLog 将事件持久化为 JSON，事件带 parent_id 并支持 active branch。ConversationState.create 可从持久化恢复并验证 agent/tool 兼容性。Canvas 可从 event fork conversation；Action 重放可能产生非幂等效果，因此不能当作工作树 checkpoint restore。

                  mini-SWE-agent

                  • 状态 / 事实类型：implemented + implemented（导出） / unknown（恢复执行）
                  • 研究锚点：见 mini-SWE-agent 画像

                  mini-SWE-agent 把 messages 作为 trajectory，并在每个 Step 的 finally 中保存。固定版本能持续导出记录，但本轮没有找到从 trajectory 重新构造 agent 并继续执行的直接证据；因此可观测持久化是 implemented，resume 为 unknown。

                  Mistral Vibe

                  • 状态 / 事实类型：implemented + implemented
                  • 谱系计数：本地 CLI、ACP 与 app-server 从同一 Mistral Vibe Session/checkpoint state 恢复，只计一个 Family。

                  Mistral Vibe 将消息与 metadata 分开持久化，loader 重建 Session 后保留模型历史中的 tool call/result；文件恢复则由 Turn checkpoint 单独负责。Session 持久化 · Session loader · resume characterization这些证据不覆盖旧 shell/MCP 连接、pending callback 或任意外部副作用。

                  Refact

                  • 状态 / 事实类型：implemented + implemented
                  • 谱系计数：daemon、project worker 与各客户端从同一 Refact trajectory-backed Chat Session 恢复，只计一个 Refact Family。

                  Refact 取得 chat id 时会复用未关闭的 live Session；已关闭或进程内不存在时，则从 trajectory 装载 messages、thread、goal、goal ledger、wake-up、waiting cards 与 background-agent summary，并迁移或修复旧 transition identity 后重新放入 Session map。trajectory-backed Session 重建这覆盖消息与部分运行语义的重建，不证明 in-flight tool、PTY process、pending approval、child quiescence 或当前 worktree 文件状态可以原样恢复。

                  Zed Agent

                  • 状态 / 事实类型：alternative + implemented
                  • 谱系计数：编辑器内 Agent Panel、ThreadStore、sandbox 与 subagent 工具共用同一个 Agent runtime，只计一个 Zed Agent Family。

                  Zed 的 ThreadStore 可从数据库 load/save DbThread 并刷新 metadata 列表，ThreadStore 持久投影但活体 RunningTurn、event receiver、tool future、approval oneshot 和 cancellation channel 留在 Thread 内存边界。Thread 与 RunningTurn 状态 Sandbox grant 虽有数据库转换 helper，grant 转换本轮未闭合其 ThreadStore wiring；恢复消息投影不等于恢复在途 Turn、工具进程、pending approval、child quiescence 或工作区快照，因此只记为 alternative。

                  Stakpak Agent

                  • 状态 / 事实类型：alternative + implemented
                  • 谱系计数：服务端 Checkpoint、本地 messages/secret map 与 async resume 属于一个 Stakpak Agent Family 的分层恢复路径。

                  async mode 可按 Session 或 active Checkpoint 取得 messages/metadata，再从历史识别 pending tool call 并应用 resume input。Session/Checkpoint 装载 · pending decision 接续本地 snapshot 另保存 messages、checkpoint id 与 SecretManager map，本地快照但 pause manifest 写失败仍可返回 Paused，且恢复不覆盖原 Run、MCP/tool process、工作区或 Warden state，所以只记为 alternative。

                  设计策略与取舍

                  恢复不是一个 resume=true 开关。它至少要回答：从什么耐久事实重建、恢复到哪条分支、工作区是否仍存在、旧工具效果怎样收尾，以及不兼容时是拒绝还是降级。

                  恢复路线 代表 Harness 重建依据 获得什么 代价与典型失败点
                  事件事实源重放 DeepSeek Harness、OpenHands append-only Session/EventLog 与 active branch 可重新投影消息、Turn 和部分运行语义，并保留审计顺序 schema/required event 必须版本化；缺失 tool result 只能标 unknown，重放 Action 可能重复副作用
                  Entry tree / active chain Pi、Qwen Code 带 parent/active leaf 的 JSONL 与 summary/checkpoint records 分支选择和模型投影可重建，原记录仍保留 cwd、worktree 和进程是独立恢复域；Qwen 丢失 worktree 时只能 partial/degraded。Gemini/Qwen 共享机制按一个 Family 计数
                  Session record + workspace checkpoint Gemini CLI、Cline project-scoped conversation/metadata 加 shadow Git 或 stash-shaped snapshot 用户可分别恢复消息和 AI 文件效果 多域选择会产生组合状态；shell、手工编辑与外部效果通常不在 checkpoint 内
                  Trajectory-backed semantic state Refact trajectory 中的 messages、goal、ledger、cards 与 background summary 新进程可重建比聊天文本更丰富的任务语义 in-flight tool、approval、PTY、child quiescence 和当前文件状态仍需重新观察
                  耐久投影 + 新活体 Mistral Vibe、Zed Agent、Stakpak Agent Session messages/metadata、ThreadStore 或 Checkpoint/local snapshot 能继续对话并创建新的 Run/RunningTurn 旧 receiver、cancel token、MCP/PTY、pending callback 和 container 不会复活；Stakpak pause manifest 还存在非原子写入窗口
                  消息导入或仅导出 aider、mini-SWE-agent Markdown chat history 或 trajectory file 实现简单，至少保留可读历史 原 Session identity、tool terminal、branch、workspace 和 executable resume 缺失；导出成功不能冒充恢复成功

                  精确恢复通常状态最多、兼容成本也最高；部分恢复更诚实，但必须把丢失域返回给调用方。实践中应先恢复 identity 和耐久事实，再验证 workspace binding，最后重建活体资源。任何阶段失败都应保留原材料，并以 exact/partial/degraded/rejected 一类可区分终态结束，而不是静默开始一个看似相同的新 Session。

                  矩阵按恢复机制和 Family 合并，省略的产品入口仍由上方实现段保留；这里不把“历史可查看”升级为可执行恢复。

                  未决问题

                  DeepSeek 新旧锚点增量实验已让可控本地服务真正完成副作用，再中断尚未记录 result 的进程。新旧真实修复函数均保持外部结果为 unknown，重复修复不重复追加 result；它没有执行副作用去重。新版还改变了合成工具消息格式。两轮都未运行完整 coordinator，不能把模块证据外推成端到端恢复。

                  • durable event 已写入但文件系统效果未落盘时，恢复协调器怎样解决反向不一致？
                  • pending approval、后台 job 和流式输出是否属于可恢复状态，目前多数样本证据不足。
                  • Session schema 或 tool schema 升级后的迁移策略没有形成共同模式。
                  • 精确恢复、部分恢复和 fork 是否需要统一结果类型，尚不足以提出 Interface。
