协调指南：任务、目标与多 Actor 编排

Theme：控制与连续性 · 本页协调工作、Actor、Job 与 Goal 证据，不定义统一 Task Primitive · 并行委派 Situation

编排把“要完成什么”的工作拓扑与“由谁运行”的 Actor 拓扑连接起来，再组合后台执行、完成证据和工作区结果。本页解释这些 Primitive 的协作关系；多 Actor 只是其中一种执行方式，不拥有所有编排状态。

原子边界

Section titled “原子边界”
Primitive 独占状态或判断 不拥有的相邻事实
工作拓扑 Work item、依赖、claim、result reference 与 join child runtime、进程资源或 workspace diff
Actor 委派 parent/child identity、lineage、Context policy、消息与取消 task graph、后台进程或 worktree ownership
后台 Job 生命周期 Job identity、running/terminal、output cursor、wait 与 cancel 目标语义、Actor lineage 或完成充分性
Goal 证据协议 goal revision、terminal proposal、Evidence Claim 与 verifier verdict 自动拆分工作或执行测试
工作区事务 baseline、diff、checkpoint、rollback 与 merge Work item/Actor 的完成状态
产物交付 Artifact identity、引用、传输与消费确认 文本报告是否代表已发生 workspace effect

三种不要混淆的拓扑

Section titled “三种不要混淆的拓扑”
flowchart TB
    subgraph Work["工作拓扑"]
        G["Goal"] --> A["Work item A"]
        G --> B["Work item B"]
        A --> J["Join / acceptance"]
        B --> J
    end
    subgraph Actors["Actor 拓扑"]
        P["Parent actor"] --> CA["Child actor A"]
        P --> CB["Child actor B"]
    end
    subgraph Worlds["Workspace 拓扑"]
        Base["Baseline"] --> WA["Shared tree or worktree A"]
        Base --> WB["Shared tree or worktree B"]
    end
  • 一个 Agent 可以串行完成多个 Work item。
  • 多个 Agent 可以只做只读调查并共享工作区。
  • 两个 child session 不自动得到两个 worktree。
  • 后台 Job 表示调度和生命周期，不自动表示新的推理 actor。

领域对象

Section titled “领域对象”
对象 最小状态
Goal 期望终态、约束、acceptance condition
Work item 输入、依赖、owner、status、result reference
Actor 模型/agent 配置、Session identity、cancel handle
Job queued/running/waiting/terminal 的调度单元
Delegation 父上下文中被选择的子上下文、权限与工具边界
Join 收集结果、检测冲突、接受/拒绝、整体验证

不变量

Section titled “不变量”
  • completed 必须相对于 acceptance condition，而不只是子模型返回了文本。
  • 子 Agent 结果应区分报告、Artifact 和已经发生的工作区效果。
  • 取消父任务时应说明是否传播到 queued/running child；只丢弃等待者可能留下后台效果。
  • actor 血缘、工作依赖和 workspace ownership 必须能分别查询。
  • 合并后的验证属于父任务或显式 verifier；不能把两个子任务各自通过测试推导为组合结果通过。

显露差异的 Situation

Section titled “显露差异的 Situation”

子 Agent 完成后父 Agent 被压缩

Section titled “子 Agent 完成后父 Agent 被压缩”

结果只存在于临时 tool output 时，compaction 可能丢掉关键 Artifact 引用。编排器应持久化 Work item 终态或可重建摘要，而不依赖父模型记忆。

父任务取消时一个子 Agent 正在写文件

Section titled “父任务取消时一个子 Agent 正在写文件”

应观察取消传播、进程终止、workspace transaction 和 child terminal event 的顺序；“父端停止等待”不能自动视为子任务已取消。

委派时序

Section titled “委派时序”
sequenceDiagram
    participant P as Parent Agent
    participant O as Orchestrator
    participant S as Session Store
    participant C as Child Agent
    participant W as Child Workspace
    participant V as Verifier

    P->>O: delegate(goal, constraints, tools)
    O->>S: 创建 work item + actor/session refs
    O->>C: 有界上下文 + completion contract
    C->>W: observe / act / validate
    C-->>O: terminal status + result + effects
    O->>S: 持久化 child terminal state
    O-->>P: structured join input
    P->>O: accept / retry / cancel / merge
    opt 已发生工作区变更
        O->>V: 在目标 workspace 整体验证
        V-->>P: final acceptance evidence
    end

Harness 导航

Section titled “Harness 导航”

本表只指出组合阅读路径；每个机制的 Implementation 状态与固定证据留在原子页。

Harness 画像 具体 Primitive 不能由组合入口推断
DeepSeek Harness Goal 证据协议 · 后台 Job 生命周期 · Actor 委派 · 工作拓扑 Goal、Job 与 child actor 共存不证明它们属于统一 Task，也不证明存在 Work item graph 或 evidence verifier
OpenCode 工作拓扑 · Actor 委派 · 后台 Job 生命周期 child Session 的 parentID 不证明 worktree 隔离、取消传播或 result durability
Qwen Code 工作拓扑 · Actor 委派 · Goal 证据协议 · 工作区事务 team、subagent 与 worktree 能组合不证明它们一一对应，也不证明合并结果已经整体验证
mini-SWE-agent 工作拓扑 · 执行放置 · 产物交付 外层 batch 并发不证明父 Session 内存在动态 delegation、共享 task graph 或自动 join

反例与未决问题

Section titled “反例与未决问题”
  • “支持 subagent”不能回答结果是否耐久、workspace 是否共享、父取消是否传播。
  • 只维护 todo list 是工作拓扑的一部分；若没有调度或 actor 状态，不应宣称为多 Agent runtime。
  • 同 Session 内并行工具调用与多个 Agent 是两种并发层级，取消和上下文所有权不同。
  • 当前样本对 backpressure、优先级、失败聚合和循环依赖没有共同契约，不提出统一 scheduler Interface。
