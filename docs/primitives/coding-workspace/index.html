                  编码工作面

                  导航：首页 · 机制地图 · 领域模型

                  编码工作面解释文本决策如何接触真实代码库。六个 Primitive 组成一条常见但非强制的反馈链；极简 Harness 可能把检索、编辑和验证全部交给一个 Shell。

                  flowchart LR
    RI["代码库智能"] --> CA["变更生成与应用"]
    CA --> EP["执行放置"]
    EP --> PC["进程连续性"]
    PC --> VF["验证与反馈"]
    VF -->|失败观察| CA
    CA --> WT["工作区事务"]
    VF --> WT

                  Primitive

                  页面 独立状态或契约
                  代码库智能 索引、相关性、符号关系、增量更新和检索预算
                  变更生成与应用 Edit protocol、定位、解析、冲突与原子应用
                  执行放置 Execution World 身份、工作区绑定、连接、租约与释放
                  进程连续性 execution-session 身份、cwd、环境、PTY、进程树与终态
                  验证与反馈 触发时机、检查范围、诊断归因和继续判定
                  版本控制与工作区事务 基线、dirty state、隔离、checkpoint、undo 与交付状态

                  协调指南

                  • 执行环境、放置与连续性串联 Execution World、执行放置、进程连续性、工具输出和取消边界；它不计入 Primitive 数量。

                  边界

                  • Repo Map 和 LSP 负责发现相关代码；上下文预算如何容纳它们属于上下文压缩。
                  • Shell 是一种工具；它运行在哪个 Execution World 属于执行放置，cwd、环境和进程树能否跨 Action 延续属于进程连续性。
                  • “能运行测试”只是工具能力；由谁决定何时验证、失败是否继续才属于验证反馈。
                  • Patch 是文件变更协议；Git commit、worktree 和恢复基线属于工作区事务。
