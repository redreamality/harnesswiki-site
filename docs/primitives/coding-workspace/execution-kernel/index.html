                协调指南：执行环境、放置与连续性

                Theme：编码工作面 · 本页协调放置、进程连续性与隔离边界，不定义第四种执行 Primitive · 高风险命令 Situation

                “执行环境”常被用来同时指行动在哪里发生、连续命令是否共享进程状态，以及进程最多能影响什么。本页保留跨维度的阅读顺序；正式契约分别由下列 Primitive 拥有，“提供 Bash 工具”只是入口，不能替代这些边界。

                原子边界

                Primitive 独占问题 不可由它推断
                执行放置 Action 位于宿主、容器、VM 还是远端 Execution World shell 是否跨 Action 保持 cwd、环境变量或进程状态
                进程连续性 一次性进程、持久 PTY/tmux、输入输出和取消终态 filesystem、network、credential 是否被强制隔离
                执行隔离 mount、network、process tree、credential 与 resource enforcement 用户是否授权本次 Action，或命令状态是否持久
                工具与能力运行时 tool schema、dispatch 与 Observation 规范化 Action 的物理放置、shell residency 或 sandbox profile

                放置与进程连续性的两个正交维度

                维度 典型选择 不能推断什么
                Execution placement 宿主机、容器、VM、远端 workspace 放在容器里不自动说明命令是否共享 shell
                Process continuity 每次新进程、持久 PTY、tmux session、远端 kernel 持久 shell 不自动提供文件系统隔离

                这里的“两个”只指执行放置与进程连续性这对执行维度，不排除独立的执行隔离维度。同一 Harness 可以在本机启动持久终端，也可以在容器中为每次 Action 新建 shell；画像必须分别记录放置、进程持续性、文件系统身份和策略边界。

                领域模型

                classDiagram
    class ExecutionWorld {
      workspace identity
      filesystem boundary
      network and credentials
    }
    class ExecutionSession {
      cwd
      environment
      process state
      lifecycle
    }
    class CommandAction {
      argv or shell text
      timeout
      input stream
    }
    class ProcessObservation {
      output chunks
      exit status
      terminal reason
    }
    ExecutionWorld "1" o-- "0..*" ExecutionSession
    ExecutionSession "1" --> "0..*" CommandAction
    CommandAction "1" --> "1" ProcessObservation

                不变量

                • Observation 必须区分正常退出、超时、用户取消、进程被杀与 transport 断开；它们对下一 Step 的含义不同。
                • 声称 cwd、环境变量或虚拟环境会持续，必须有稳定的 ExecutionSession identity；仅保留容器文件系统不等于保留 shell 进程。
                • 取消进程不能撤销已经发生的文件、网络或子进程效果；恢复责任属于工作区事务和外部系统。
                • Tool Runtime、语言服务与 Shell 若观察不同 workspace，应显式暴露世界身份，否则代码检索与实际执行可能分叉。
                • shell=True、bash -lc 和 argv spawn 有不同的 quoting 与注入面，不能用统一的“运行命令”标签掩盖。

                显露差异的 Situation

                两个连续 Action：先 cd，再运行测试

                持久 PTY 会在第二个 Action 继承 cwd；每次新 subshell 则回到默认工作目录。模型若把前者的心智模型用于后者，会在错误目录验证。

                长命令产生输出后被取消

                应观察输出是否流式保留、子进程树是否终止、Action 终态如何记录，以及已经修改的文件是否仍可见。只返回一个通用 error 会丢失关键事实。

                生命周期状态

                stateDiagram-v2
    [*] --> Starting
    Starting --> Running: process/session ready
    Running --> Running: input or output chunk
    Running --> Completed: exit status
    Running --> Cancelling: abort / timeout
    Cancelling --> Cancelled: process tree terminated
    Cancelling --> Orphaned: transport lost or child survives
    Starting --> Failed: spawn error
    Completed --> [*]
    Cancelled --> [*]
    Failed --> [*]
    Orphaned --> [*]

                持久执行会话在单条命令 Completed 后仍可回到 Running；一次性进程则直接结束。图中的 Orphaned 是必须检查的失败状态，不表示所有 Harness 都显式建模它。

                Harness 导航

                本表只给出组合阅读入口；Implementation 状态与固定证据由具体 Primitive 页拥有。

                Harness 画像 具体 Primitive 不能由组合入口推断
                OpenHands 执行放置 · 进程连续性 · 执行隔离 持久 terminal 不证明 Canvas 拥有 sandbox，也不证明所有部署使用同一种放置边界
                mini-SWE-agent 执行放置 · 进程连续性 · 执行隔离 容器文件系统持续不证明 shell 持续，也不证明实际 mount、network 或 credential policy
                Cline 执行放置 · 进程连续性 · Action 授权 单次命令的 process handle 与取消语义不证明持久 shell、安全隔离或默认需要审批
                aider 执行放置 · 进程连续性 · Action 授权 宿主命令执行不证明存在 sandbox；确认建议也不能改变 Execution World

                反例与未决问题

                • “Docker environment”不能直接写成“沙箱”：挂载、网络、凭据和 daemon 权限决定实际隔离边界。
                • 持久终端提高交互效率，也会让隐藏 cwd、环境变量和后台进程成为恢复状态的一部分。
                • 当前证据不足以为不同 Harness 的 streaming chunk、PTY resize 和 backpressure 提出统一事件契约。
                • 远程 workspace 断线后，命令继续还是终止，必须由具体实现证明；协议存在不等于具备重连语义。
