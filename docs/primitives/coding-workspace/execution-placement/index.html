                  Primitive：执行放置

                  Theme：编码工作面 · 成熟度：Accepted Primitive · 高风险命令 Situation

                  共识 Family：OpenHands、mini-SWE-agent、Cline、aider

                  执行放置决定一个 Action 绑定到哪个 Execution World：宿主机、容器、虚拟机或远端工作区。它拥有世界身份、工作区挂载和可达性生命周期，不拥有 shell 是否持续，也不能单凭“运行在容器里”证明安全隔离。

                  领域模型

                  要素 契约
                  输入 Action 的工作区、平台、资源、网络和凭据需求
                  状态 world identity、workspace root、placement kind、连接与租约状态
                  输出 可供 Tool Runtime 使用的执行端点与能力集合
                  所有者 创建、选择、重连和释放 Execution World 的 runtime 或宿主
                  终态 已释放、不可达，或仍可由稳定 identity 重新附着 
                  classDiagram
    class PlacementRequest {
      workspace identity
      platform and resource needs
      policy constraints
    }
    class ExecutionWorld {
      world identity
      workspace root
      filesystem and network view
      lease state
    }
    class ToolRuntime {
      action endpoint
    }
    class ExecutionSession {
      process continuity
    }
    PlacementRequest --> ExecutionWorld
    ExecutionWorld "1" --> "1..*" ToolRuntime
    ExecutionWorld "1" o-- "0..*" ExecutionSession

                  Execution World 是能力共同观察和修改的环境边界。一个容器可以承载许多一次性 shell；一个宿主目录也可以承载持久 PTY。前者是放置关系，后者属于进程连续性。

                  不变量

                  • 每个 Action 和 Observation 必须能关联到明确的 world identity；只记录 cwd 无法区分两个同路径的远端工作区。
                  • Shell、文件工具和语言服务若不共享世界，Harness 必须暴露分叉，不能让一边的检索结果冒充另一边的可执行状态。
                  • placement kind 只说明在哪里执行；filesystem、network、credential 和 process enforcement 属于独立的执行隔离契约。
                  • 远端 transport 断开不等于世界已销毁，世界仍运行也不等于客户端可安全重连。
                  • 释放世界前必须处理仍被引用的文件、进程和 Artifact；删除目录不能替代明确终态。

                  显露差异的 Situation

                  本机 LSP 与远端 Shell 观察到不同提交

                  Harness 在本机计算定义跳转，却把测试命令送到远端工作区。应观察两条能力是否携带同一 world/workspace revision，版本不一致时能否拒绝或显式降级。

                  恢复 Session 时原远端工作区已经消失

                  恢复应区分“Session 历史可读”和“原 Execution World 不可达”。实现可以重新 provision、要求重新绑定或保留部分恢复状态，但不能静默在另一个目录继续执行。

                  生命周期

                  stateDiagram-v2
    [*] --> Requested
    Requested --> Provisioning: choose placement
    Provisioning --> Ready: world identity assigned
    Ready --> Attached: tool runtime connected
    Attached --> Detached: transport lost or client leaves
    Detached --> Attached: reattach same world
    Detached --> Unreachable: lease expired or world removed
    Attached --> Releasing: explicit teardown
    Ready --> Releasing: unused world
    Releasing --> Released: resources and references settled
    Unreachable --> [*]
    Released --> [*]

                  Detached 与 Unreachable 必须分开：前者允许重连，后者表示原效果边界已经无法继续寻址。

                  各 Harness 的实现

                  OpenHands

                  • 状态 / 事实类型：implemented + documented
                  • 研究锚点：OpenHands 画像

                  OpenHands Canvas 把 Action execution 委托给 Agent Server runtime。宿主直跑时 agent 可访问宿主文件系统；Docker 是可选部署方式，只暴露显式挂载的项目路径。Canvas、runtime 与 workspace 的所有者因此必须分别记录，不能把前端仓库当作执行世界。Canvas 架构边界 · 宿主与 Docker 入口

                  mini-SWE-agent

                  • 状态 / 事实类型：implemented + implemented
                  • 研究锚点：mini-SWE-agent 画像

                  mini-SWE-agent 把 Environment 作为可替换放置边界，提供 Local、Docker、Bubblewrap、Singularity 与远端 SWE-ReX。Docker Environment 保留容器和文件系统，但每个 Action 仍通过新的 docker exec ... bash -lc 执行，直接证明放置与进程连续性正交。Environment 实现树 · Docker 实现

                  Cline

                  • 状态 / 事实类型：alternative + implemented
                  • 研究锚点：Cline 画像

                  Cline SDK 的 Bash executor 在宿主进程环境中启动 child process；固定实现没有在该工具边界 provision 独立容器或远端世界。由 SDK host 选择工作区是同一 Situation 的宿主放置方案，不应写成“没有执行放置”。Bash executor

                  aider

                  • 状态 / 事实类型：alternative + implemented
                  • 研究锚点：aider 画像

                  aider 直接在宿主机使用 subprocess.Popen(..., shell=True)。仓库根与宿主进程共同给出世界身份；确认建议命令是人类控制，不会把 Action 移到另一个 Execution World。命令执行实现

                  Gemini CLI

                  • 状态 / 事实类型：implemented + documented
                  • 谱系计数：Gemini CLI 与 Qwen Code 的同源 sandbox 基础只按一个 Harness Family 计数；本段记录 Gemini 锚点的放置契约。

                  Gemini CLI 可把 Shell Action 放到宿主、macOS Seatbelt、Docker/Podman、Windows native sandbox、gVisor 或预先存在的 LXC/LXD container；不同 provider 拥有不同的 filesystem、network 与 process 边界。Execution World 选择与 provider 契约 · gVisor 与 LXC 放置 LXC 路径要求容器已存在且运行，说明“选中 world”不等于 Harness 拥有其 provision、lease 或销毁生命周期。

                  Kilo Code

                  • 状态 / 事实类型：implemented + implemented
                  • 谱系计数：Kilo 是 OpenCode fork；这里只计 Kilo workspace adapter 的分化，不重复计入继承的本地执行设计。

                  Kilo 把 workspace Target 明确建模为本地 directory 或带 URL/headers 的 remote target，并让相同 workspace operation 按 Target 进入本地 store 或远端 HTTP 路径。Target 契约 · 本地/远端分派这证明 placement 可寻址；远端隔离强度与断线存活不由该 adapter 保证。

                  Loopal

                  • 状态 / 事实类型：implemented + implemented
                  • 谱系计数：local/cross-Hub child 是一个 Loopal Family 内的两种放置路径。

                  Loopal 的 local child 可继承 caller cwd、context 与 worktree path；cross-Hub spawn 则明确不传 cwd、fork context 或 resume，目标 Hub 使用自己的 default cwd。local/cross-Hub field boundary这把 placement/trust boundary 写进协议，而不是从路径名推断。

                  Claude Code

                  • 状态 / 事实类型：implemented + documented
                  • 谱系计数：本地、cloud 与 self-hosted runner 是同一 Claude Code Family 的不同 Execution World。

                  固定发布记录说明 claude self-hosted-runner 可让自有机器或容器承载 web、mobile 与 desktop Session。self-hosted environment它证明 Session 可放置到不同 world；world identity、lease、销毁以及重新附着时原 world 是否仍存活未公开。

                  Antigravity CLI

                  • 状态 / 事实类型：alternative + documented
                  • 谱系计数：TUI、SSH 使用方式与 GUI 共享 engine，只计一个 Antigravity Family。

                  官方 README 把 CLI 定位为适合 SSH/remote session 的终端界面，同时声明 CLI 与 GUI 共用 engine。SSH workflow 与共享内核这只证明 CLI 可在操作者选择的 host 上运行；没有公开 managed world provisioning、world identity 或 lease，所以标为 alternative。

                  MiniMax Code

                  • 状态 / 事实类型：unknown + documented
                  • 谱系计数：桌面、Remote Control 与所谓“远程任务”均属于同一 MiniMax Code Family。

                  Remote Control 只证明手机可附着桌面 Session，Worktree 只改变 workspace branch。Remote Control，v3.0.52（快照 2026-08-19）没有公开 Action 是否在远端 world 执行，也没有 world identity、lease 或销毁契约；因此执行放置保持 unknown。

                  Browser Use

                  • 状态 / 事实类型：implemented + implemented
                  • 谱系计数：本地 launch、已有 CDP endpoint 与远端浏览器是一个 browser-use Family 的 placement 选项，只计一次。
                  • 适用边界：它是跨域 Corpus Harness，只支撑浏览器 Execution World 的选择与连接语义，不支撑代码 workspace、容器或 Git placement 结论。

                  BrowserProfile 选择启动本地浏览器、连接现有 CDP URL 或使用远端 endpoint；BrowserSession 再拥有连接、focused target、watchdog 与事件总线。Browser profile和BrowserSession证明运行位置与 Session identity 分离；固定源码没有通用 world lease、代码快照、provision/join 或销毁协议。

                  设计策略与取舍

                  Execution placement 只回答 Action 在哪个世界发生。它不自动回答该世界是否安全、shell 是否持续、文件是否独立或客户端是否远程。

                  放置路线 代表 Harness World 怎样选择 Harness 拥有什么 主要收益 主要代价与失败点
                  宿主进程世界 aider、Cline、Antigravity CLI 的 SSH 使用方式 启动 Harness 的 host 与 cwd 决定 本地 process/workspace reference 最少 provisioning，和开发机工具链直接集成 环境漂移与 ambient credential 最大；“通过 SSH 操作”不等于 Harness 管理远端 world
                  可替换 Environment provider mini-SWE-agent、Gemini CLI local、OS sandbox、container、gVisor/LXC 或 remote provider provider selection 与部分启动契约 同一 Agent loop 可在多种环境运行 provider 能力不等价；选中已有容器不代表 Harness 拥有 provision、lease 或 teardown
                  前端委托 runtime OpenHands Canvas 把执行交给 Agent Server，再由部署选择 host/Docker/VM/remote UI 与 runtime owner 的明确边界 前端可独立演化，执行后端可替换 部署文档中的可选后端不能反写成当前 Run 的实际 placement
                  可寻址 local/remote target Kilo Code workspace Target 选择本地目录或远端 HTTP endpoint target identity 与 operation routing 控制面可用同一操作管理不同位置 adapter 可达不等于隔离、持久或可信；断线与远端 lease 需要额外协议
                  分布式 Hub placement Loopal local child 继承部分路径，cross-Hub child 由目标 Hub 选择 cwd Hub identity、spawn route 与字段边界 跨机器委派时能显式切断本地 cwd/context 假设 远端接受命令不等于已启动或已完成；trust、cancel 和 artifact 回流更复杂
                  产品级 cloud/self-hosted world Claude Code local、cloud 或 self-hosted runner 由产品入口选择 固定材料证明 Session 可在自有环境承载 用户可从 web/mobile/desktop 控制自己的 runner world id、lease、销毁与重新附着语义未公开，不能由 Remote Control 推断
                  领域专用远端世界 browser-use local launch、已有 CDP 或远端 browser endpoint BrowserSession 与连接/watchdog 对浏览器状态有专门 owner，适合网页任务 没有代码快照、Git 或通用 process contract；跨域证据不能替 coding placement
                  客户端远程但 placement 未知 MiniMax Code Remote Control 只改变控制入口 固定材料未定位 execution owner 可以远程观察和下指令 手机远程控制桌面 Session 不等于 Action 在云端执行

                  共同的最低记录应包含 world identity、provider、workspace root、provisioning owner、lease 和 teardown policy。只记录 remote=true 没有意义：它可能表示模型 API 在远端、客户端在远端、命令在远端，或三者的任意组合。

                  本地宿主最适合需要完整开发工具链的低延迟任务；容器/VM 适合可重复环境；remote target 或 Hub 适合弹性和多机器协作。每增加一层远端放置，都要补上连接失败、重复启动、旧 world 重连和 artifact 回传语义。隔离强度继续由执行隔离判断，shell/cwd 是否保留则由进程连续性判断。

                  反例与边界

                  • “支持 Docker”不是统一 placement contract；镜像、挂载、daemon 和生命周期所有者都可能不同。
                  • Worktree 改变 workspace identity，但通常仍在同一宿主 Execution World；它首先属于工作区事务。
                  • 持久远端工作区不保证持久 shell，也不保证断线期间输出可重放。
                  • 本页不判断允许哪些 Action；授权、审批与最大效果边界应分别记录。
