                  Primitive：进程连续性

                  Theme：编码工作面 · 成熟度：Accepted Primitive · 上下文预算压力 Situation

                  共识 Family：OpenHands、mini-SWE-agent、Cline、aider

                  进程连续性决定多个 Action 是否寻址同一个执行会话，以及 cwd、环境变量、PTY、前台进程和后台子进程能跨越哪些边界继续存在。它不决定进程位于本机还是远端，也不负责把全部输出放进模型 Context。

                  领域模型

                  要素 契约
                  输入 规范化命令、stdin、timeout/cancel signal、可选 session handle
                  状态 execution-session identity、cwd、environment、PTY/process tree、lease
                  输出 process handle、output chunks、exit status 与 terminal reason
                  所有者 创建、复用、取消和关闭执行会话的 Tool Runtime
                  终态 单进程结束、持久会话关闭，或失去控制后进入 orphaned 
                  classDiagram
    class ExecutionSession {
      session identity
      cwd
      environment
      terminal state
      lease
    }
    class CommandAction {
      action identity
      argv or shell text
      timeout
    }
    class ProcessHandle {
      pid or remote handle
      process-tree scope
    }
    class ProcessObservation {
      output reference
      exit status
      terminal reason
    }
    ExecutionSession "1" --> "0..*" CommandAction
    CommandAction --> ProcessHandle
    ProcessHandle --> ProcessObservation

                  持久文件系统不等于持久进程：容器可以在每次 Action 时新建 shell；宿主机也可以用 tmux 保留同一终端。进程所在世界由执行放置说明。

                  不变量

                  • 声称 cwd、环境变量或 virtualenv 跨 Action 保留时，必须存在稳定的 execution-session identity。
                  • Observation 必须区分 spawn failure、正常退出、非零退出、timeout、用户取消、transport 断开和 orphaned process。
                  • 取消等待方不等于杀死进程；取消必须传播到明确的 process tree 或远端 handle，并报告未能终止的后代。
                  • 关闭持久会话不能假装撤销已写文件、网络请求或外部服务效果。
                  • 原始输出的保留与下一次模型调用能看到多少输出是两个状态机；后者见工具输出保留。

                  显露差异的 Situation

                  先激活虚拟环境，再在下一 Action 运行测试

                  持久 shell 会继承 activation、cwd 和环境变量；每 Action 新进程必须在第二条命令中重新建立状态。Harness 应让模型知道采用哪种契约，不能靠偶然 shell 行为猜测。

                  长命令输出一部分后客户端取消

                  应检查 cancel 是否终止完整进程树、已经产生的输出是否仍可寻址、Action 写入什么终态，以及远端 transport 丢失时进程是否成为 orphaned。

                  生命周期

                  stateDiagram-v2
    [*] --> Creating
    Creating --> Idle: persistent session ready
    Creating --> Running: one-shot process spawned
    Idle --> Running: command admitted
    Running --> Idle: command exits, session retained
    Running --> Completed: one-shot process exits
    Running --> Cancelling: cancel or timeout
    Cancelling --> Idle: process tree stopped, session retained
    Cancelling --> Cancelled: one-shot process stopped
    Cancelling --> Orphaned: handle lost or child survives
    Idle --> Closing: explicit close or lease expiry
    Closing --> Closed
    Completed --> [*]
    Cancelled --> [*]
    Orphaned --> [*]
    Closed --> [*]

                  对一次性实现，Creating -> Running -> Completed 就是完整生命周期；不能因为没有 Idle 状态就写成不支持命令执行。

                  各 Harness 的实现

                  OpenHands runtime

                  • 状态 / 事实类型：implemented + documented
                  • 研究锚点：OpenHands 画像

                  OpenHands Terminal 把命令会话定义为持久 shell，cwd、环境变量和 virtualenv activation 可跨命令保留。Factory 优先使用 tmux，回退到 subprocess PTY；两种 backend 都由 Terminal session identity 提供连续性，而不是由 Canvas UI 提供。Terminal 契约 · Terminal factory

                  mini-SWE-agent

                  • 状态 / 事实类型：alternative + implemented
                  • 研究锚点：mini-SWE-agent 画像

                  mini-SWE-agent 为每个 Bash Action 新建进程，stdout/stderr 合流；默认 prompt 明确说明 cd 和环境变量不会跨 Action 保留。即使 Docker 容器持续存在，每次仍是新的 docker exec ... bash -lc。Local Environment · 默认契约

                  Cline

                  • 状态 / 事实类型：alternative + implemented
                  • 研究锚点：Cline 画像

                  Cline SDK 的 Bash tool 每次调用 Node spawn 创建 child process，继承宿主环境，并实现 timeout、AbortSignal 和跨平台进程树清理。它拥有单 Action 的 process handle 与取消语义，但不是持久 shell。Bash executor

                  aider

                  • 状态 / 事实类型：alternative + implemented
                  • 研究锚点：aider 画像

                  aider 为命令使用宿主 subprocess.Popen(..., shell=True)。固定实现证明命令有独立进程与输出收集，但没有持久 execution-session handle；需要持续的 cwd 或 environment 时，用户或模型必须把状态放进同一条命令或外部工具。命令执行实现

                  设计策略与取舍

                  当前样本形成两条清楚路线：保留一个可寻址 shell，或让每次 Action 使用新进程。容器是否持续存在与这项选择无关。

                  进程路线 代表 Harness 跨 Action 保留什么 取消与清理 主要收益 主要代价与失败点
                  持久 terminal Session OpenHands runtime cwd、环境变量、virtualenv 和 shell 内状态 Terminal identity 通过 tmux/PTY backend 管理，Session 负责关闭 适合交互式 REPL、开发服务器准备和多步命令，减少重复初始化 shell 状态会漂移且难复现；backend fallback、断线重连和孤儿进程需要显式处理
                  每 Action 新进程 + 完整取消 Cline 不保留 cwd/env 变更，只保留工具结果 保存 child handle、timeout、AbortSignal，并清理进程树 每次调用边界清楚，取消语义较强，宿主状态较少 复杂环境设置必须重复或写进命令；杀 wrapper 后仍要确认整棵子进程树静止
                  每 Action 新进程 + 极简环境 mini-SWE-agent、aider 不保留 shell 内状态；容器或工作目录可以另行持续 独立进程结束后收集输出，完整跨平台 reaping 契约较薄 实现简单、单步结果易理解，适合短命令 cd、export、激活环境不会自然延续；长服务需交给 tmux、Job registry 或其他外部 owner

                  共同点是每个命令都需要 execution identity、stdout/stderr、exit/cancel terminal；差异只在 shell state 是否跨 Action 留存。持久 shell 提高交互效率，却让后续命令依赖隐藏历史；新进程更可重复，却把环境准备成本交给每条命令或更高层脚本。

                  选择时先看任务是否真的依赖 shell 内存状态。编译、测试和一次性脚本通常适合新进程；REPL、持续 server 和多步调试适合持久 terminal。若进程要在 Turn 返回后继续，不能只把 terminal 留着，而应升级为后台 Job 生命周期并提供 stable id、日志和停止确认。

                  反例与边界

                  • “有 terminal tool”不能推断是持久 PTY，也不能推断 shell state 会跨 Action 保留。
                  • tmux、PTY 与 remote kernel 是实现手段，不是统一协议；session identity、lease 和取消范围仍需逐项记录。
                  • 把命令改写为 cd path && test 可以适配一次性进程，但没有把它变成持久会话。
                  • 持久 shell 增加隐藏状态，也扩大恢复所需覆盖；恢复聊天记录不恢复旧进程。
