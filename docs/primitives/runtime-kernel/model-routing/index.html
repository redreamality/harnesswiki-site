                  Primitive：模型接入与路由

                  Theme：运行内核 · 成熟度：Observed Pattern · Agent 循环

                  模型接入与路由把 Provider 认证与协议、模型能力、任务角色和某次 Step 的实际模型选择分开，使 Harness 能在不重写循环的前提下选择或切换推理后端。

                  领域模型

                  输入 路由状态 输出
                  Provider 配置、认证、模型清单 当前模型、角色映射、fallback、能力缓存 可执行的模型请求目标
                  工作模式与任务角色 architect/editor/reviewer 等绑定 每个 Step 的实际 model id
                  Session 恢复信息 历史模型与兼容性 继续使用、迁移或拒绝

                  不变量

                  • Provider 兼容同一种 API 不代表模型具有相同 tool、vision、reasoning 或 context 能力。
                  • “运行中换模”必须说明历史如何继续、能力差异如何处理，以及新选择是否持久化。
                  • 多模型角色不等于多 Agent；两个角色可以在同一 Turn 中串行调用并共享 Session。
                  • 自动 fallback 只有在保留触发原因和实际模型时才可审计。

                  显露差异的 Situation

                  从规划模型切到编辑模型

                  方案模型输出高层计划，编辑模型需要结合计划、当前文件和 edit protocol 生成变更。应观察两次请求是否使用不同上下文、工具权限和完成条件。

                  恢复会话时原模型不可用

                  Provider 凭据失效或模型被下线。Harness 可以要求用户选模、自动 fallback、以兼容模型继续或拒绝恢复；任何路径都应保留实际选择。

                  各 Harness 的实现

                  Pi

                  • 状态 / 事实类型：implemented + documented
                  • 研究锚点：见 Pi 画像

                  Pi 把统一模型 API 与 coding-agent core 分成不同包，扩展可以动态注册或覆盖 Provider；交互会话支持切换模型，并将 provider/model id 写入持久的 ModelChangeEntry。路由层因此可独立于默认四工具循环演进。

                  OpenCode

                  • 状态 / 事实类型：implemented + documented
                  • 研究锚点：见 OpenCode 画像

                  OpenCode 在 Provider/model 配置之外，还允许 agent 通过 model 配置覆盖全局选择。primary、subagent 与内部 agent 可获得不同模型绑定；固定配置示例为 build、plan 与 code-reviewer 指定了不同 provider/model id，因此路由输入包含工作角色，而不只是全局下拉框。

                  aider

                  • 状态 / 事实类型：alternative + documented
                  • 研究锚点：见 aider 画像

                  aider 的模型设置显式区分主模型、weak model 与 editor model，并在构造时解析角色模型及 editor edit format；architect 流水线再把选出的 editor model 交给新的 coder。它展示了模型路由与变更协议相互约束：切换模型可能同时改变模型输出应遵循的 edit format。

                  Gemini CLI

                  • 状态 / 事实类型：implemented + implemented
                  • 谱系计数：Gemini CLI 与 Qwen Code 共同继承的基础模型接入只计一个 Family；Qwen 的独立分化不重复计入本条。

                  Gemini CLI 为当前 Turn 组装包含 curated history、request 与 requested model 的 routing context；第一次决策后把选择固定为当前 sequence model，再经过可用性选择，并按最终 model id 重建工具声明。路由、序列粘性与最终工具面这让“路由输入”“本次连续调用实际使用的模型”和“模型相关能力面”成为三个可核验步骤，而不是只读取一个全局模型字符串。

                  设计策略与取舍

                  模型路由可以发生在 Session 开始、Actor 创建、任务阶段或每个调用序列开始时。选择越晚，越能适应当前任务；选择越早，连续性和可复现性越容易保证。

                  路由路线 代表 Harness 决策时机与输入 绑定的相邻状态 主要收益 主要代价与失败点
                  用户/Session 显式切换 Pi 用户或 extension 注册 provider，并在会话中切换 model id ModelChangeEntry 进入持久 Session 行为可见、易复盘，provider 可独立扩展 切换后 token budget、capability 和历史兼容性仍需重新计算
                  Actor/角色绑定 OpenCode primary、subagent、internal agent 配置选择模型 prompt、permission、role 与 child Session 不同角色可用不同成本和能力模型 角色配置漂移会让同名任务行为不同；fallback 必须保留实际选择
                  阶段模型 + 输出协议绑定 aider architect、main、weak、editor model 按流水线阶段选择 editor model 同时约束 edit format/coder 规划与编辑可分别优化，协议适配更精确 模型替换可能连带改变补丁语法；阶段交接和第二次调用增加延迟与错误面
                  每 sequence 动态路由 Gemini CLI 当前 history、request、requested model 与可用性在 Turn 内决定 sequence model、tool declarations 与后续 continuation 能根据任务和可用性选择，同时保持同一工具序列模型稳定 路由器、availability fallback 和工具面重建必须原子一致；中途漂移会破坏 tool-call 连续性

                  四条路线都不能只保存“用户请求的模型”。可审计记录至少需要 requested、selected、实际 provider/model、fallback reason、capability snapshot 和适用范围。否则一次失败可能来自模型本身，也可能来自路由降级后工具 schema、上下文窗口或 edit format 已经改变。

                  默认选择应与状态边界匹配：短会话和人工控制适合显式切换；多 actor 系统适合角色绑定；有明确规划/编辑阶段时可绑定阶段协议；动态流量、可用性或上下文差异明显时才值得每 sequence 路由。无论哪条路线，同一批并行 tool call 开始后都应保持模型和工具声明稳定，除非协议明确终止旧 sequence 并建立新边界。

                  反例与边界

                  • 模型供应商 SDK 只解决请求传输，不自动拥有 Session 恢复、角色路由或完成判定，因此不是 Harness。
                  • 按价格、延迟或错误做自动负载均衡是可选策略，不是本 Primitive 的固定阶段。
                  • Context Snapshot 怎样适应目标窗口属于上下文压缩。
                  • 模式怎样限制工具属于Agent 循环与工作模式。
