                aider

                语料层级：Anchor Harness · 形态：交互式 CLI
                研究锚点：main@5dc9490bb35f9729ef2c95d00a19ccd30c26339c · 快照日期：2026-08-17
                许可证：Apache-2.0 · 谱系：aider

                aider 是面向本地 Git 仓库的 AI pair programmer。它把 Repo Map、可替换 edit format、Git commit/undo 与 lint/test feedback 做成可观察的专用链路，适合与“只给模型一个 Bash”的极简 Harness 对照。

                纳入理由与边界

                aider 拥有持续对话循环、模型角色与 coder 模式、代码相关性表示、文件编辑协议、命令执行、Git transaction 和验证反馈。它不是单次补丁生成器，也不是只提供 SDK 的框架。

                自身领域模型

                flowchart LR
    Chat["chat files + mentioned identifiers"] --> Map["RepoMap"]
    Map --> Coder["Coder / edit format"]
    Coder --> Parse["parse + dry-run"]
    Parse --> Files["workspace changes"]
    Files --> Git["auto commit / undo boundary"]
    Files --> Check["lint / optional test"]
    Check -->|failure + user confirms| Coder
                • RepoMap 是有 token 预算、随对话变化的代码表示，不是 LSP。
                • Coder 族把 whole、search/replace、unified diff、patch 等 edit format 作为可替换协议。
                • Architect 模式先由 architect 产生方案，经用户确认后创建 editor coder，用第二次模型调用实施。
                • Git 记录 AI 变更边界；chat history 可从 Markdown 恢复消息，但不构成完整工具/进程 checkpoint。

                已研究 Primitive

                Primitive 状态 aider 的实现取向
                Agent 循环与工作模式 implemented coder 类型与 architect/editor 两阶段角色
                模型接入与路由 implemented 主模型、editor/weak model 等角色化选择
                代码库智能 implemented Tree-sitter tags + personalized PageRank + token 裁剪 Repo Map
                变更生成与应用 implemented 多 edit format；search/replace 先 dry-run 后写盘
                执行放置 alternative 命令直接放在启动 aider 的宿主环境，没有独立 world provisioning
                进程连续性 alternative 每次命令经独立 Popen(..., shell=True) 执行，不提供持久 shell identity
                验证与反馈 implemented 默认 auto-lint；test opt-in；失败经用户确认反射到下一轮
                版本控制与工作区事务 implemented dirty baseline、auto-commit 与受限 /undo
                状态持久化与恢复 alternative Markdown chat history 可恢复消息，运行/工具状态不在覆盖范围
                Artifact 交付 implemented Git commit/diff 与聊天输出提供可检查的变更引用，交付不等于远端合并

                Repo Map 管线

                sequenceDiagram
    participant C as Coder
    participant R as RepoMap
    participant T as Tree-sitter
    participant G as Reference Graph
    participant B as Token Budget

    C->>R: repo files + chat files + mentioned ids
    R->>T: extract definitions/references
    T-->>R: tags
    R->>G: build MultiDiGraph + personalization
    G-->>R: PageRank-ranked tags
    R->>B: render tree candidate
    B-->>R: binary-search fitted representation
    R-->>C: budgeted Repo Map

                设计取向

                • 专用代码表示：用符号引用图与对话 personalization 预先缩小仓库，而不是完全依赖模型反复 grep。
                • 编辑协议显式可替换：不同模型可以使用不同输出语法，applicator 负责定位与明确失败。
                • Git 是交互事务的一部分：auto-commit 和 /undo 有所有权与安全前置条件。
                • 验证由人类控制闭环：lint 默认自动，修复失败和测试触发仍保留用户决策。

                已知证据空白

                • 未发现 LSP 驱动 Repo Map 的证据；不能把 Tree-sitter 标签图写成 LSP。
                • 本机命令执行没有通用 isolation，建议确认不是 OS enforcement。
                • chat history restore 不恢复 cwd、子进程或完整工作区 Checkpoint。
