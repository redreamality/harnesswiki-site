                  Mistral Vibe

                  Corpus Harness 索引 · 形态：CLI / Programmatic / ACP / App Server
                  研究锚点：mistralai/mistral-vibe v2.24.2@5e6aa0f6beb3454454f4c1de74a7652ba577ab05 · 快照日期：2026-08-19
                  许可证：Apache-2.0 · Python：>=3.12

                  Mistral Vibe 是拥有完整 Agent loop、模型历史、permissioned tools、Session store、worktree ownership 和多种交付表面的 Coding Harness。本页只陈述固定提交可见的开源 CLI/core/app-server 契约；Mistral 托管模型、Vibe Code 云端项目与桌面宿主的不可见内部实现不由这些源码替代证明。

                  定位与边界

                  vibe/core 是模型与工具执行引擎，vibe/app_server 是外部 Session、Turn、callback 和事件投影的 composition root；Textual CLI、ACP 与 programmatic mode 都适配同一个 app-server client API，而不是各自重写 loop。架构决策

                  这形成三个不能混写的身份：core AgentLoop 拥有模型上下文和工具执行；app-server Session 拥有客户端可见 Turn/callback/event watermark；Git worktree 则由独立 claim、ownership record 和 holder marker 标识。恢复某个 Session 不自动证明旧进程、旧 worktree 或全部外部副作用也被恢复。

                  事实类型限定如下：本页的源码和测试断言均为 implemented，README/ADR 为 documented；本轮没有启动 Vibe 或执行上游测试，因此没有 observed Claim。

                  • SessionMetadata 保存 parent/child 关系、消息元数据与可选 created_worktree；消息内容和 metadata 分开落盘。
                  • ToolEffect 在公开投影中把 call、stream、approval block、result、duration 和终态收敛为一个 effect identity。

                  • Checkpoint 记录 Turn 边界与文件前后状态，供 rewind 使用；它不是进程、网络或任意外部副作用的全世界快照。

                  一次 Turn 由 app server 创建稳定 identity，core 以 async generator 产出 assistant、reasoning、tool、approval、compaction 等 typed events。app server 将它们归约为客户端 projection；公开事件 ID 必须单调，客户端发现 gap 时通过 session/read 整体替换 snapshot，而不是猜测缺失增量。事件式 loop 决策 gap 与 snapshot 测试

                  Primitive 反向索引

                  Primitive 状态 Mistral Vibe 中的实现
                  会话与运行拓扑 implemented 本地 Session identity、parent/child link、app-server runtime 与客户端 projection 分层
                  Agent 循环与工作模式 implemented event-driven async loop，支持默认、plan、explore、自定义 agent profile 与预算 middleware
                  上下文压缩 implemented compaction summary 形成显式边界；失败不修改 live messages，overflow 按完整 round 裁剪
                  工具与能力运行时 implemented Pydantic args/result/config/state、内建工具、MCP、skills、hooks 与 client-hosted ToolIOPort
                  版本控制与工作区事务 implemented worktree claim、holder、base commit、dirty/untracked/ahead 检查与保守清理
                  Action 授权 implemented 工具声明 required permissions；workspace 外路径、shell 语义和永久/session allow 分开判定
                  状态持久化与恢复 implemented 本地消息与 metadata resume；恢复后的模型请求保留历史 tool call/result，worktree 另域处理
                  Actor 委派 implemented child Session link、parent identity、独立 Agent profile 与 Task tool 结果回传
                  控制平面 implemented typed app-server host/session API 为 CLI、ACP、programmatic surface 提供同一控制入口
                  在线事件流 implemented 单调 event ID、增量 patch、callback blocked 状态和 snapshot gap reconciliation

                  关键差异

                  Approval 是工具 effect 的中间状态

                  工具先将参数解析为类型化 permission requirement，再由 loop 发出带 request_id 和 tool_call_id 的 approval event。app server 先投影 callback，随后把关联 effect 标成 blocked；客户端回答可只批准一次、批准本 Session、永久批准、拒绝或取消 Turn。永久决策进入 permission store，拒绝反馈则回到模型可见结果。permissioned tool 决策 approval/rejection characterization

                  这证明的是 Action policy 与单客户端 callback lifecycle；没有多审批者身份、quorum 或跨进程 pending durability 的证据，不能把它扩写成多人审批系统。

                  Worktree 删除以 ownership 和未交付工作为门槛

                  命名 worktree 可以复用同仓库同分支，自动命名路径则先原子 claim 再创建，冲突时选择新名称。释放前同时检查 ownership record、其他 holder、uncommitted/untracked 内容以及 base commit 之后的提交；记录缺失、被占用或存在工作时均保留。崩溃遗留 holder 会造成安全方向的泄漏，而不是让另一个进程误删目录。worktree 实现测试

                  因此 worktree 是带保守回收协议的 Execution World binding，不是 Session JSON 的附属字段；CLI 自动退出清理和 app-server 删除 Session 的规则也不同。

                  Rewind 只声明它实际记录的文件效果

                  每个 Turn 开始时 recorder 为上轮涉及文件建立 pre-edit snapshot，工具写入前继续补记录，Turn 结束后 seal post-edit state。rewind 可以恢复 write/edit/bash 删除造成的文件状态，也可以只裁剪消息而保留文件；新 Turn 会从被选中的边界继续。recorder rewind 集成测试

                  这些断言不覆盖远端 API、已经发送的消息、数据库事务或旧 shell process；“文件可回退”不能写成全运行原子 rollback。

                  Compaction failure 不污染活动历史

                  compaction manager 先在候选副本上生成 summary；primary 失败时可走 fallback，超长输入按完整对话 round 裁剪，只有成功结果才提交边界。测试还固定了 tool call/result 在 fallback transcript 中保留、失败时 live messages 不变，以及 compaction 不消耗普通 Turn budget。管理器 边界测试

                  摘要是否忠实仍取决于模型；“提交是事务式的”不等于语义信息无损。

                  已知证据空白

                  • 画像基线没有执行 CLI、ACP、app-server 或上游测试。2026-10-24 的取消与静止探针在同一固定提交上执行真实 cancel_tasks()，得到模块级 observed 证据；其他运行行为仍保持源码级 implemented。
                  • app-server 的单调 event ID 与 gap snapshot 已有测试，但跨进程 durable cursor、长时间断线窗口、backpressure、多 writer ownership 和认证租约没有闭合证据。
                  • Session resume 能恢复模型历史中的 tool call/result；pending callback、managed shell process、MCP connection 和 hook 子进程是否跨 crash 恢复仍为 unknown。
                  • worktree holder 在强杀后选择保留；自动判断 holder 已过期、跨客户端接管和用户确认后的安全回收没有统一协议。
                  • checkpoint 覆盖文件内容，不覆盖任意外部副作用；并发文件 writer、rename/symlink 竞态和超大二进制恢复边界仍需专门实验。
                  • ACP 与 programmatic surface 共享 engine 不等于所有客户端具有完全相同的展示、取消、文件托管或认证能力。
