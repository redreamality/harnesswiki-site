                Gemini CLI

                Corpus Harness 索引 · 层级：Validation Harness · 快照：2026-08-17
                研究锚点：main@2a87e7be103308b8734246097ba723cc7deb4122 · 包版本：0.56.0-nightly.20260806.g761f604c1 · 许可证：Apache-2.0 本地物化：571851b1077a51cef757146ce13f9da887326bec（2026-08-25）· 与研究锚点漂移，旧 Claim 保留原 SHA，迁移待逐 Claim 审计

                Gemini CLI 是本地交互式、headless 与 ACP 形态共用 core 的 Coding Harness。Core 拥有模型循环、工具调度、Context Graph、Policy、checkpoint、Session 录制与恢复；CLI/ACP 是不同控制面。

                为什么纳入

                Gemini CLI 是首批八个 Anchor 之外的独立验证样本，用来检查既有 Primitive 是否过拟合。它还与 Qwen Code 形成 Harness Family：Qwen 起源于 Gemini CLI v0.8.2，共同继承的机制不能当成两票。

                本锚点提供四类高价值证据：

                • AgentProtocol 将 activity stream、subagent thread 与 trajectory event 分开。
                • 实验 Context Graph 保存节点变换血缘，不把上下文当线性消息数组。
                • Shadow Git checkpoint、conversation rewind 与 session worktree 是不同工作区机制。
                • Policy decision、用户 confirmation 与 OS/container sandbox 是不同安全边界。

                streamId 标识一段 Agent activity，threadId 标识 actor/context 分支；二者都不是 Session id。Trajectory 保存运行事件，Context Graph 则是模型输入的活动投影，后者的节点可通过 replacesId/abstractsIds 保留变换来源。

                来源：AgentProtocol · Context 实现

                架构取向

                旧 core 的 client/turn 路径仍能在一个外部输入内跨多次模型请求和工具反馈；client 负责 loop detection、model selection、turn budget 与 next-speaker continuation。因此 Turn != 单次模型请求 在另一个谱系中再次成立。

                来源：Client loop · Turn events

                三个有解释力的细节

                Context Graph 把压缩建模为有血缘的变换

                异步 state snapshot processor 以旧 snapshot 和 aged-out nodes 生成候选 {newText, consumedIds}；应用前同步 processor 验证 consumed ids 仍在当前 graph，失效时重新生成。新 SNAPSHOT 节点用 abstractsIds 保留被摘要节点血缘。

                来源：Async snapshot · 应用与一致性校验

                Rewind 不等于完整环境恢复

                编辑工具前可在 ~/.gemini/history/<project_hash> 的独立 shadow Git repo 建立 commit，并保存 conversation/tool call。Rewind 可以只回会话、只回 AI 文件编辑或两者；文档明确不撤销手工修改与 Shell 造成的变化。

                来源：Checkpoint · Git service · Rewind

                ACP 可以把文件能力代理给客户端

                ACP mode 通过 stdio JSON-RPC 覆盖 initialize/auth/new/load/prompt/cancel/mode/model，并可把 filesystem call 代理给 client。这说明控制面协议不仅传 UI 事件，也会重新放置 capability ownership。

                来源：ACP mode

                证据空白

                • Context Graph profile 属实验路径；源码存在不等于稳定版本默认启用。
                • 固定锚点未定位到可核实的原生 LSP tool，状态为 unknown，不是 absent。
                • 未找到“每次编辑后自动跑 lint/test”的通用 controller；验证主要由 Agent/tool loop 驱动。
                • Session resume 不保证恢复所有 shell side effect、外部进程与服务状态。
