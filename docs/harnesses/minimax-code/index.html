                MiniMax Code

                Corpus Harness 索引 · 层级：闭源 / 黑盒 Harness 样本 · 快照：2026-08-19
                研究锚点：桌面端 v3.0.65（2026-08-13） · 官方产品页
                许可证 / 分发：macOS 与 Windows 官方桌面二进制；本轮官方入口未提供核心源码仓库或 OSS 许可证

                MiniMax Code 是桌面端通用 Agent / coding Harness。官方产品页把 Agent Team、长期记忆、聊天软件接入和 workspace 作为同一产品能力；版本化更新日志进一步记录 Session、Goal、工具、权限、Worktree、Artifact 和 Remote Control 行为。本页只描述这些公开可观察契约，不猜测闭源内核使用的类、数据库 schema 或 Agent loop 实现。

                定位、计数与证据边界

                • macOS / Windows 桌面端、minimax 命令行快捷入口、手机 Remote Control 和 IM channel 是同一 MiniMax Code 产品的入口，只计 一个 Harness。
                • Agent Team 的主 Agent、subagent 和定时任务 worker 是同一 Harness 内 actor / job，不独立计数。
                • Work mode 与 Coding mode 是工作模式，不是两套 Harness。
                • 官方更新日志曾提到内置 OpenCode 兼容问题，但这不足以证明 MiniMax Code 的当前核心就是某个公开 OpenCode commit；本页不建立该源码映射。
                • 没有已核验的官方核心 Git 仓库，因此 MiniMax Code 不计入本项目的 68 个 Git upstream，也没有伪造 commit permalink。
                • 本页没有安装或运行二进制，所有 Claim 的事实类型均为 documented，没有 observed。

                Session 是可搜索、归档、恢复并绑定项目的对话身份；Turn 可接收排队追加消息；Goal 是跨多个 Turn 持续推进、等待信息或权限并产生明确终态的工作对象。Workspace 表达当前项目或独立分支绑定，ClientAttachment 只表达谁在控制 Session，不说明 Action 在哪里执行。

                已研究 Primitive

                Primitive 状态 事实类型 MiniMax Code 的可核验取向
                会话与运行拓扑 implemented documented Session 可按项目分组、搜索、归档、恢复；Team actor 属于 Session 内拓扑
                Agent 循环与工作模式 implemented documented Coding / Work mode 与 Goal mode 改变推进方式；内部模型请求循环未知
                上下文压缩 implemented documented 自动摘要与 /compact 有状态反馈；摘要选择、provenance 和损失边界未知
                指令发现与组装 unknown documented Skill、项目约定和记忆会影响行为，但来源作用域、precedence 与 trust 契约未公开
                长期记忆 implemented documented 用户 / Agent / 项目三层记忆与主动记忆跨 Session 调用
                工具与能力运行时 implemented documented 文件、终端、Browser Use、MCP 与 Skill 形成可扩展能力集合
                Action 授权 implemented documented 允许 / 确认 / 阻止三态与 HARD / SOFT 风险规则决定敏感动作能否继续
                审批协调 implemented documented 桌面、Remote Control 与 Goal 节点可呈现权限请求；对外提交前再次确认
                审批者身份 unknown documented IM 首次发送者验证已记录，但跨 desktop / mobile / IM 的统一 approver identity 和竞争语义未知
                执行隔离 unknown documented Worktree、回收站与权限规则不等于 OS sandbox；官方材料未给出稳定效果边界
                执行放置 unknown documented Remote Control 和“远程任务”不证明 Action 在远端 world 执行，world identity / lease 未公开
                工作区事务 implemented documented 可在当前项目、独立分支或已有分支运行；完整 rollback / side-effect 边界未知
                工作拓扑 alternative documented Goal、Agent Team 与消息队列组织工作；claim、dependency cycle 与 join contract 未公开
                Actor 委派 implemented documented Agent Team 与并行 subagent 暴露主/子 Actor 分工；lineage 与取消协议未公开
                后台 Job 生命周期 alternative documented 定时任务与后台队列可持续推进；稳定 Job id、output cursor 与 crash recovery 未公开
                Goal 证据协议 alternative documented Goal 有 completed / unable-to-continue 终态和补充信息节点，但没有公开独立 evidence verifier
                控制平面 implemented documented 手机可查看进度、发送指令和审批，IM /stop 与桌面停止指向同一运行
                持久 Transcript implemented documented 历史可搜索、归档和 resume；存储 schema、原子性与 branch lineage 未公开
                Artifact 交付 implemented documented 文件结果、代码行定位、Office 预览与 Browser preview 形成用户交付面

                关键可核验行为

                Goal 暴露持续工作的生命周期

                v3.0.54 的 Goal mode 记录了 status、elapsed time、补充信息节点、权限申请以及 completed / unable-to-continue 两类明确结果。它证明 Goal 不是单个长模型请求，也不是普通 todo label；但官方材料没有公开 goal revision、evidence verifier 或持久队列 schema。Goal mode，v3.0.54（2026-07-27，快照 2026-08-19）

                授权、审批和隔离不能互相替代

                v3.0.27 把 permission classifier 升级为 allow / confirm / block，并要求灾难性命令必须确认；v3.0.28 又记录 HARD / SOFT 风险 registry 与 LLM 审查理由。Browser Use 对发布、发送、提交等外部副作用在执行前再次确认。这些行为能证明 authorization 与 mediation，不能证明所有工具都被 OS sandbox 约束。权限版本记录，v3.0.27、v3.0.28、v3.0.54（快照 2026-08-19）

                Worktree 改变 workspace，不证明 execution world 改变

                v3.0.30 提供 Worktree mode，v3.0.34 将入口改为“当前项目 / 独立分支 / 已有分支”，v3.0.46 又增加 base ref 选择。它们共同证明 workspace transaction 与 actor binding；没有容器、VM、远端租约或网络边界资料，所以执行放置与隔离仍为 unknown。Worktree 版本记录，v3.0.30、v3.0.34、v3.0.46（快照 2026-08-19）

                长期记忆与上下文压缩处理不同状态

                v3.0.20 记录用户 / Agent / 项目三层跨会话记忆，v3.0.58 增加主动记忆；另一路径在 v3.0.23 展示自动压缩摘要，并在 v3.0.46 为 /compact 增加状态反馈。前者跨 Session 保存可复用知识，后者缩减当前模型输入，不能合并成一个“记忆”机制。记忆与压缩版本记录（快照 2026-08-19）

                Remote Control 是 Session 控制，不是远程执行证据

                v3.0.52 允许手机查看桌面 Agent 进度、发送指令并处理权限审批；v3.0.37 至 v3.0.40 记录 IM /stop 与桌面停止按钮一致。它们证明多个客户端可以控制同一运行，但没有公开 session address、run id、event cursor、断线 replay 或 writer ownership。Remote Control 与 IM stop（快照 2026-08-19）

                版本、分发与开放性

                • 官方更新日志在本轮快照中的最新桌面版本为 v3.0.65，发布日期 2026-08-13，提供 Apple Silicon、Intel macOS 与 Windows 64-bit 下载。
                • 官方下载页提供 macOS 与 Windows 二进制，并把 Agent Team、memory、chat integration 和 workspace 作为产品能力。官方下载页（快照 2026-08-19）
                • 本轮检查的官方产品页与文档没有给出核心源码仓库或 OSS license；因此页面保持“闭源 / 黑盒”证据等级，不根据包内容、旧产品名或第三方仓库猜实现。

                已知证据空白

                • Agent loop 的 request / tool scheduling、completion condition、retry 和 interruption propagation 均为 unknown。
                • Session、Goal、Team 和定时任务的持久 schema、transaction boundary、branch lineage 与 crash recovery 保证均未公开。
                • Skill、memory、项目约定和系统提示词的 precedence、provenance、trust 与压缩后重组规则均为 unknown。
                • 三态 permission classifier 的规则覆盖面、LLM classifier 输入、fail-open / fail-closed 路径和审计日志 schema 未公开。
                • Remote Control / IM 的认证绑定、command correlation、event ordering、重连 replay 与多客户端审批竞争结果未公开。
                • Worktree 之外的进程、数据库、服务、网络和凭据副作用如何隔离或恢复仍为 unknown。
                • “自主组建小队”说明产品行为，不足以证明 actor mailbox、共享任务存储、取消传播或 work ownership 的内部协议。
