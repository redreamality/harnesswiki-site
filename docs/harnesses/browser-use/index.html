                browser-use

                Corpus Harness 索引 · 层级：跨域 Corpus Harness（非 Coding Harness）
                研究锚点：browser-use/browser-use v0.13.8@3c989dc0adc594d592be62272d70e28caaa5553b · 快照日期：2026-08-19
                许可证：MIT · Python：>=3.11,<4.0

                browser-use 是以网页任务为目标的可执行 Harness：它拥有模型 loop、浏览器状态投影、类型化 action registry、BrowserSession event bus、任务历史和可选 trace judge。它适合检验跨域的 Action/Observation、Execution World、轨迹与终态验证边界，但不得据此支撑代码库理解、补丁应用、测试反馈或 Git 工作区事务等 coding-specific 结论。

                定位与边界

                本页研究固定提交中的开源 Python library/CLI。browser-use 依赖独立的 browser-harness package，并可连接本地 Chrome、已有 CDP endpoint 或云浏览器；本页不会把依赖包、托管 Browser Use Cloud 或远端浏览器提供商的不可见实现算作本仓库源码事实。package metadata

                这里还需区分三个经常都被叫作“Session”的对象：Agent 的 session_id 用于一次任务运行与 telemetry；BrowserSession 拥有 CDP connection、tab focus、watchdog 和事件总线；浏览器 storage_state/profile 则保存 cookie 等网站身份。三者可组合，但保存 profile 不等于恢复 Agent 的模型历史或未决 Action。

                事实类型限定为 implemented 与 documented。本轮读取了固定源码和测试，但没有启动浏览器、模型或上游测试，因此不产生 observed Claim。

                • AgentState 是可序列化的 loop state，包含暂停/停止、Step、计划、消息管理和文件系统状态；运行中的 asyncio event 不在其中。
                • BrowserSession 把浏览器生命周期拆成 typed events 与 watchdog，支持 launch、connect、stop、reconnect 和状态请求。
                • BrowserStateSummary 是给模型的当前网页投影，不是完整 CDP event log；每步历史另保留交互元素、URL、结果与可选 screenshot path。
                • ActionRegistry 将 Pydantic action model、注入参数与 terminates_sequence 等执行元数据绑定，内建 navigate、click、input、upload、extract、evaluate 和 done。
                • JudgementResult 是可选 LLM judge 对 task、trace、最终文本和最多十张截图的判定；它与 Agent 自报 success 并存，不覆盖原终态。

                架构与单步时序

                flowchart LR
    Task["Task + optional ground truth"] --> Agent["Agent loop"]
    Agent --> MM["MessageManager"]
    MM --> Model["LLM"]
    Model --> Actions["typed ActionModel[]"]
    Actions --> Registry["Tools / Registry"]
    Registry --> Session["BrowserSession event bus"]
    Session --> World["Local Chrome / existing CDP / remote browser"]
    World --> State["DOM + tabs + URL + screenshot"]
    State --> MM
    Registry --> Result["ActionResult"]
    Result --> History["AgentHistoryList"]
    History -. optional .-> Judge["Trace judge"]

                每个 Step 读取当前 browser state、构造 model messages、解析一到多个 action、执行并把 ActionResult + BrowserStateHistory 追加到 trajectory。批量 action 不是盲目顺序执行：navigate 等 action 用静态 terminates_sequence 截断队列，每个 action 后还比较 URL 与 focus target；页面变化会丢弃剩余基于旧 DOM 的 action。loop 与 multi-action guard guard tests

                Primitive 反向索引

                Primitive 状态 browser-use 中的跨域实现
                Agent 循环与工作模式 implemented browser state → model → typed actions → results 的 Step loop，支持 plan、pause/stop、max steps 与 follow-up task
                上下文压缩 implemented 将 task、完整 step history 与 read state 生成 summary，提交后记录 compaction count/boundary
                工具与能力运行时 implemented 类型化 registry、依赖注入、custom action 与页面/文件/提取工具
                执行放置 implemented BrowserProfile 在本地 launch、已有 CDP endpoint 与远端浏览器之间选择 Execution World；不表示代码 workspace placement
                Action 授权 alternative allowed/prohibited domains、可选 IP blocking、敏感值替换与 upload containment 是预执行 policy；没有逐 Action 人工审批
                验证与反馈 alternative trace judge 对网页任务、历史、截图和 ground truth 判定，且保留自报 success；不能替代 coding test/build feedback
                评测 Trajectory implemented 每步 model output、action result、browser state、耗时、usage 与可选 judgement 可序列化/加载
                产物交付 alternative done action 返回文本/结构化结果并附带 sandbox 文件；没有通用远端 artifact manifest

                关键差异

                BrowserSession 是事件化 Execution World，不是对话记录

                BrowserSession 使用 resilient event bus 将 browser start/stop、launch/connect/kill、tab、navigation、DOM、download、screenshot、storage state 与 reconnect 分给 watchdog。BrowserProfile 决定启动参数、CDP URL、profile 路径和 keep_alive；远端 connection lost 时可产生 reconnecting/reconnected 事件。Session 与 watchdog 组合 事件契约

                这些事件解决浏览器资源协调，但没有证据表明它们是可跨进程重放的 durable transcript。keep_alive、cookie storage_state 和 reconnect 也分别只说明进程释放策略、网站身份与 CDP transport，不应写成完整 Agent resume。

                模型看到的是受控状态投影

                MessageManager 将 task、系统指令、历史、上一步结果和当前 BrowserStateSummary 组装为请求；state message 可包含 URL、tabs、DOM、截图与可用文件。达到配置门槛时，compaction 输入包含 task、完整 agent history 和 read state，并在发送前过滤敏感值；成功后更新 summary 与 compaction boundary。message manager compaction tests

                当前源码中的逐消息 token 展示仍有 TODO，所以本页只确认 compaction state machine，不声称其 token accounting 已形成精确、跨模型一致的预算器。

                Stale DOM 由静态和动态两层 guard 阻断

                模型可以在一个 Step 中返回多个 action。注册表先声明 navigate/search/go-back/switch 等会终止序列；对其余 action，loop 在每次执行后比较 URL 和 focus target。任一变化都会停止剩余 action，避免把先前 selector map 的 index 应用到新页面。click 还区分 DOM index 与坐标输入，并由 browser event handler 返回 validation metadata。action 实现

                这是网页环境里的 Observation freshness 机制；它不能证明并发文件编辑、Git branch 或编译产物也有同样的一致性保护。

                安全边界是 policy gate，不是人类审批

                BrowserProfile 可配置 allowlist、denylist 与可选 block_ip_addresses；测试覆盖 wildcard、redirect、认证绕过、IPv4/IPv6 及非标准编码。upload action 又把 Agent 文件路径限制在受管 filesystem，远端 Session 不会因 basename 碰撞而改写成本地任意文件。历史序列化和 compaction 输入会替换已声明 sensitive values。domain tests IP tests upload containment

                block_ip_addresses 默认是 false，domain policy 也不理解购买、发送或删除等业务副作用；没有 callback identity、用户确认、quorum 或 durable approval record。因此这里只视为 Action 授权的替代策略，不视为审批协调实现。

                Judge 不覆盖 Agent 自报终态

                done action 写入 is_done、success、最终文本和 attachments。可选 judge 另读取 task、结构化 step trace、最终结果、ground truth 与截图，返回 verdict、failure reason、impossible/captcha flags；结果附到最后一个 ActionResult，但源码明确保留 self-reported success，telemetry 可以比较两者。judge input 终态与 judge 分离

                这提供了有价值的外部复核结构，但 judge 仍是模型判断，不是网站数据库、邮件收件箱或付款系统的权威回执。

                已知证据空白

                • 本轮没有实际启动 Chrome、远端 CDP、模型或 pytest；页面只记录固定源码与测试中的 implemented 契约。
                • 本样本不拥有 repository map、代码 patch、Git baseline/join 或自动 build/test controller；任何 coding-specific 页面都不能把它算作支持证据。
                • AgentState 可注入、AgentHistoryList 可保存/加载，但 crash 后如何恢复未决 action、事件总线、focus identity 与网站副作用没有完整协议证据。
                • BrowserSession reconnect 是 transport/runtime 行为；断线期间事件是否耐久、cursor 如何重放、多客户端谁拥有 tab 和 action writer 仍为 unknown。
                • domain/IP/upload policy 限制访问面，不判断业务动作风险；默认配置、custom action 和直接 CDP/evaluate 路径仍需端到端安全验证。
                • sensitive-data redaction 依赖调用者声明的值，不能证明网页、截图、下载、第三方日志和模型 provider 中没有其他秘密泄漏。
                • judge 的正确率、ground-truth provenance 与 adversarial page resistance 没有在本页实测；verdict=true 不是外部世界完成证明。
                • 开源 README 中的 Cloud scalability、stealth、proxy 与 persistent filesystem 声明不作为本地库内部机制证据。
