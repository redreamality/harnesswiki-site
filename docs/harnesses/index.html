                Corpus Harness 索引

                导航：首页 · 设计精髓总览 · 机制地图 · 情境索引 · 生态调研

                Harness 页面是版本化实现画像和 Primitive 反向索引，不复制横向机制正文。第一次阅读不要从 20 个项目名中随机选择；先用设计精髓总览按极简循环、专用编码工作面、事件事实源、Server/daemon、IDE 内嵌、多 Actor 与跨域运行等设计路线建立对照。

                当前共有 20 个 Corpus 画像：19 个 Coding Harness + 1 个跨域 browser-use；其中 17 个画像有固定提交下可读的核心源码（16 个 Coding Harness + browser-use），3 个闭源/黑盒画像只依据固定版本的官方发布材料与公开契约。20 个画像中有 19 个对应本地 gitlink，MiniMax Code 是唯一尚无已核验官方核心 Git 仓库的画像。画像的研究锚点与本地 gitlink 是否一致仍需按设计独有性调研底稿逐项审计，不能机械替换 SHA。源码可读不等于开源；Loopal 的公开源码采用专有许可证。browser-use 只检验通用跨域机制和边界，不支撑 coding-specific 结论。

                Pi TUI、Print/JSON、RPC、SDK 源码可读 Session tree、极简工具、扩展生命周期、权限反例
                Cline VS Code、CLI、SDK、Agent Core 源码可读 逐行动审批、Diff review、checkpoint
                OpenHands Web、CLI、Server 源码可读 Frontend/agent 分离、本机/容器/VM/远程执行放置
                mini-SWE-agent CLI、批处理 源码可读 单 Bash 工具、无持久 Shell、直接 trajectory
                Gemini CLI TUI、Headless 源码可读 工具调度、项目指令、压缩与安全配置验证样本
                Qwen Code TUI、Headless、Daemon/ACP 源码可读 Auto-memory、subagent/team、worktree、控制面验证样本
                Kilo Code IDE、CLI、Agent Manager 源码可读 OpenCode Family 分化、项目记忆、远端 workspace、后台进程
                Loopal TUI、Server、ACP、Hub cluster 源码可读（专有许可） Hub/Agent 拓扑、耐久 Transcript、任务/Actor/Job 边界
                Mistral Vibe CLI、Programmatic、ACP、App Server 源码可读 事件化 Session、权限工具、worktree ownership 与多交付面

                计数规则

                • 研究锚点是具体 commit 或 release；“截至某日的 main”不替代 commit hash。
                • 同一 Harness 的多个前端只算一个实现。
                • 20 个画像是研究入口数量，不等于 20 份独立机制证据。Fork、前后代和共享核心形成 Harness Family，继承机制不能重复计票；例如 Kilo Code 从 OpenCode 继承的机制只算一次，只有可定位的分化实现才增加独立证据。
                • 19 个画像能映射到 68 个上游中的当前 gitlink，但“有本地仓库”不表示画像研究 SHA 已被该浅克隆物化；MiniMax Code 只使用固定版本的官方黑盒证据，不为凑数虚构核心仓库。
                • browser-use 是跨域 Corpus Harness，只能检验通用 Action/Observation、Execution World、Trajectory 与终态边界，不能支撑代码理解、补丁、测试或 Git 事务结论。
                • Antigravity CLI 与使用同一 core engine 的 Antigravity GUI、Claude Code 的各客户端、MiniMax Code 的桌面/远端/IM 入口都分别只算一个 Harness。
                • 闭源/黑盒画像可以记录官方材料明确承诺的 documented 契约，但不能把发布说明升级成源码级事实，也不能用 unknown 补成 implemented。
                • 产品参考与相邻项目保留在生态调研，不混进 Corpus 或独立实现计数。

                双向导航

                每个 Harness 页链接其已研究 Primitive；每个 Primitive 页也必须回链到出现过的 Harness。跨多个 Primitive 的完整运行路径集中在情境索引。

                阅读单个画像时，建议依次看：自身领域对象 → 关键运行路径 → Primitive 反向索引 → 独有机制 → 证据空白。先理解项目自己的状态所有者，再把它映射到 Wiki 术语；不要反过来用统一术语覆盖项目差异。
