                OpenCode

                语料层级：Anchor Harness · 形态：TUI / Server / SDK / IDE
                研究锚点：dev@a0f8dccbfe139ffc7137d1eaf6fee6e4195af599 · 快照日期：2026-08-17
                本地物化：9b0dd36cda0b9accb429a7f9f9ad9b054a27d04a（2026-08-25）· 与研究锚点漂移，旧 Claim 保留原 SHA，迁移待逐 Claim 审计
                许可证：MIT · 谱系：OpenCode

                OpenCode 是 client/server 取向的 Coding Harness：TUI 也是 Server 的客户端，Session、Message/Part、Agent、工具和事件 API 由共享运行时拥有。它特别适合研究 child session、参数化权限和多前端控制。

                纳入理由与边界

                固定源码包含完整 Session loop、模型接入、文件/LSP/命令工具、权限解析、持久化和 Server API，不是只包装另一个 CLI 的界面。桌面、Web、TUI 与 IDE 共享内核，因此仍只计一个 Harness。

                自身领域模型

                flowchart LR
    Client["TUI / Web / SDK"] --> Server["OpenCode Server"]
    Server --> Session["Session"]
    Session --> Message["Message"]
    Message --> Part["Part"]
    Message --> Agent["primary / subagent / hidden agent"]
    Agent --> Loop["session prompt loop"]
    Loop --> Tool["Tools + Permission"]
    Tool --> Bus["Bus / SSE events"]
                • Session 是持久聚合和 API 寻址边界。
                • Message + Part 承载文本、推理、工具调用与结果等运行事实。
                • Agent 是附着于请求/消息的运行模式；primary、subagent 以及隐藏的 compaction/title/summary agent 共享这个配置模型。
                • 主循环中的 step 是驱动器局部计数，不是已证明的持久顶层实体。
                • Subagent 创建带 parentID 的 child session；会话血缘不自动说明文件系统隔离。

                已研究 Primitive

                Primitive 状态 OpenCode 的实现取向
                会话与运行拓扑 implemented Session 聚合 Message/Part；fork 和 child session 建立新 Session
                Agent 循环与工作模式 implemented primary/subagent 与隐藏维护 agent 共用配置模型
                模型接入与路由 implemented provider/model 能力解析并可按 agent 覆盖
                上下文压缩 implemented 隐藏 compaction/summary agent 处理维护任务
                上下文表示降级 implemented compaction 前后以 placeholder/part metadata 降低高成本内容表示
                指令发现与组装 implemented local/global AGENTS、CLAUDE fallback 与 custom instructions
                代码库智能 alternative LSP、文件搜索和逐步探索替代单一 Repo Map
                版本控制与工作区事务 alternative Session diff/undo 与 worktree adapter 可见；统一 checkpoint/join contract 未证实
                Action 授权 implemented 工具 + 参数 pattern 按 last-match 规则解析 allow/ask/deny
                工作拓扑 alternative Session Todo 是有序工作清单，但没有通用 dependency/claim graph
                Actor 委派 implemented subtask 创建带 parentID 的 child Session，并可用 task id 继续
                后台 Job 生命周期 implemented background facade 提供 start/list/wait/promote/cancel 与 Session 取消传播
                配置、资源发现与项目信任 implemented 全局/项目 config、agent、rules、MCP 的 precedence
                扩展与生命周期 implemented plugins、bus events 与 runtime hooks 分层
                控制平面与互操作协议 implemented Server API、异步 prompt、abort、SSE events
                在线事件流 implemented Server SSE 按 Session 发布 message、part、tool 与终态事件，供客户端增量投影
                重连投影 alternative SSE/Session state 可供客户端重建，但 cursor/window/completeness contract 未闭合

                Child Session 时序

                sequenceDiagram
    participant P as Parent Session
    participant L as Session Loop
    participant S as Subagent Tool
    participant C as Child Session
    participant M as Model

    P->>L: model requests subtask
    L->>S: task(agent, prompt)
    S->>C: create Session(parentID)
    C->>M: child context + tools
    loop child Steps
        M-->>C: tool calls / response
    end
    C-->>S: child result + session identity
    S-->>P: tool result for parent loop

                图表达会话血缘；工作区是否隔离需要另查工作区事务，不能从 child Session 推断。

                设计取向

                • Server 是核心形态：TUI 通过 API 消费相同 Session 与事件，不把文本终端当唯一控制面。
                • Message/Part 是耐久细粒度事实：运行结果和展示可以从聚合内的 part 投影。
                • Agent 是配置化模式：用户角色与 compaction/title 等内部维护 actor 使用共同抽象。
                • 细粒度 permission pattern：策略输入包含工具参数和专门 guard，不仅是工具开关。

                已知证据空白

                • SSE 的事件 cursor、重放窗口和多客户端同时写入语义仍为 unknown。
                • child Session 的 workspace isolation 不能由 parentID 证明。
                • 自动 build/test 触发策略不在本轮 runtime 固定证据范围内。
