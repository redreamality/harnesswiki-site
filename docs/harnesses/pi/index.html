                Pi

                语料层级：Anchor Harness · 形态：TUI / Print / JSON / RPC / SDK
                研究锚点：main@d3ab2af969d64997338253c9151190aa1bc33580 · 快照日期：2026-08-17
                本地物化：59a71b235dadb4ad0d67557a8abb0aaa093e68b4（2026-08-25）· 与研究锚点漂移，旧 Claim 保留原 SHA，迁移待逐 Claim 审计
                许可证：MIT · 谱系：Pi（Oh My Pi 等衍生实现需去重）

                Pi 是模块化但默认工具集刻意精简的 Coding Harness。它用 JSONL Session tree 保存分支历史，用 AgentSession 管理运行投影，并允许 extensions 深入模型、工具、压缩和 UI 生命周期；同时明确不内置权限系统，是共识检验的重要反例。

                纳入理由与边界

                Pi monorepo 把 unified model API、agent core、TUI primitives 与 coding-agent 分包，coding agent 又支持交互、print/JSON、RPC 和 SDK。它拥有完整 loop、Session、tools、compaction 与 extension lifecycle，不是需要用户自行补全循环的通用 SDK。

                Pi 的衍生项目不能因仓库不同重复计票；只有独立改写的契约才能作为差异证据。

                自身领域模型

                flowchart LR
    Runtime["AgentSessionRuntime"] --> Session["AgentSession"]
    Session --> Agent["agent core loop"]
    Session --> File[("Session JSONL")]
    File --> Entry["entry id / parentId"]
    Entry --> Leaf["active leaf"]
    Leaf --> Projection["context projection"]
    Projection --> Agent
    Resource["Resource loader"] --> Ext["extensions / skills / prompts"]
    Ext --> Session
                • Session JSONL 中的 entry 用 id/parentId 组成树，active leaf 决定当前分支。
                • Context projection 从 leaf 回溯 root，并处理 compaction checkpoint、branch summary 和消息类型。
                • AgentSession 拥有当前消息、模型、压缩与运行事件；更外层 runtime 在 new/resume/fork/import 时替换它并重建 cwd-bound 资源。
                • 同一文件内切换 branch 与 fork 成另一个 Session 是不同操作。

                已研究 Primitive

                Primitive 状态 Pi 的实现取向
                会话与运行拓扑 implemented 单 JSONL 文件保存树形 entry 与 active leaf
                模型接入与路由 implemented unified model API 与 coding-agent Session 解耦
                上下文压缩 implemented compaction entry 与 branch summary 是不同历史事件
                语义上下文快照 implemented compaction summary/branch summary 以有范围的历史 entry 保存，并参与 active path projection
                工具与能力运行时 implemented 默认 read/write/edit/bash 工具，扩展可注册更多能力
                Action 授权 absent core 明确不内置 permission system；extension hook 可作为外置替代
                执行隔离 absent / alternative 内置工具继承进程权限；容器、VM 或外部 policy sandbox 承担隔离
                Actor 委派 absent / alternative core 不内置 subagent；SDK/extension 可自行注册 spawn tool
                后台 Job 生命周期 absent / alternative core 不内置 background Bash registry；extension 或外部 tmux 可承担
                状态持久化与恢复 implemented JSONL 原历史、分支和 compaction projection 可重建
                配置、资源发现与项目信任 implemented user/project resources 由 loader 汇总，SDK 可显式构造
                扩展与生命周期 implemented extensions 可注册工具/命令/UI 并介入 compaction
                控制平面与互操作协议 alternative stdio RPC 或 embedded SDK，而非 HTTP server
                耐久 Transcript implemented JSONL tree 保留 entry、branch 因果与 compaction/summary 事件
                在线事件流 implemented RPC/SDK 以结构化事件发布当前 message/tool/session 变化；断线重放保持 unknown

                分支与压缩关系

                sequenceDiagram
    participant U as User / Host
    participant R as AgentSessionRuntime
    participant S as AgentSession
    participant J as Session JSONL
    participant M as Model

    U->>R: resume(file, leaf) / branch
    R->>J: load entries and active path
    J-->>R: messages + compaction + branch summaries
    R->>S: replace active AgentSession
    S->>M: projected Context
    M-->>S: response / tool calls
    S->>J: append new entries with parentId

                设计取向

                • 分支是耐久历史结构：不是把消息数组复制成无法追踪的第二份文本。
                • 原历史与模型投影分离：compaction entry 改变继续点，原 JSONL 仍可审计。
                • 嵌入优先：RPC/SDK 提供结构化控制，不要求部署独立 Server。
                • 外部安全边界：默认工具继承宿主权限，强隔离由部署者提供；这不是未实现证据，而是明确设计选择。

                已知证据空白

                • 内置工作树 checkpoint/rollback 与自动 lint/test policy 未形成直接证据。
                • RPC 进程断线后的重连、事件 cursor 和多 client ownership 由宿主组合，不能从 Session JSONL 自动推断。
                • 扩展 hook 的完整排序、热重载事务和失败回滚仍需更细行为测试。
