                Cline

                语料层级：Anchor Harness · 形态：VS Code / CLI / SDK / Agent Core
                研究锚点：main@8bbdde2a5c1f972864fe1b954f639c21fac61a40 · 快照日期：2026-08-17
                本地物化：8a038022a439f401d78764a059e1561578848e81（2026-08-25）· 与研究锚点漂移，旧 Claim 保留原 SHA，迁移待逐 Claim 审计
                许可证：Apache-2.0 · 谱系：Cline

                Cline 是 IDE 形态但拥有完整 Agent Core 的 Coding Harness。当前源码的核心实现位于 sdk/packages/{agents,core,shared}；它将文件工具、patch、权限 callback、diff preview、Session artifacts 与 Git checkpoint 组合成可嵌入 runtime。

                纳入理由与边界

                Cline 不只是 VS Code UI：SDK runtime 自己拥有模型循环、工具 dispatch、Session 持久化、permission policy 与 checkpoint restore。IDE diagnostics 和 diff coordinator 是其交互面的一部分，但不能据此推断所有 SDK 宿主都启用同样策略。

                自身领域模型

                flowchart LR
    Host["VS Code / CLI / SDK host"] --> Runtime["Agent runtime"]
    Runtime --> Session["metadata + manifest/messages"]
    Runtime --> Policy["tool policy + approval callback"]
    Policy --> Tools["editor / apply_patch / bash / search"]
    Tools --> Preview["IDE diff coordinator"]
    Tools --> Workspace["workspace"]
    Runtime --> CP["Git checkpoint hooks"]
    CP --> Ref[("private snapshot refs")]
                • 未配置 tool policy 时，工具默认 enabled 且 auto-approved；显式 autoApprove:false 才调用 approval callback，无 callback 时拒绝。
                • checkpoint-hooks 在新用户 run 开始前创建 stash-shaped snapshot，而不是每个 tool 后创建 checkpoint。
                • Session metadata/artifacts、Agent message snapshot 和 Git workspace snapshot 是相关但独立的持久域。

                已研究 Primitive

                Primitive 状态 Cline 的实现取向
                代码库智能 alternative rg --json 搜索 + 短 TTL 文件索引回退；LSP 自动使用为 unknown
                变更生成与应用 implemented 唯一 old_text editor 与 context-based apply-patch 两条路径
                执行放置 alternative Bash 继承 SDK host 的 cwd/environment，没有独立 Execution World provisioning
                进程连续性 alternative 每次 Bash tool 新建 child process，支持 timeout/abort/tree cleanup，但不保持 shell state
                验证与反馈 unknown / alternative tool errors 回到 loop；自动 build/test 与 diagnostics 注入未确认
                版本控制与工作区事务 implemented run 前 private Git snapshot，restore 前再建恢复事务
                Action 授权 implemented tool policy 分开 enabled/autoApprove；无 approval callback 时 fail closed
                审批者身份 alternative runtime 把响应者认证与 principal provenance 委托给 SDK host callback
                状态持久化与恢复 implemented SQLite metadata + artifacts；messages 与 workspace 可分别恢复

    alt explicit approval required
        P-->>U: callback(action / diff)
        U-->>P: allow / deny

    opt file edit preview
        R->>D: show computed changes
    end
    R->>T: execute accepted call
    T-->>R: tool result / error
    R->>R: persist messages and manifest

                设计取向

                • SDK Core 是事实边界：UI 行为不能替代 runtime defaults 的源码证据。
                • 编辑前计算变更：editor 强制唯一匹配，patch path 在写盘前计算 change set。
                • 恢复域显式分离：用户可恢复工作树或裁剪消息，破坏性恢复前另建事务。
                • 预览与强制隔离分开：diff preview 提高可见性；Plan guard 的命令黑名单不宣称完备 sandbox。
