                Claude Code

                Corpus Harness 索引 · 层级：闭源 / 黑盒 Harness 样本 · 快照：2026-08-19
                研究锚点：main@354757e5b2d9aa1ebb62e5d05ecd384f0e11c0f7 · 发布记录版本：2.1.234
                许可证 / 分发：© Anthropic PBC，保留所有权利，使用受 Commercial Terms 约束

                Claude Code 是 Anthropic 的 agentic coding 产品，可从终端、IDE 和 GitHub 工作流使用。公开仓库在固定提交中提供产品 README、CHANGELOG、设置示例和官方插件，但没有把这些材料当作核心运行时源码发布；因此本页可以核验公开行为与配置契约，不能声称核验了内部类、调度器或存储实现。产品定位

                定位、计数与证据边界

                • 终端、IDE、GitHub 入口和 Remote Control 是同一 Claude Code 产品的交互面，本页只计 一个 Harness；没有把每个客户端重复计票。
                • Subagent、agent team teammate、background task 和另一条可通信 Session 是同一 Harness 内的 actor 或工作单元，不是新的 Harness。
                • 仓库内插件是扩展样本，不是核心 runtime 的替代源码，也不独立计数。
                • 固定提交的发布说明是 documented 事实；没有行为实测，因此本页没有 observed Claim。

                可观察领域模型

                下图只整理官方材料暴露的稳定对象，不主张这些名称对应闭源内核中的类。

                Session 是可恢复和可由远端客户端重新附着的对话身份；Turn 是一次仍可能包含多次工具调用、后台通知和权限变化的用户推进；AgentActor 表达 fork、teammate 或后台执行者。PermissionRequest 只决定 Action 是否获准，ExecutionWorld 才描述动作实际在哪个本机、云端、自托管机器或 worktree 中发生。

                已研究 Primitive

                状态列描述 Claude Code 是否处理该 Primitive；事实类型列描述本轮能看到的证据强度。闭源核心的公开发布说明统一记为 documented，不会写成源码级 implemented 证据。

                Primitive 状态 事实类型 Claude Code 的可核验取向
                会话与运行拓扑 implemented documented Session 可 resume；subagent 可 fork 父对话；命名 Session 可跨 Session 通信
                Agent 循环与工作模式 implemented documented Turn 内执行工具，后台 actor 可完成后唤醒后续推进；内部调度算法仍不可见
                上下文压缩 implemented documented auto-compaction、显式 /compact 与 Remote Control 的压缩边界可见
                指令发现与组装 implemented documented CLAUDE.md 进入 system prompt；项目指令与安全设置不是同一来源
                工具与能力运行时 implemented documented 内置工具、MCP、hook、skill 和 plugin 共同扩展能力集合
                Action 授权 implemented documented allow / ask / deny、管理策略和自动模式分类器决定 Action 是否可进入执行
                审批协调 implemented documented 终端、IDE 与 Remote Control 可呈现并回答权限请求；回答按 Session 作用域保存
                审批者身份 unknown documented 已有账号切换和远端控制约束，但公开材料不足以证明 approver credential、租约和竞争响应契约
                执行隔离 implemented documented Bash sandbox 约束命令效果；公开材料未证明它覆盖非 Bash 工具
                执行放置 implemented documented 本机、云端和 self-hosted runner 可承载 Session；连接恢复不等于原世界仍存活
                工作区事务 implemented documented worktree 把 actor 绑定到独立 checkout；它不等于完整 Execution World snapshot
                工作拓扑 alternative documented agent team 与跨 Session 协作可见，但公开材料不足以证明 claim、dependency 与 join contract
                Actor 委派 implemented documented fork subagent、teammate 与命名 Session 消息暴露不同 Actor lineage 和 context policy
                后台 Job 生命周期 alternative documented 后台 actor 可完成后唤醒推进；稳定 Job id、output cursor 与 quiescence contract 未公开
                控制平面 implemented documented Remote Control 将 web / mobile 客户端附着到 terminal、Desktop 或 IDE 承载的 Session
                持久 Transcript implemented documented Session restore 与 resume 依赖耐久历史；格式、事务和迁移保证未知
                重放投影 unknown documented Remote Control 可恢复历史和压缩边界，但公开材料没有 cursor、窗口或 snapshot + tail 契约
                Artifact 交付 implemented documented Remote Control 中的文件可上传给用户并从 web / mobile 打开；完整传输协议未知

                关键可核验行为

                Actor 分支不等于新 Session 或新工作区

                2.1.232 明确记录：subagent_type: "fork" 继承完整对话和 prompt cache，交互会话中的非 teammate actor 默认在后台运行；命名 Session 则通过 SendMessage 彼此寻址。这证明 actor context 分支、后台生命周期和跨 Session 通信是三个对象。fork 与跨 Session 消息

                授权策略与执行隔离是两层契约

                固定发布记录确认 Claude Code 提供 Linux/macOS Bash sandbox；仓库内的设置示例又把 Bash ask / deny rule 与 sandbox 分开，autoAllowBashIfSandboxed 说明“沙箱内可自动批准”是一条策略，而不是 sandbox 本身。不过仓库明确警告这些示例由社区维护、可能不受支持或不正确，因此其中“只覆盖 Bash、不覆盖其他工具”的精确矩阵只作为待官方文档交叉核验的 documented 边界，不冒充核心源码事实。Bash sandbox 发布记录 · 示例警告与设置矩阵 · 严格权限示例 · Bash sandbox 示例

                Remote Control 是控制附着，不是另一个 Agent loop

                发布说明记录 phone 与 claude.ai/code 会同步宿主 Session 的 permission mode、model 和 effort；重连、接管、离线状态与 resume 也有独立行为。这足以证明多客户端控制边界，但没有公开 event cursor、全序、backpressure 或两个客户端同时提交审批时的仲裁协议。状态同步 · 恢复、接管与离线状态

                Worktree 隔离覆盖 actor，不等于完整世界快照

                固定版本发布说明明确修复了 worktree-isolated Session 及其 subagent 对主 checkout 执行破坏性 Git 命令的问题，并说明隔离覆盖文件编辑和 Bash。它证明 actor 到 workspace 的绑定存在，但没有证明外部服务、进程、网络或凭据能随 Session 一起回滚。worktree 隔离边界

                版本、分发与开放性

                • 固定提交的 CHANGELOG 顶部版本是 2.1.234；本页不把网页上的滚动最新版套回该提交。版本锚点
                • README 推荐原生安装脚本、Homebrew 与 WinGet，npm 安装已标为 deprecated。安装分发
                • 仓库 LICENSE 不是 OSI 开源许可，而是“保留所有权利 + Commercial Terms”。公开插件中的 Python、Shell 或 Markdown 不能替代闭源核心的实现证据。

                已知证据空白

                • Session transcript 的 schema、原子写入、分支 lineage 和跨版本迁移保证均为 unknown。
                • Remote Control 的 command id、event cursor、重放窗口、多 writer 序列化与审批竞争结果均为 unknown。
                • Bash sandbox 的平台级 enforcement 实现、network proxy 失败语义和非 Bash 工具的最大效果边界没有核心源码证据。
                • auto-compaction 的选择算法、provenance 保留和压缩后工具结果留存策略不能从发布说明反推。
                • self-hosted runner 能把 Session 放到机器或容器，但 world identity、租约、销毁和重新附着契约未公开。
                • 本页没有运行闭源二进制，故没有把任何发布说明升级为 observed。
