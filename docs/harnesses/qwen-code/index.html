Qwen Code

Corpus Harness 索引 · 层级：Validation Harness · 快照：2026-08-17
研究锚点：main@f2a6e6c727c4964ccc7d7e516740678aaf80763b · 包版本：0.21.11 · 许可证：Apache-2.0
行为锚点：b4f5079dc0cc89ce1448785898ab72b358399c95 · 实验日期：2026-08-19
本地物化：b4f5079dc0cc89ce1448785898ab72b358399c95（2026-08-25）· 仅与行为锚点对齐；静态研究锚点仍漂移，见版本审计

Qwen Code 是从 Gemini CLI 谱系独立演化出的多形态 Coding Harness。TUI/headless 直接构造 core，qwen --acp 经 ACP bridge 承载同一 core，qwen serve 再增加 HTTP/SSE、多客户端、workspace-scoped runtime 和恢复语义。

谱系与独立计数

Section titled “谱系与独立计数”

官方 README说明项目起点是 Gemini CLI v0.8.2，Qwen v0.1 后停止同步并独立发展。共同继承的 loop、基础工具或配置机制只算一个 Harness Family 的证据；daemon、多客户端 permission、Goal protocol、原生 LSP、microcompaction 等后续分化可以作为独立差异证据。

Direct Session 用 JSONL 和 parentUuid 重建 active chain；branch 复制选中路径并用 forkedFrom 保留来源。Daemon SessionEntry 是绑定 ACP sessionId 的 live control object，另有 FIFO、EventBus、permission、attached clients、heartbeat 与 terminal tombstone。Durable transcript、live session 与 replay projection 是三个对象。

架构取向

Section titled “架构取向”
flowchart LR
    TUI["TUI / headless"] --> Core["packages/core"]
    Web["Web / IDE / SDK / Channels"] --> Serve["qwen serve<br>HTTP + SSE"]
    Serve --> Bridge["ACP bridge"]
    Bridge --> ACP["qwen --acp child"]
    ACP --> Core
    Core <--> World["Execution World"]

HTTP prompt 是异步控制命令：返回 202 与 prompt/event identity，真正的 Agent Turn 终态通过 SSE turn_complete/turn_error 到达。因此 Control Plane command completion 与 Turn completion 必须分别建模。

来源：Architecture

行为实测

Section titled “行为实测”

控制面行为实测在固定行为锚点直接执行 daemon 的 MultiClientPermissionMediator 与 EventBus。两个同时 pending 的 2-of-3 approval 按 requestId 分别闭合；事件订阅断开没有取消 pending；离线期间产生的 partial/terminal 可按同一 epoch 与 cursor 回放；Session close 将 pending 唯一闭合为 cancelled/session_closed，晚到 vote 只能读到既有终态。以上为模块级 observed，不覆盖 HTTP/SSE adapter、认证租约、daemon crash recovery 或模型/工具执行。

恢复边界行为实测在同一固定锚点直接执行 worktree restore 与 Session history projection。目标 worktree 已丢失时，helper 清理 stale sidecar 并返回空 context，说明 Session 可继续不等于工作区被重建；已有 compression record 时，下一次模型请求只收到 snapshot、ack 与压缩后 tail，压缩前原文仍在 durable input 中但不再进入 API history。以上为模块级 observed，不覆盖完整 CLI resume、摘要内容正确性或旧进程恢复。

四种容易被叫成“压缩”的机制

Section titled “四种容易被叫成“压缩”的机制”
机制 处理对象 产物 是否减少模型 token
Microcompaction 旧 tool response / media 显式 placeholder + cache invalidation 是
Semantic compression 完整 model-visible history <state_snapshot> 是
Attachment restoration 摘要前后的 media/files/plan/subagent state summary + ack + restored attachments 维持可用状态
Replay compaction Daemon SSE/live journal turn-boundary folded event window 否

Replay compaction 只优化客户端重连所见事件，不能归入 Context Compaction。Microcompaction 丢弃字节但不声称理解语义；semantic snapshot 才由模型生成状态摘要。

来源：Microcompaction · Semantic compression · Replay compaction

三个有解释力的细节

Section titled “三个有解释力的细节”

Approval routing 不是 Authentication

Section titled “Approval routing 不是 Authentication”

Daemon mediator 支持 first-responder、designated、N-of-M consensus 与 local-only，并在 issue 时冻结 voter snapshot。v1 的 X-Qwen-Client-Id 却是客户端自报、没有 possession proof；看到 originator id 的客户端可冒用。因此 approval ownership policy 不能当成强身份隔离。

来源：Permission mediation

Goal Verifier 验证证据声明，不替 Agent 跑测试

Section titled “Goal Verifier 验证证据声明，不替 Agent 跑测试”

Goal 使用 id、revision、phase、turn permit 与 evidence checkpoint；complete/blocked proposal 必须引用 evidence。Verifier 区分 user_input、delivered_output、external_fact 的证明能力。它检查 terminal claim 是否有充分 provenance，普通 Turn 的测试仍由 Shell/LSP/tool Observation 完成。

来源：Goal protocol · Goal verifier

Actor context 与 Worktree 隔离正交

Section titled “Actor context 与 Worktree 隔离正交”

Named subagent 用新 context，fork 继承父 conversation，team actor 可互发消息；agent tool 另可为非 fork actor 分配 isolated worktree。fork_turns 选择继承多少上下文，不是复制多少文件状态。

来源：Subagents · Agent tool · Worktree

证据空白

Section titled “证据空白”
  • Daemon self-reported client id 不提供强身份；认证 reverse proxy 等部署边界不由 core 自动保证。
  • 普通编辑没有已确认的统一 auto-lint/test controller，不能从 Goal Verifier 反推。
  • Rewind 可能先移动 conversation 再报告部分文件失败，且不撤销 shell/Git/manual change，不是原子全状态 rollback。
  • Portable Agent Plugins v1 只激活部分资源；“安装 extension”不代表 commands/agents/hooks 全部生效。
