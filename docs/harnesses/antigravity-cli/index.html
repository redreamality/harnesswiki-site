                Antigravity CLI

                Corpus Harness 索引 · 层级：闭源 / 黑盒 Harness 样本 · 快照：2026-08-19
                研究锚点：main@76ff39c65b5d52482172b6408c27ded9b17c303d · 发布记录版本：1.1.14
                许可证 / 分发：官方安装脚本与 release binary；固定仓库未提供 OSS 许可证，使用受产品 Terms 约束

                Antigravity CLI 是 Google Antigravity 的终端界面，面向键盘工作流与 SSH 环境。官方 README 明确它与 Antigravity 2.0 GUI 使用同一 core agent engine，并把 multi-step reasoning、multi-file editing、tool calling 和 persistent history 带到终端。产品与共享内核声明

                公开仓库在固定提交中只有 README、CHANGELOG、示例脚本和演示资源，没有可供本轮核验的核心 runtime 源码。以下机制均来自项目方发布材料，事实类型为 documented，不是源码级 implemented 证据。

                定位、计数与证据边界

                • TUI、headless print mode 和 SSH 使用方式只计 一个 Antigravity CLI Harness。
                • Antigravity CLI 与 Antigravity 2.0 共享 engine；两种界面不能作为两个独立内核样本重复计票。
                • Session export 到 GUI 是跨界面继续工作的产品契约，不自动证明数据库文件、live process 或控制事件原样迁移。
                • Subagent、custom agent 和 background task 是同一 Harness 内的 actor / job，不单独计数。
                • 本页没有运行 release binary，因此没有 observed Claim。

                Conversation 是可恢复、可导出并持久化的用户会话；Step 是消息、工具调用或后台进度等可呈现单元；AgentActor 表达主 Agent、subagent 和后台 worker。PermissionRequest 决定动作是否获准，Sandbox 约束已获准命令的最大效果，二者不能合并成一个“安全模式”。

                已研究 Primitive

                Primitive 状态 事实类型 Antigravity CLI 的可核验取向
                会话与运行拓扑 implemented documented SQLite Conversation 可 resume；主对话与 subagent Conversation 分开呈现
                Agent 循环与工作模式 implemented documented 共享 engine 执行多步 reasoning、tool calling 与 background work；内部 scheduler 不可见
                上下文压缩 implemented documented 长 Conversation 有 trajectory truncation 与受保护 checkpoint；具体选择算法未知
                指令发现与组装 implemented documented rules、skills、agents、hooks 和 plugin customization 被发现，并有配置优先级
                工具与能力运行时 implemented documented native tools、MCP、plugin 与 subagent tool 进入同一可见工具活动流
                Action 授权 implemented documented project、shared user 与 CLI settings 合并出 permission rule；headless 无人审批时 soft-deny
                审批协调 implemented documented TUI 展示完整命令并接受 approve / deny；嵌套 subagent 请求中继到根 Conversation
                审批者身份 unknown documented 登录身份存在，但公开材料没有 approver capability、租约或多客户端竞争契约
                执行隔离 implemented documented --sandbox、network proxy 与 proceed-in-sandbox 形成 enforcement 与 policy 的组合
                执行放置 alternative documented CLI 在本机或 SSH host 上运行；没有公开 managed world provisioning / lease 契约
                Actor 委派 implemented documented custom agent、nested subagent Conversation 与根 Conversation activity 分开呈现
                后台 Job 生命周期 alternative documented background task 有独立 activity 入口；稳定 Job id、output cursor 与 restart recovery 未公开
                控制平面 alternative documented TUI、one-shot structured print output 和 Session export 覆盖部分控制职责；未公开常驻双向协议
                持久 Transcript implemented documented SQLite Conversation 保存可恢复历史，schema 与 transaction boundary 未公开
                Live 事件流 implemented documented stream-json 发出 typed init、step update 和 terminal result；它不是历史 replay
                Artifact 交付 implemented documented Artifact viewer 支持审查、评论和外部编辑；review state 与工具批准状态分开

                关键可核验行为

                GUI 与 CLI 是共享内核的两个界面

                README 同时声明 shared core agent engine、双向同步 settings / permissions 和 Session export。它支持跨界面继续工作的产品边界，也意味着 CLI 与 GUI 的相同机制只有一份 family 证据；本页不会把 UI 差异误算成独立 Agent loop。共享引擎与集成

                Durable Conversation、active actor 与 live event stream 是不同对象

                1.0.4 把 SQLite 定为 Conversation 格式；/resume 会扫描 .db / .db-wal，同时跳过 subagent Conversation。structured print stream 则为 tool call 和 delegated subagent 输出 correlation 数据。这些记录分别证明耐久会话、actor 子拓扑与机器可读事件流，不能合并成一个 transcript 对象。resume 与 subagent 边界 · SQLite 与扫描入口 · structured output

                无人值守模式不能假装有人批准

                固定版本说明 headless -p 会应用持久化 permission、file access、sandbox、auto-execution 和 artifact review policy；工具需要人工 confirmation 时会 soft-deny 并返回所需 allow rule，而不是静默批准。这是 Action authorization 在不同交互面上的明确降级契约。headless policy

                Sandbox 通过授权模式接入，但不是授权本身

                proceed-in-sandbox 自动批准 sandbox 内命令，越过 sandbox 才请求人工批准；后续发布又修复 --sandbox 在 headless 模式的传播。这个组合直接说明 policy decision 和 isolation enforcement 是两个阶段。sandbox permission mode · headless sandbox

                版本、分发与开放性

                • 固定提交的 CHANGELOG 顶部版本是 1.1.14，本页结论不跨越该版本。版本锚点
                • README 提供 macOS、Linux 与 Windows 安装脚本，并以 agy 启动；仓库发布的是产品材料和二进制入口。安装方式
                • 固定仓库树没有 OSS license 文件；README 要求遵守 Google Terms，并警告 autonomous execution、data exfiltration、prompt injection 与 supply-chain risk。缺少 OSS license 不能被 README 可读性替代。Terms 与风险声明

                已知证据空白

                • shared core agent engine 的 loop、context builder、tool dispatcher 和 persistence schema 没有源码级证据。
                • SQLite 表结构、事务边界、branch lineage、崩溃恢复与版本迁移保证均为 unknown。
                • structured stream-json 是输出投影；没有公开 command channel、cancel target、event cursor 或重连 replay 契约，不能升级为完整双向控制协议。
                • permission rule 已公开多层合并与 UI 行为，但 approver identity、多客户端争用和审批审计记录为 unknown。
                • sandbox 的平台 enforcement、filesystem / network / credential 覆盖范围和失败关闭语义没有核心实现证据。
                • README 中的 SSH workflow 只说明 CLI 可在远端 shell 使用，不证明 Harness 会 provision 或租赁远端 Execution World。
