                  Zed Agent

                  Corpus Harness 索引 · 形态：IDE 内嵌 Agent Panel / Agent Thread
                  研究锚点：zed-industries/zed main@3624a5bfda8a4610bf9926499517a776c7028321 · 快照日期：2026-08-19
                  Agent crate 版本：0.1.0 · 许可证：GPL-3.0-or-later

                  Zed Agent 是编辑器进程内的 Coding Harness，不是只负责显示或启动外部 CLI 的 UI 壳。固定提交中的 agent crate 自己维护 Thread、模型请求、工具执行、审批、上下文压缩、sandbox grants 和 subagent；本页只研究这套 Agent runtime，不把 Zed 其他协作、编辑器或云服务模块自动归为 Harness 机制。

                  定位与边界

                  Zed 的核心聚合是 Thread。一个 Thread 有稳定 Session id、消息、当前模型、项目上下文、工具表和可跨多个“模型请求 → 工具结果”循环存活的 RunningTurn；ThreadStore 则把可恢复的 Thread 数据交给数据库。两者不是同一个对象：Thread 是当前活体运行投影，ThreadStore 是已保存数据和列表索引。

                  Tool permission 与 execution sandbox 也必须分开。ToolPermissionDecision 先把调用归约为 Allow、Deny 或 Confirm；sandbox 再约束 terminal 的网络、写路径或 unsandboxed escape。用户批准一条命令不等于关闭 sandbox，批准 sandbox escape 也不等于所有工具获得授权。

                  spawn_agent 是 Thread 的工具动作。它创建或恢复另一个 subagent Session，发送任务并等待结果，同时把 child Session id 和消息范围附在 tool-call metadata 中。Child identity、父 Turn 的 tool call 和 child 输出是三个边界，不能压成一个匿名函数调用。

                  来源：Thread 状态边界 · ThreadStore 的 load/save · subagent create/resume 与执行

                  已研究 Primitive

                  Primitive 状态 Zed Agent 中的实现
                  会话与运行拓扑 implemented ACP Session id 标识 Thread，ThreadStore load/save 持久投影，subagent 另有独立 Session id
                  Agent 循环与工作模式 implemented RunningTurn 跨模型请求与工具轮次存活，支持 queued steering boundary、cancel、retry 与显式终态事件
                  工具与能力运行时 implemented 每轮刷新可用工具；调用经 restricted-workspace gate、scoped tool-call event stream、执行和结果回注
                  上下文压缩 implemented 自动阈值压缩与手动压缩都生成 summary message，并区分取消、失败、retry 和插入位置
                  Action 授权 implemented hardcoded deny、规则优先级、shell 子命令解析和 Allow/Deny/Confirm 归约
                  审批协调 alternative tool-call id 绑定 oneshot 响应；pending 时设置变更可自动 resolve，但未证实跨客户端 approver ownership
                  执行隔离 implemented local project 可启用 OS sandbox；network、写路径与 unsandboxed escape 分层授权并合并 thread/persistent grants
                  Actor 委派 implemented spawn_agent 创建或恢复 child Session，发送任务、等待结果并返回 Session id 与消息范围
                  状态持久化与恢复 alternative ThreadStore 可恢复保存的 Thread，sandbox grants 有数据库转换形式；运行中 Turn、工具进程和 child quiescence 恢复未闭合
                  在线事件流 implemented send/run_turn 返回 ThreadEvent receiver，流式发送文本、tool call、审批、retry、compaction 和 stop/error

                  关键机制

                  Thread 的 Turn 不等于一次模型请求

                  send() 先把用户消息加入 Thread，再由 run_turn() 创建事件流、cancellation channel 和 RunningTurn。内部循环每轮重读模型、刷新工具和构造请求；模型流可同时产生文本、工具输入和工具任务，工具结果处理完成后才决定结束 Turn、执行 retry，或以 ToolResults intent 发起下一次模型请求。

                  因此 Zed Thread 的一次用户推进可以包含多次 completion 和并行 tool future。queued steering 只在下一个 message boundary 结束当前 Turn；它不是立即把正在执行的工具伪装成成功。

                  来源：发送与 RunningTurn 创建 · Turn 事件与取消终态 · 模型流和并行工具 future · 结果回注与下一轮条件

                  压缩会改写模型可见历史，不会回滚工作区

                  手动压缩先 flush pending message 并取消在途 Turn，再基于明确的 request end 构造 summary；自动压缩在每轮请求前按 context threshold 判断。成功结果作为 Compaction message 插入或追加，后续 completion 从压缩后的投影继续。该机制只改变 Thread 的模型可见 history；源码没有把 project filesystem、tool process 或 subagent 状态纳入同一 checkpoint。

                  来源：手动压缩边界 · 自动压缩与 summary 写入

                  授权归约、审批等待与 sandbox escalation 是三步

                  Tool permission 先应用不可覆盖的 hardcoded security rule，再按 deny、confirm、allow、tool default 和 global default 的顺序归约。Terminal 的 allow rule 还要能安全解析全部子命令；解析失败时不会把 allow pattern 当作放行依据。若结果为 Confirm，ThreadEvent 携带 tool-call id、选项和 oneshot response；等待期间配置变更可重新归约并关闭 prompt。

                  Terminal sandbox 另把 network、全局写、具体 canonical path 和 unsandboxed 组成 SandboxRequest。用户可以只批准一次或批准本 Thread；persistent setting 和 thread grant 分开合并。批准 unsandboxed 或 sandbox-creation fallback 后，该 Thread 的 terminal 会退化为 ambient access，因此 UI 显示的“已审批”不能被解释成“仍在 sandbox 内”。

                  来源：权限优先级与 shell 解析 · 审批与设置变更竞态 · SandboxRequest 与 thread grants · unsandboxed/fallback 语义

                  Subagent 是可寻址 Session，不是无状态工具 helper

                  spawn_agent 可按输入新建 child，也可用既有 Session id 恢复。它在发送任务前发布 child identity，并在结束时返回 child 的消息起止索引；失败输出也保留可用的 Session 信息。父 Thread 另保存运行中 child 的弱引用用于 cancellation propagation。

                  这证明 child 有独立 Session identity 和可检查输出，但不能据“父任务取消”推断 child 所有工具、外部进程或工作区已静默。源码中的 cancellation reference 是传播入口，不是跨资源 quiescence 证明。

                  来源：subagent 工具生命周期 · 父 Thread 的 child reference

                  ThreadStore 保存投影，不保存活体 Turn

                  ThreadStore 通过数据库 load/save DbThread，写入后刷新 metadata 列表。固定路径没有把 RunningTurn、event receiver、tool future 或 cancellation channel 写入数据库；恢复 Thread 不能等同于恢复在途执行。ThreadSandboxGrants 同时存在“只活在 Thread”注释与 to_db/from_db 转换 helper，但本轮没有闭合 helper 到 ThreadStore 的实际 wiring，因此只记录为待核验。

                  来源：ThreadStore load/save · 活体 RunningTurn 与 grant 注释 · grant 数据库转换 helper

                  证据空白

                  • ThreadStore 可保存消息投影，但数据库的事务、schema migration、torn write 处理和 crash 中在途 Turn 的恢复语义未在本页闭合。
                  • tool-call approval 有稳定 id 和 pending response；多客户端 approver identity、lease、断线重放、晚到响应和 exactly-once resolution 保持 unknown。
                  • sandbox 仅在 feature flag、local project 和平台 integration 可用时适用；各平台 wrapper 的完整 fail-closed 行为和绕过面没有在本页逐项审计。
                  • Thread 的 child cancellation reference 不能证明外部进程、MCP server、网络请求和 child workspace 已全部 quiescent。
                  • 自动压缩只证明 summary projection；摘要忠实度、压缩前 tool result 的可追溯性和 crash 时的原子写入仍需行为验证。
                  • Zed 的编辑器 checkpoint、Git 操作和 action log 未在本轮形成统一 workspace transaction 证据，因此没有把“IDE 内运行”升级为版本控制事务实现。
                  • Agent crate 使用 GPL-3.0-or-later；仓库其他组件可能有不同许可，不能把该 crate 的结论外推为整个仓库的单一许可证。
