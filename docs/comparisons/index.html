                Situation 横向比较

                导航：首页 · 设计精髓总览 · 机制地图 · Harness 索引 · 研究方法

                Situation 页跟踪一次真实情境怎样穿过多个 Primitive。它们不做产品排行，而是显露状态边界、替代机制和缺席机制造成的行为差异。

                Situation 串联的 Primitive 刻意观察的差异
                首次进入陌生仓库并完成修复 代码库智能 → 变更生成与应用 → 验证与反馈 → 工作区事务 专用 Repo Map 与 Shell 自主探索
                长会话遇到上下文预算压力 会话拓扑 → 工具输出保留 / 语义快照 / 表示降级 → 上下文血缘 → 压缩 → 状态恢复 原文保留、显式降级、摘要有效性与来源范围
                高风险命令触发审批 工具运行时 → Action 授权 → 审批协调 / 审批者身份 → 执行隔离 → 执行放置 规则决策、待决请求、回答权与实际 enforcement
                审批等待跨进程暂停并恢复 审批协调 → 状态恢复 → 控制平面 / 耐久 Transcript → 工具运行时 在线等待、耐久暂停、Session close 取消与无 responder 拒绝
                并行委派后合并工作区变更 工作拓扑 → Actor 委派 → 后台 Job → 工作区事务 → 验证 → 产物交付 → Goal 证据 claim、child lineage、quiescence、交付与 join 责任
                Goal 完成前进行独立验证 验证与反馈 → Goal 证据 → 工作区事务 / 评测 Trajectory → 产物交付 自报完成、检查结果、独立复核与 revision-bound 终态
                外部客户端取消并恢复运行 控制平面 → 在线事件流 → 重连投影 → 耐久 Transcript → 会话拓扑 → 状态恢复 → 进程连续性 结构化取消、replay cursor、Session 恢复与进程终止是否一致

                写法约束

                • 情境必须包含可观察触发、状态变化和终态，不能只是“是否支持某功能”。
                • 每个分支都回链到相关 Primitive 与 Harness 画像。
                • 时序图描述领域事件，不把未验证的内部调用画成事实。
                • 未找到证据时写 unknown，只有一手材料明确时才写 absent。
