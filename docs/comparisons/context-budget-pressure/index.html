                Situation：长会话遇到上下文预算压力

                导航：Situation 索引 · 运行内核 · Harness 索引

                情境定义

                契约字段 内容
                触发 同一个 Session 的下一次模型请求即将超过可用上下文预算，或 Provider 已返回溢出错误。
                初始状态 Session 已积累多轮工具结果、文件片段和用户 steering，Execution World 可能已有未提交效果。
                关键事件 Harness 选择压缩边界与保留集，生成带来源边界的压缩产物，并据此重建下一次 Context Snapshot。
                可观察终态 运行能够继续；模型知道任务目标、已完成工作、当前工作区状态与未决风险，且未保留的细节没有被伪装成仍然存在。

                该情境连接会话与运行拓扑、上下文压缩、状态持久化与恢复和扩展生命周期。

                压缩不是删除旧消息

                一个可解释的压缩周期至少需要回答：

                • 触发：由 token 阈值、模型溢出错误、用户命令还是分支切换触发？
                • 输入边界：压缩整个 Session、当前分支，还是某个 Turn 之前的历史？
                • 保留集：项目指令、最近消息、工具结果、文件状态和任务计划哪些不可丢？
                • 产物：生成摘要消息、branch summary、结构化 state，还是直接截断？
                • 耐久性：压缩结果能否在进程重启后复用，原历史是否仍可审计？

                领域时序

                sequenceDiagram
    participant L as Agent Loop
    participant B as Budget Manager
    participant S as Session Store
    participant C as Compactor
    participant M as 模型

    L->>B: 估算下一 Context Snapshot
    B-->>L: 超过预算阈值
    L->>S: 读取当前分支历史与 durable state
    L->>C: 请求压缩（保留规则 + 目标预算）
    C->>M: 生成或校验摘要
    M-->>C: Compression artifact
    C->>S: 保存摘要、边界与原历史引用
    C-->>L: 新的上下文起点
    L->>B: 重新估算
    B-->>L: 可继续
    L->>M: 指令 + 摘要 + 最近事件 + 当前观察

                某些 Harness 会把 Compactor 实现成隐藏 agent，某些直接调用当前模型或允许扩展拦截；图只表达职责，不声称它们必须是独立组件。

                实现分支

                Pi：线性压缩与分支摘要是不同事件

                • 状态：implemented
                • 研究锚点：见 Pi 画像

                Pi 的 Session 是带 id/parentId 的 JSONL 树。普通 compaction 为当前活动路径生成新的压缩入口；离开分支时还可以产生 branch summary，帮助另一条路径理解被舍弃分支发生过什么。两者都与树形 Session 相关，但触发和语义不同。

                Pi 扩展可以观察或介入 compaction 生命周期，因此压缩同时也是扩展边界，而不只是 token 工具函数。

                OpenCode：专门的隐藏 compaction/summary agent

                • 状态：implemented
                • 研究锚点：见 OpenCode 画像

                OpenCode 把 compaction、summary 与 title 等内部职责建模为隐藏 agent。它说明工作模式不只服务用户可选角色；Harness 也可用受限内部 actor 处理上下文维护，并将结果写回 Session 事件。

                DeepSeek Harness：Log bracket 与 model surface 分离

                • 状态：implemented
                • 研究锚点：见 DeepSeek Harness 画像

                DeepSeek Harness 把压缩做成可替换 capability seam。compaction/start|summary|end 是 log-only bracket，真正改变下一次模型可见历史的是另一条 surfaceOp: replace 事件；pressure、confirmed overflow 与手动 region 具有不同触发/继续语义。Append-only Session log 仍是耐久事实基础。

                这里的对照重点是“压缩上下文”与“删除会话事实”被明确分开。

                失败模式

                失败 后果 应观察的 Primitive
                摘要遗漏用户约束 后续行动违反原目标 指令组装、压缩保留集
                工具结果被压缩但工作区已变化 模型误判当前状态 压缩、Execution World、恢复
                原历史被覆盖 无法审计或重新压缩 Session persistence、trajectory
                分支摘要混入主路径事实 模型把未合并工作当成当前状态 Session topology、branch summary
                压缩后仍超预算 循环无法继续或反复压缩 budget manager、完成判定
