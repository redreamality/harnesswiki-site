                Situation：外部客户端取消并恢复运行

                导航：Situation 索引 · 组合与互操作 · 运行内核

                情境定义

                契约字段 内容
                触发 发起长 Turn 的 IDE 客户端断线，用户从另一个客户端重新连接并要求取消。
                初始状态 同一 Session 仍可寻址，Turn 可能继续运行，部分 Action 可能已经产生外部效果。
                关键事件 新客户端恢复 Session 投影，定位 active Turn，提交取消命令，并接收取消与已发生效果的终态事件。
                可观察终态 所有客户端对“哪个 Turn 被取消、哪些行动已发生、从哪里恢复”达成一致，用户可以从明确边界继续工作。

                这个情境连接控制平面、会话与运行拓扑、状态持久化与恢复和Trajectory/回放。

                领域时序

                sequenceDiagram
    actor U as 用户
    participant C1 as Client A
    participant CP as Control Plane
    participant H as Harness Core
    participant S as Session Store
    participant T as Tool Process
    participant C2 as Client B

    U->>C1: 开始任务
    C1->>CP: startTurn(sessionId, input)
    CP->>H: 创建 Turn
    H->>S: 持久化 turn/started
    H->>T: 执行长行动
    CP-->>C1: 流式事件
    C1-xCP: 客户端断线
    C2->>CP: subscribe(sessionId, cursor)
    CP->>S: 读取快照与 cursor 后事件
    CP-->>C2: 当前 Turn + 已发生事件
    U->>C2: 取消
    C2->>CP: cancel(turnId)
    CP->>H: 取消正确 Turn
    H-xT: interrupt
    H->>S: 持久化 action/terminal + turn/cancelled
    CP-->>C2: 一致终态
    C2->>CP: resume(sessionId, new input)
    CP->>H: 从 durable state 开启新 Turn

                取消不是“关掉前端”。如果工具已经修改文件，终态还必须记录部分效果；恢复也不是“重新发送聊天文本”，而是选择一个明确 Session、事件 cursor 与工作区状态继续。

                实现分支

                Codex CLI：Thread/Turn/Item 的结构化 App Server 边界

                • 状态：implemented
                • 研究锚点：见 Codex CLI 画像

                Codex 的 protocol/app-server 使用 Thread、Turn、Item 与结构化事件供桌面端或 IDE 驱动内核。取消与审批可以指向明确运行对象，客户端无需解析 TUI 文本；持久化和恢复的具体覆盖范围见对应 Primitive 页。

                OpenCode：Server API 与 SSE 事件

                • 状态：implemented
                • 研究锚点：见 OpenCode 画像

                OpenCode 的 TUI 本身是 Server 客户端；Headless Server 暴露 Session API、异步 prompt、abort 和 SSE 事件。多种前端共享会话寻址，但断线重放窗口、事件顺序和并发写入所有权仍是需要行为测试的边界。

                Pi：RPC/SDK 嵌入的替代拓扑

                • 状态：alternative
                • 研究锚点：见 Pi 画像

                Pi 可以通过 stdin/stdout RPC 或 SDK 嵌入宿主，以命令和事件驱动同一 agent session。它不需要 HTTP/SSE server；宿主负责进程生命周期与断线策略，Session JSONL 则提供可恢复的树形历史。

                Qwen Code：Daemon/ACP 验证样本

                • 状态：implemented + observed
                • 研究锚点：见 Qwen Code 画像与控制面行为实测

                Qwen Code 的 daemon/serve 与 ACP 入口把 agent session 暴露给外部客户端。固定行为锚点的模块级实测让 EventBus 订阅者在 cursor 2 断开，离线产生事件 3–6，再以相同 epoch 重连并收到有序回放与 replay_complete；断开观察者本身不取消 pending approval，Session close 才产生 cancelled。实验没有经过 HTTP/SSE、没有取消真实 Turn，也没有重启 daemon，因此只闭合本 Situation 的 cursor/approval 子路径。

                一致性问题

                问题 不充分实现的后果
                Session addressing 新客户端意外创建另一个会话
                Event cursor / replay 断线期间的审批、工具效果或终态丢失
                Cancel target 取消整个 Session，或错杀下一 Turn
                Partial effects UI 显示 cancelled，但工作区已经变化
                Multi-client ownership 两个客户端同时 steering，事件顺序不确定
                Protocol version 客户端把未知事件误当完成

                未决问题

                • 除 Qwen 进程内 EventBus 外，哪些 transport 提供显式事件 cursor、gap 与断线重放保证？
                • 审批 pending 时真实 transport writer、认证 lease 或 daemon 断线，Turn 应暂停、拒绝还是继续等待？
                • 恢复时工作区已被外部进程修改，Session 应如何标记状态漂移？

                这些问题没有足够共同证据，暂不写成统一 Interface。
