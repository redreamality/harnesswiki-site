                Situation：并行委派后合并工作区变更

                导航：Situation 索引 · 控制与连续性 · 编码工作面

                情境定义

                契约字段 内容
                触发 一个修复需要同时调查两个相互独立的模块，父 Agent 决定并行委派。
                初始状态 两个子任务共享目标与基线，但 actor、Session 和 Workspace 可以共享，也可以隔离。
                关键事件 两个 actor 读取代码、运行命令并返回报告或工作区变更；父任务收集结果、处理冲突并安排统一验证。
                可观察终态 父任务能区分报告与实际变更，知道每项效果的所有者、冲突与合并状态，并明确谁验证和接受最终结果。

                该情境连接任务、目标与多 Agent 编排、会话与运行拓扑、工作区事务和验证反馈。

                三种正交拓扑

                有多个子任务不必有多个 Agent；有多个 Agent 也不代表工作区隔离。把三种拓扑混成“支持 multi-agent”，会掩盖真正的并发风险。

                领域时序

                sequenceDiagram
    actor U as 用户
    participant P as Parent Agent
    participant O as Orchestrator
    participant A as Child A
    participant B as Child B
    participant WA as Workspace A
    participant WB as Workspace B
    participant V as Verifier

    U->>P: 提交可拆分任务
    P->>O: 创建子任务 A、B 与完成条件
    par 调查/修改 A
        O->>A: 任务 + 有界上下文 + workspace identity
        A->>WA: 读取、修改、验证
        A-->>O: 结果 + artifact/diff + 终态
    and 调查/修改 B
        O->>B: 任务 + 有界上下文 + workspace identity
        B->>WB: 读取、修改、验证
        B-->>O: 结果 + artifact/diff + 终态
    end
    O->>P: 汇总结果与冲突信息
    P->>P: 选择、合并或要求返工
    P->>V: 在目标工作区运行整体验证
    V-->>P: 可交付终态
    P-->>U: 说明合并范围与验证

                若 WA 与 WB 指向同一个工作区，图中的并行修改就没有事务隔离；Harness 需要串行写入、文件锁或把子 Agent 限制为只读调查。若它们是 worktree，最终仍需显式合并与整体验证。

                实现分支

                OpenCode：child session 表达 actor 血缘

                • 状态：implemented
                • 研究锚点：见 OpenCode 画像

                OpenCode 区分 primary agent 和 subagent，子 Agent 创建 child session，客户端可在 parent/children 之间导航。它清楚表达会话血缘，但 child session 本身不自动证明文件系统隔离；工作区写入边界必须另查工具与事务实现。

                DeepSeek Harness：subagent、goal 与 background job 是不同 seam

                • 状态：implemented
                • 研究锚点：见 DeepSeek Harness 画像

                DeepSeek Harness 分开建模同会话 goal、background jobs 与 subagent capability。工作是否持续、是否产生独立 actor、结果如何回到 consumer 是不同契约，避免用一种“task”对象承担全部含义。

                Qwen Code：team/subagent 与 worktree 可组合

                • 状态：implemented
                • 研究锚点：见 Qwen Code 画像

                Qwen Code 提供 subagent/team 以及 worktree 相关能力，适合观察 actor 拓扑和 workspace 拓扑如何组合。是否默认隔离、冲突如何回报和最终由谁合并，仍应以固定锚点源码与对应 Primitive 页为准。

                mini-SWE-agent：外部批处理的替代机制

                • 状态：alternative
                • 研究锚点：见 mini-SWE-agent 画像

                mini-SWE-agent 核心循环不需要内建子 Agent；批量 runner 可以在多个独立环境中并行运行完整任务。它把并发、隔离和结果收集放到 Harness 外层，适用于彼此独立的任务，但不等同于一个父 Session 内的动态委派。

                Kilo Code：child 恢复、权限上限与 Agent Manager worktree 分开

                • 状态：implemented
                • 研究锚点：见 Kilo Code 画像

                Kilo Task 沿 parentID 计算深度，创建或恢复 child Session；恢复只接受当前 parent 的直接 child，并在模型选择后施加 mutation/MCP permission ceiling。child identity 与恢复约束 · permission ceiling

                前台等待与实验性后台结果注入共享同一 child identity，但它们不会自动创建 Agent Manager worktree。收益是 child lineage 与 capability ceiling 清楚；代价是 host、Session、background delivery 和 workspace placement 必须由调用方分别组合。

                Loopal：local 与 cross-Hub child 是不同信任边界

                • 状态：implemented
                • 研究锚点：见 Loopal 画像

                Loopal Agent tool 可选择 foreground/background、model/subagent type 与 local worktree。Local child 可以继承 caller cwd 和压缩 Context；cross-Hub child 明确不传 cwd、fork Context 或 resume，由目标 Hub 选择 default cwd。Agent tool · local/cross-Hub boundary

                它把分布式 placement 对 Context 和 cwd 的影响写成显式边界，避免远端 child 假装拥有本地环境。收益是跨 Hub 信任传播可解释；代价是跨 Hub resume、完整取消级联和最终 worktree join 仍需额外协议。

                设计取舍

                策略路线 代表 Harness 收益 代价 / 失败模式 适用条件
                child Session，默认共享工作区 OpenCode actor 血缘和继续点简单 并行写冲突需另行防护 只读调查或写入可串行化
                provider 化 durable child DeepSeek Harness one-shot、continue、cold resume 可区分 provider negotiation、取消和 disposal 更复杂 需要多 backend/长生命周期 child
                actor + 可选 worktree Qwen Code Context 与 Workspace 可独立组合 join、冲突、嵌套限制需显式处理 子任务可能并行修改代码
                parent-bound child + capability ceiling Kilo Code 恢复归属和权限上限明确 host/worktree/background 仍需多轴配置 IDE/远端 host 介导委派
                local/cross-Hub 双边界 Loopal 跨机器时不误继承 cwd/Context 分布式消息、取消、恢复和交付成本更高 多 Hub fleet 或远端 specialist
                外层批处理多个完整任务 mini-SWE-agent 内核最小、环境天然可隔离 不是父 Session 内动态协作，难共享中间状态 彼此独立的 benchmark/批处理任务

                共同点是都能并行获得结果；真正差异在于并发被放在 Session 内、provider、远端 Hub 还是外层 runner。选择路线时应先决定是否需要共享中间 Context、动态 steering 和同一 Goal，再决定是否值得承担 child lifecycle 与 workspace join 的复杂度。

                必须记录的终态

                层次 最小终态
                子任务 completed / failed / cancelled，以及完成条件
                子 Session 最后事件、父引用、可访问产物
                工作区 基线、diff、冲突、是否已合并
                父任务 接受/拒绝哪些结果，是否重新验证

                只返回一段子 Agent 文本会丢失工作区事实；只合并文件而不保存子任务终态会让恢复和审计失去依据。
