                Harness 机制地图

                导航：首页 · 设计精髓总览 · 领域模型 · Primitive 重写规划 · 研究方法 · Harness 索引 · 情境索引

                机制地图采用“Theme → Primitive → Situation → Implementation”四层导航。当前共有 35 个正式 Primitive；Theme 只回答“去哪里找”，Primitive 才是比较机制的基本页面。另有 4 个协调指南串联相邻 Primitive，但不参与 Primitive 计数。详情见领域模型。

                运行内核

                研究一次持续运行如何形成、怎样向模型提供输入，以及模型行动如何进入能力系统。

                Primitive 核心问题
                会话与运行拓扑 Session、Turn、Step、分支和终态怎样组织？
                Agent 循环与工作模式 观察、决策、行动和完成判定如何循环？模式改变了什么？
                模型接入与路由 Provider、能力、角色与运行中换模如何解耦？
                上下文压缩 预算不足时压缩事务何时触发、提交什么、怎样继续？
                工具输出保留 旧 Observation 以原文、裁剪还是占位符进入后续 Context？
                语义上下文快照 哪段历史被提炼为带范围和有效性的模型可见继续状态？
                上下文表示降级 高成本节点怎样降级，原内容还能否重新取得？
                上下文血缘 替换、裁剪或摘要后的节点怎样保留来源关系？
                长期记忆 哪些知识跨 Session 写入、召回、更正和遗忘？
                指令发现与组装 项目指令从哪里发现，如何处理作用域、信任和优先级？
                工具与能力运行时 工具如何注册、派发、执行并规范化 Observation？

                主题说明与边界见运行内核索引。

                编码工作面

                研究 Harness 如何理解、修改、执行和验证真实工作区，而不是只生成文本建议。

                Primitive 核心问题
                代码库智能 如何在有限预算下定位相关文件、符号和依赖？
                变更生成与应用 模型输出如何成为确定、可检查的文件变更？
                执行放置 Action 绑定哪个 Execution World，世界怎样寻址、重连和释放？
                进程连续性 cwd、环境、PTY 和进程树跨哪些 Action 继续存在？
                验证与反馈 何时运行检查，失败如何归因并进入下一 Step？
                版本控制与工作区事务 如何保护基线、隔离并发修改、回退和交付？

                主题说明与主链路见编码工作面索引。

                控制与连续性

                研究一个运行怎样受约束、跨时间保存，并被拆成可管理的工作拓扑。

                Primitive 核心问题
                Action 授权 哪个 Action 在什么 policy context 下被 allow、ask 或 deny？
                审批协调 待决请求怎样呈现、回答、超时、撤回和恢复？
                审批者身份 哪个 principal 有权回答，控制租约和竞争响应怎样处理？
                执行隔离 已授权 Action 的文件、进程、网络和凭据效果被什么强制边界约束？
                状态持久化与恢复 会话和工作区的哪些状态能恢复，恢复到哪里？
                Goal 证据协议 complete 或 blocked 声明需要什么证据和终态义务？
                工作拓扑 Work Item 的依赖、claim、lease、join 和结果归属怎样组织？
                Actor 委派 parent 怎样授予 child 身份、Context、权限和取消边界？
                后台 Job 生命周期 长时执行怎样获得稳定 identity、输出、等待、取消和终态？
                配置、资源发现与项目信任 启动时实际加载什么，来源如何合并并取得信任？

                主题说明与连续性边界见控制与连续性索引。

                组合与互操作

                研究内核怎样被扩展、由其他客户端控制，以及怎样留下可观察、可重放的运行记录。

                Primitive 核心问题
                扩展与生命周期 扩展如何发现、加载、拦截事件并撤销副作用？
                控制平面与互操作协议 客户端如何寻址会话、发送命令、接收事件和取消运行？
                耐久 Transcript 哪些 Session 事实跨进程保存并可用于重建历史？
                在线事件流 当前订阅者怎样接收增量状态、背压和明确终态？
                重连投影 新客户端从哪个 cursor 恢复有界状态并接入在线流？
                遥测导出 运行信号怎样采样、脱敏、聚合并发送给观测后端？
                评测 Trajectory 怎样把任务、Action/Observation、终态和评分组织成可比较样本？
                产物交付 Patch、报告或文件怎样成为外部消费者可稳定检查的 Artifact？

                主题说明与协议分层见组合与互操作索引。

                协调指南

                协调指南描述多个 Primitive 怎样组合，不拥有新的状态或契约，也不参与 35 个正式 Primitive 的计数。

                协调指南 串联的 Primitive
                执行环境、放置与连续性 执行放置、进程连续性、工具运行时与输出保留
                权限、审批与隔离边界 Action 授权、审批协调、审批者身份与执行隔离
                任务、目标与多 Actor 编排 Goal 证据、工作拓扑、Actor 委派、后台 Job 与产物交付
                运行记录与回放边界 耐久 Transcript、在线事件流、重连投影、遥测导出与评测 Trajectory

                阅读路径

                • 第一次系统阅读：先用共同语言和设计精髓与横向比较认识六段所有权与术语，再按总览的 5 个代表性 Harness 建立具体直觉，回到同抽象比较后才沿 Primitive / Situation 深挖；不要从本页 35 个术语随机跳读。
                • 想理解概念边界：从领域模型进入，再选择一个 Theme。
                • 想比较同一机制：进入 Primitive 页，沿 Situation 查看多个 Implementation。
                • 想理解单个产品：从Harness 索引进入，再反查其 Primitive。
                • 想观察端到端行为：从情境索引进入，跨 Primitive 跟踪一次运行。

                成熟度说明

                当前页面同时包含 Observed Pattern、Proposed Abstraction 和 Accepted Primitive。页面数量不等于抽象已经稳定；只有解释三个独立实现并经反例检验后，Primitive 才能升级为 Accepted Primitive。成熟度升级规则见研究方法。
