                  DeepSeek：副作用未知终态、失效压缩候选与证据保留

                  导航：首页 · 画像 · 既有恢复实验 · 版本演进
                  观察日期：2026-10-24 · 第二轮最新源码刷新：fetched，保留首轮两次直连失败历史
                  首轮 Claim 与行为锚点：99f6f02fecdb7dff40c3fbc9470f5907c29f74ca；第二轮 Claim 锚点：22ddee3792402c3e70ec5f86a63c3e3e895a2f60

                  本轮补上两类实质证据。第一类让本地服务真正完成一次写入，再杀死尚未记录 result 的日志生产进程。第二类暂停异步摘要，在等待期间改变投影，并连续运行两次压缩。全部调用固定提交中的真实模块，不使用模型凭据，不修改真实业务系统。

                  边界一：外部成功不等于日志知道成功

                  Evidence Claim 字段 内容
                  Harness / Primitive DeepSeek Harness / 状态持久化与恢复
                  Situation 服务完成写入并确认响应，进程在记录工具 result 前被杀死
                  Fact type observed，实现探针；恢复策略由固定源码支持
                  Claim 修复函数补写 unknown 终态而非重放工具；再次修复已闭合日志不追加事件。这是日志修复幂等性，不是外部效果去重
                  Source interruptedTurnClosers、本轮探针与机器证据
                  Limit 不覆盖 coordinator 的并发恢复、真实工具调度或模型后续决策；服务是专属 loopback 计数器

                  子进程先把 seq 0–4 写入并同步磁盘，最后一条为 tool/call。随后向 127.0.0.1 的临时端口发送 POST。服务将计数和收据落盘，返回 count: 1；子进程收到确认后通知父进程，父进程发送 SIGKILL，等待子进程退出，再读取日志。此时服务已经成功，但日志只有五条事件，没有 tool/result。

                  检查 实际结果
                  工具终态 合成 seq 5，TOOL_OUTCOME_UNKNOWN，引用原 call seq 4；不把未知误报为外部失败
                  旧执行闭合 seq 6 为 step/end，seq 7 为 turn/end，原因 interrupted
                  外部效果 修复后 GET 仍为 count: 1，服务收据只有一条；修复函数没有发起 POST
                  相同输入 对未修复的原日志重复调用，返回相同 closers
                  已完整修复 持久化 closers 后再读日志，修复返回 []
                  模拟部分修复的完整记录边界 将仅含合成 result 的前缀实际落盘并重读，剩余为 step/end、turn/end；另一个前缀多含 step/end 时只剩 turn/end。补齐后再落盘重读，修复均为空；这里没有第二次杀进程
                  缺少 call 的对照 去掉 seq 4 后，返回 TOOL_NOT_STARTED，与已记录调用的 unknown 分类不同
                  故意盲重试 探针另发一次 POST，计数变成 2；这是对照操作，不是 Harness 自动执行

                  新增之处是“外部确实成功”已有独立落盘收据，且进程确实被终止。旧实验仅种下一个缺结果的调用，没有真实执行 write_remote。两者都支持谨慎处理 unknown，但只有本轮实测同时掌握独立外部状态。

                  本地服务没有实现幂等键，合成 result 也不查询服务。callId 的相关性和修复日志的稳定性不能替代业务接口的去重协议。固定提交的语义 checkpoint 设计记录明确不承诺通用 exactly-once；本轮不推断其他 provider 是否另有去重能力。

                  边界二：摘要等到回来时，原区间可能已经变化

                  Evidence Claim 字段 内容
                  Harness / Primitive DeepSeek Harness / 上下文压缩
                  Situation compaction/start 已追加，摘要 Promise 尚未完成，其他写入改变当前模型投影
                  Fact type observed，真实 compactSurfaceRegion 事务函数与真实投影管理器
                  Claim selected-span 只容忍选区外的追加；选区改写使候选失效。whole-surface 连选区外追加也拒绝
                  Source compactSurfaceRegion、两种稳定性检查
                  Limit 直接调用事务层；不验证 Agent.runMaintenance 的真实排队、UI 提示或模型生成质量

                  先准备三条可见消息，选中前两条，摘要函数停在一个受控 Promise 上。在真正等待期间实施一次变更，再释放摘要。不是顺序构造两个完成后的快照。

                  用例 owner / stability 等待期间的变更 终态与保留证据
                  selected-replaced null / selected-span 另一个 replacement 替换选区头节点 ManualCompactionError.code=changed；只有 start、带 error 的 end，无 summary；竞争者的 replacement 保留
                  selected-tail null / selected-span 在选区外追加消息 成功追加 summary、replacement、end；投影 [6,2,4] 保留原 tail 与并发追加消息
                  whole-tail current-turn / whole-surface 开放 turn 中在选区外追加消息 SurfaceChangedError；只有 start、带 error 的 end，无 summary；追加消息仍可见

                  自动路径的异常没有被强行写成手动入口的 changed 分类。源码中自动 compactRegion 与手动 compactNow 分别采用上述参数。compaction/start 记录开始等待的事实，compaction/end {error} 保留失败尝试；拒绝候选不意味着日志回到尝试之前，也不意味着删除并发写入。

                  两次压缩：保留原始证据，不自动恢复模型原文

                  这是边界二的连续压缩扩展，关联上下文血缘与耐久 Transcript。事实类型为 observed；源码为提交摘要与 replacement、投影重建与血缘校验。

                  初始消息是 ORIGINAL_A、ORIGINAL_B、RETAINED_TAIL。第一次压缩前两条，第二次压缩当前摘要与 tail。两次都执行真实事务提交逻辑，随后把全部事件写入 JSONL、重新读取，并调用真实 foldSurface。

                  层次 实际结果
                  第一次压缩 summary seq 4、replacement seq 5，遮蔽 [0,1]
                  第二次压缩 summary seq 8、replacement seq 9，遮蔽 [5,2]；范围按投影位置解释，不按数字升序
                  第二次摘要输入 包含 SUMMARY_ONE，不包含 ORIGINAL_A；输入来自当前投影
                  落盘后事件 共 11 条，两个 compaction/summary；原始文本和第一份摘要仍在日志
                  重载后的模型投影 只有 seq 9，含 SUMMARY_TWO，没有原文或第一份摘要
                  第二次 replacement 的来源 [7,8,5,2]，分别包含本轮 start、summary、上一轮 replacement 和 tail
                  血缘负向对照 删去 [5,2] 后重建投影，被 must include every shadowed surface node 拒绝

                  保留链是 seq 9 引用 seq 5，seq 5 再引用原消息；不是每轮都复制所有祖先 seq。原始信息可以沿日志审计，不能从第二份摘要推断语义完全保留。摘要生成器是固定返回值，本轮没有测量摘要忠实度、多轮遗漏率或自动检索旧证据。

                  尚未闭合与失败记录

                  • 第二轮刷新已经成功；首轮异步压缩和两次压缩的 observed 仍只属于旧行为 SHA，新版压缩模块执行边界见第二轮证据。
                  • 外部效果由探针子进程发起，日志由探针持久化；未验证真实工具执行、checkpoint policy、JSONL coordinator 与模型恢复串成的完整崩溃流程。
                  • 部分修复实验显式构造完整记录前缀、落盘并重读，没有第二次杀进程、半行 JSON、磁盘故障或并发 coordinator，因此不证明存储修复具备原子性。
                  • 异步压缩覆盖真实等待与区间变更，但不覆盖多进程竞争、flush 失败、真实 Agent 排队和执行期间再次崩溃。
                  • “两份摘要及原文仍在日志”不证明无限压缩后的语义完整性，也不证明产品 UI 提供递归证据召回。
                  • 早期运行因隔离依赖缺失而在模块加载阶段失败；一次运行把摘要误构造成字符串，已改为上游要求的 ContentBlock 数组。只将最终成功运行保存为正向证据。

                  本页保留首轮实验，不覆盖或撤回其历史结论。三个目标模块在旧画像与旧行为提交间 blob 完全相同，而第二轮默认分支三个 blob 均改变；版本区间及迁移边界见版本记录。
