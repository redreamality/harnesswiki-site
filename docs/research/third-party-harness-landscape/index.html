                第三方 Harness 仓库全景

                初始快照：2026-08-17；Corpus 状态同步：2026-08-19。本文核验第三方 Harness、IDE 内嵌 Harness、垂直领域 Harness，以及容易被误算成 Harness 的控制层和工作流壳。Mistral Vibe、Refact、Zed Agent、Stakpak Agent 与 browser-use 已在后续覆盖审计中进入正式 Corpus；开源不是收录条件，开放性只决定能否对内部实现作源码级判断。

                口径与证据

                本文沿用生态调研的定义。一个完整 Harness 至少同时拥有：

                1. 面向任务的可运行入口；
                2. 持续推进模型决策与 observation 的 agent loop；
                3. Session、消息历史或等价的上下文状态；
                4. 自己定义的工具执行语义，而不是把完整循环交给另一个 Harness。

                调研只使用项目官方仓库、README、LICENSE、release、源码和官方包元数据。表中的“完整”表示满足上述职责，不表示功能多、质量高或适合所有场景。“边界层”不是贬义：AgentsMesh 一类控制平台解决的是比单 Harness 更高一层的问题，但不能重复计为新的底层 agent loop。

                独立 Coding Harness

                这些项目均有可核验的任务入口、执行循环、状态和工具。优先级描述的是对 Harness Wiki 机制研究的增量价值，不是产品排名。

                Grok Build 完整 Harness。仓库同时包含 Rust CLI/TUI、agent runtime、工具、workspace 与 memory；不是只公开 UI 或插件。 xAI 独立实现，Apache-2.0。建议列为 P0：Rust 分层可与 Codex、goose 做直接结构比较。固定锚点 9fabadea800fa6e2ed8ec91c4f45f02b7e2504f4。 README · agent · tools · workspace · LICENSE
                Mistral Vibe 完整 Harness。事件驱动 loop 自己拥有模型请求与工具执行；durable local Session 支持压缩、fork/rewind 和 child session。 独立实现，Apache-2.0；本轮已进入正式画像，用于研究 loop、Session、压缩与恢复边界。 仓库 · 事件驱动 loop ADR · Session ADR · LICENSE
                Freebuff 完整 Harness。agent runtime 明确分开单步运行、历史压缩与工具目录，覆盖连续 tool-call 和 context maintenance。 当前 canonical repo 是 CodebuffAI/freebuff，旧 Codebuff 地址已迁移；Apache-2.0。建议 P0：适合研究 TypeScript runtime 如何暴露 agent step。 README · run-agent-step.ts · compact-history.ts · tools · LICENSE
                SWE-agent 完整任务型 Harness。Agent 实现显式 action/observation loop、trajectory、review/retry，并有独立 environment 与工具层。 SWE-bench issue repair 谱系；与其后继 mini-SWE-agent 必须按 family 标注，不能把继承设计当两份独立证据。建议 P0：保留为任务型 Harness 的历史主干。 README · agents.py · environment · tools · LICENSE
                Open SWE 完整异步 Coding Harness。具备云 sandbox、编码工具、消息队列 middleware、Slack/Linear/GitHub 入口和 PR 交付闭环。 基于 Deep Agents/LangGraph 组合，不是独立底层 framework 发明。建议 P1：研究异步入口、队列、云执行和交付，不把 LangGraph 原语重复计票。 README · 源码 · LICENSE
                Refact 完整 Harness。当前仓库包含 daemon、worker、Session 状态、工具、worktree fleet 与 memory，覆盖本地任务到并行工作区执行。 当前 canonical repo 是 JegernOUTT/refact；旧 smallcloudai/refact 已声明迁移并归档。BSD-3-Clause；本轮已进入正式画像，用于研究 daemon/worker、控制平面与 worktree fleet。 当前仓库 · 当前 README · 旧仓库迁移说明 · LICENSE
                Pochi 完整 IDE Harness。任务入口、文件/命令工具、worktree 并行与自动压缩由 Pochi 自己拥有。 Tabby 的 agent 能力已经拆到 TabbyML/pochi；不能从 TabbyML/tabby 服务端反推 IDE agent loop。Apache-2.0。建议 P0：作为 Tabby→Pochi 边界拆分案例。 README · 源码 · LICENSE · Tabby 仓库
                RA.Aid 完整但停止活跃的 Coding Harness。LangGraph 流程覆盖 research→plan→implement，可选择原生编辑或 Aider，另有 shell 审批、memory、自动测试和 CLI/Web 入口。 独立产品层，但复用 LangGraph/Aider 时需标注依赖。建议 P1 历史样本：适合研究显式阶段工作流。 README · 源码 · releases
                AutoCodeRover 完整窄域 Harness。围绕 issue repair 组合 AST 结构检索、patch 生成、测试与故障定位，并提供 GitHub、本地仓库和 SWE-bench 入口。 独立研究谱系；默认分支最后可核实提交为 2025-04-24。建议 P1 历史样本：用于比较结构化检索与通用 shell-first Harness。 README · 源码 · commits · LICENSE
                Prime Agent 完整长任务 Harness。具有持久 IPython、RLM 子 agent、continual harness refinement、daemon、heartbeat 与 schedule。 README 明确基于 Pi，应归入 Pi Family，不能按全新 loop 机制独立计票。建议 P1：研究长任务持续性与运行中自改进。 README · 源码 · LICENSE
                DeepSeek-Reasonix 完整 Harness。单 Go binary 让 TUI、Desktop、Web、ACP 共用内核；planner/executor 双模型、cache-aware compaction、checkpoint/rewind 和扩展协议均由项目实现。 与 DeepSeek Harness 名称相近，但当前证据显示是 esengine 的独立实现，不应按官方 DeepSeek Harness fork 处理。MIT。建议 P0：适合研究多前端共核与双模型 loop。 README · 源码 · LICENSE
                DeepCode 完整 Harness。CLI/Desktop 共用 runtime，并显式维护 Session、Goals、Skills、权限、验证和 headless 运行。 HKUDS/DeepCode 独立实现，MIT。建议 P1：与同名旧项目或“Deep Code”营销名区分，按规范仓库地址记录。 README · 源码 · LICENSE
                Stakpak Agent 完整 DevOps Harness。Autopilot、异步作业、secret substitution、network guardrail、rulebooks 和持久 knowledge 构成面向长期运维任务的运行宿主。 垂直领域独立实现，Apache-2.0；本轮已进入正式画像，用于研究异步作业与 secret/network 安全边界。 README · 源码 · LICENSE
                mi 极简完整 Harness。README 直接展示约 30 行核心 loop，以 Bash/skill/delegate/goal 组合任务，支持 Docker sandbox、REPL 与非交互入口。 av/mi 是最小实现反例；快照时仓库 API 未识别许可证，开放性记为 未确认，不能擅自标 MIT。建议 P0 极简样本。 README 与 loop · 源码 · commits
                Kilo Code 完整多入口 Harness，覆盖 IDE、CLI 等产品面并拥有运行时、Session 和工具执行。 README 明确 Kilo CLI fork 自 OpenCode，应归入 OpenCode Family；MIT。建议 P1 产品谱系样本，只把 fork 后新增机制视为独立证据。 README · 源码 · LICENSE

                IDE 内嵌与垂直领域 Harness

                IDE、浏览器或 DevOps 产品并不会因为不是终端工具就自动成为“GUI 壳”。只要产品自身拥有 loop、Session 和工具执行，仍属于完整 Harness；反之，漂亮的 UI 如果只是启动外部 Claude Code/Codex，则留在控制层。

                项目 判定与关键机制 状态与研究价值 一手证据
                Zed Agent IDE 内嵌完整 Harness。crates/agent/src/thread.rs 直接连接 thread 状态、工具、subagent、权限、sandbox、compaction 与 retry。 活跃 IDE 内核样本；本轮已进入正式画像，用于研究 editor thread ownership、审批、隔离与 subagent。 Zed README · thread.rs · agent crate · LICENSE
                Void IDE 内嵌完整 Harness。chatThreadService.ts 管理持久 Thread、工具执行状态、审批、checkpoint 与重试。 仓库已归档，Apache-2.0。建议 P1 历史样本：与 Zed/Cline 比较 IDE 内 thread ownership。 README · chatThreadService.ts · LICENSE
                Warp Agentic development environment 内嵌完整 Harness。仓库包含 agent、computer-use、persistence、sandbox 与多 agent client，而不只是终端渲染。 AGPL-3.0 源码样本。建议 P0：终端、IDE 与 agent runtime 组合形态有明显增量。 README · agent 源码 · LICENSE
                browser-use 可嵌入的浏览器专用 Harness/runtime。Agent(task).run()、BrowserSession、工具和 history 共同提供浏览任务闭环。 MIT；本轮已作为跨域正式画像进入 Corpus，不计作 Coding Harness。它补足 DOM/视觉 observation、浏览器状态与高风险动作控制，并继续与 browser-use/browser-harness skill 仓库分层。 README · agent 源码 · browser session · LICENSE

                通用 Agent Harness 邻接样本

                以下项目拥有真正的 agent runtime，但主要任务对象不限于代码仓库。它们适合验证浏览器、通用 shell、多角色 SOP 等机制，不与 coding Harness 混在同一产品排名中。

                项目 判定 研究用途 一手证据
                OpenManus 完整通用 Harness。提供 CLI task 入口、agent loop、shell/files/browser MCP 工具和多 agent flow。 MIT。可研究通用 agent 如何把浏览器、shell 与多 agent flow 组合为任务宿主。 README · agent 源码 · flow 源码 · LICENSE
                MetaGPT framework/runtime 边界样本。有 metagpt "Create a 2048 game" 这类 turnkey 入口，但核心抽象是 Role、Action、Environment 和 SOP 多 agent 原语。 不作为完整 coding Harness 独立计票；用于研究固定角色/SOP 与动态 subagent delegation 的差异。 README · 源码 · LICENSE

                控制层、工作流叠加层与排除项

                这一组都与 Harness 生态直接相关，但当前证据不支持把它们列为新的底层 Harness。保留它们能防止两种遗漏：一是忽略多 Harness 控制平面，二是把“能启动 agent”误认为“自己实现 agent loop”。

                项目 正确分类 边界理由 一手证据
                AgentsMesh 多 Harness 控制/调度平台 官方定位是 agent control layer。Runner 在隔离 worktree AgentPod 中运行 Claude Code、Codex、Gemini、Aider、OpenCode 等外部 Harness；Autopilot 是持续控制 agent，但 worker loop 仍属于外部 Harness。BSL-1.1。应纳入 P0 控制平面研究，不计作新底层 loop。固定锚点 1f90b14194d0，release v0.44.7。 固定 README · Autopilot RFC · LICENSE · release
                Trellis 项目层/工作流记忆层 面向约 22 个外部 coding agent 提供项目知识和工作流，不拥有底层模型工具循环。适合研究跨 Harness memory/interoperability，不能按 22 个 agent 的共同 runtime 处理。 README · 源码 · LICENSE
                browser-harness 安装到现有 Harness 的 skill/workspace 仓库把浏览器 workspace 和技能安装给 Claude Code、Codex 等宿主；agent loop、Session 和通用工具策略仍由宿主所有。不要与 browser-use/browser-use runtime 混淆。 README · skills · LICENSE
                Vibe Kanban 多 Harness 编排壳 给外部 coding agent 分配 branch、terminal 和 workspace，不拥有 worker loop；官方 README 已标注项目 sunsetting。可作为 branch/workspace orchestration 的历史样本。 README 与 sunsetting 状态 · 源码 · LICENSE
                bolt.diy AI app builder，当前不按完整 Harness 计 README 把从 single model calls 迁移到 backend agent architecture 列为计划项，因此不能用未来架构反推快照日已有持续工具循环。 README · 源码 · LICENSE
                Dyad 待进一步核验的本地 AI app builder README 可证明本地 app builder 与代码生成入口，但本轮证据不足以确认由项目自身拥有完整持续 loop。许可证按目录区分 Apache-2.0/FSL，不应简化成单一“开源”。 README · 源码 · LICENSE
                Tabby 模型服务/补全与聊天服务端 Tabby 本体不再代表完整 IDE agent；相关 agent ownership 应检查独立 TabbyML/pochi 仓库。保留此行是为阻止把服务端能力错误归到 Pochi loop。 Tabby README · Pochi README
                PR-Agent PR 单工具工作流 官方 README 明确 /review、/improve 等每个工具通常只做一次 LLM 调用；它是有价值的 PR automation，但不是持续的通用 agent/tool loop。 README · tools · LICENSE

                闭源与 Source-available 入口

                开放性不作为排除条件，但证据强度必须匹配材料。没有公共核心仓库时，本文只记录官方产品/发布入口和外部可观察行为，不猜测内部 loop；有公开源码但许可证限制使用时，则标为 source-available 或 proprietary，而不是笼统写“开源”。

                产品 可记录入口 当前证据边界
                Claude Code 官方公共仓库 是完整且重要的闭源 Harness；公共仓库用于插件、安装、release 与 issue tracking，不包含完整核心实现，不能把仓库可见等同核心开源。
                Loopal 公开源码仓库 完整多 agent 产品入口，但仓库采用 proprietary license。可以研究官方架构与外部行为，复用或开放性判断必须服从其许可证。
                Antigravity CLI 官方发布仓库 公共仓库主要承载说明、示例和二进制发布，当前不能据此作完整核心源码断言。
                MiniMax Code 官方下载入口 已确认产品与二进制入口，尚未定位到可核验的官方核心仓库。仓库列表不应为补齐表格而引用非官方镜像。

                历史、归档与安全风险

                历史项目仍能解释 Harness 设计怎样演化，但“曾经完整”不代表今天适合安装或作为生态活跃度样本。安全事件尤其不能埋在普通维护状态里。

                项目 历史判定 当前处理 一手证据
                GPT Pilot 历史上是完整 Coding Harness。 官方 README 说明项目不再维护，并披露 2025-08 至 2026-06 的发布曾包含凭据窃取供应链恶意代码。仅保留为历史架构样本；研究、安装或复现实验前必须先固定到事件前的可信提交并独立审计。 官方安全与维护说明 · commits
                GPT Engineer 历史 code-generation pipeline，是 Lovable 的前身之一。 仓库已归档；用于研究 prompt/codegen pipeline 演变，不代表持续工具循环的当前最佳实践。 归档仓库 README · 源码 · LICENSE
                Mentat 历史 Coding Harness。 官方 PyPI mentat 1.0.19 明确描述为 archived project；AbanteAI/mentat 当前无法作为可解析的规范公共仓库锚点。新 Mentat 服务也没有本轮已核实的公共核心仓库，因此不把旧包和新服务混为同一活跃开源项目。 官方 PyPI 元数据
                smallcloudai/refact Refact 的旧规范仓库。 README 明确迁移到 JegernOUTT/refact 且旧仓库已归档；后续研究只用新仓库，旧地址仅作迁移证据。 旧仓库 README · 当前仓库

                Harness Family 与去重规则

                仓库数量不等于独立机制数量。后续纳入 Wiki 时至少按下列 family 关系标注：

                Family 仓库关系 计数规则
                OpenCode Family anomalyco/opencode → Kilo-Org/kilocode Kilo 是完整产品，但 CLI fork 自 OpenCode；共享 loop 只算一份证据，Kilo fork 后新增的 IDE、provider、策略或协作机制才独立计入。
                Pi Family earendil-works/pi → PrimeIntellect-ai/prime-agent，另有 can1357/oh-my-pi Prime Agent 与 Oh My Pi 均可形成完整产品，但继承的 Session/tool loop 不重复计票；只比较 persistent kernel、daemon、reviewer、worktree 等增量。
                SWE-agent Family SWE-agent/SWE-agent → SWE-agent/mini-swe-agent 两者适合做“复杂 ACI”与“单 Bash 极简化”的演变对照，不当作两个完全无关的机制来源。
                Tabby / Pochi TabbyML/tabby 与 TabbyML/pochi 这是职责拆分而非简单 fork：服务/模型能力按 Tabby 证据，完整 IDE agent ownership 按 Pochi 证据。
                Refact 迁移 smallcloudai/refact → JegernOUTT/refact 只把当前仓库作为活跃 canonical source；旧仓库不重复列成另一实现。
                browser-use browser-use/browser-use 与 browser-use/browser-harness 前者是可嵌入 runtime/Harness，后者是安装到外部 Harness 的 skill/workspace；组织相同不代表所有仓库属于同一架构层。
