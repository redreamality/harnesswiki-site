                  上游仓库引入清单

                  初次引入快照：2026-08-19 · 版本职责复核：2026-08-25
                  清单来源：Harness 仓库列表
                  用途：为浅克隆研究仓库提供规范 Git URL、默认分支、克隆前基线、当前引入结果和建议路径。

                  核验方法与结论

                  • 从仓库列表机械提取并去重得到 68 个 GitHub 仓库；另有 MiniMax Code 只有官方下载入口，没有已核验的官方核心 Git 仓库。
                  • 在主任务开始引入前，根目录没有 .gitmodules，git submodule status 为空，也没有上游仓库目录；因此下表 68 项的基线状态均为“未引入”。这是克隆前快照，不描述后续并行任务的实时状态。
                  • 默认分支通过仓库自己的 Git HEAD（git ls-remote --symref <url> HEAD）或 GitHub 官方仓库页的 defaultBranch 元数据核验。每行仓库链接与分支链接均指向一手来源。
                  • URL 重定向审计确认旧地址 OpenInterpreter/open-interpreter 已迁移到 openinterpreter/openinterpreter，清单使用新规范地址。
                  • 建议统一放在 upstreams/<owner>/<repo>。保留 owner 可区分 Refact 新旧仓库、browser-use 的 runtime/skill，以及同名或同 family 项目。
                  • 浅克隆模板：git clone --depth 1 --branch <default-branch> <git-url> <path>。若采用 submodule，还应记录固定提交；--depth 1 只限制本地抓取历史，不替代版本锚点。

                  当前引入结果

                  2026-08-19 的本地审计以 .gitmodules 和顶层 gitlink 为权威清单，并通过 pnpm upstreams:check 逐项读取子仓库元数据，不做网络请求：

                  检查项 结果 判定
                  .gitmodules 声明 68 与机械去重后的仓库清单一致
                  子仓库 HEAD = 顶层 gitlink 68 / 68 当前 gitlink 全部物化；不代表画像旧研究锚点已存在于浅克隆
                  origin = 规范 URL 68 / 68 比较前规范化末尾 .git 与 /
                  Git shallow repository 68 / 68 每个子仓库都只保留浅历史
                  .git 形态 58 个目录 + 10 个 gitfile 两种形态均可被 Git 正常寻址

                  因此仓库列表中已核验到官方 Git 地址的 68 项都已作为浅 submodule 引入。MiniMax Code 仍不计入 68：目前只有官方下载安装入口，没有可核验的核心 Git 仓库，不能为满足数量而猜测地址。审计刻意不把子仓库“工作树必须 clean”当成引入条件；身份、版本和浅克隆正确性由 gitlink、HEAD、origin 与 shallow 四项共同判定。
