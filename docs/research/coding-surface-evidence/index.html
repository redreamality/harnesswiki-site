                编码工作面、执行与工作区事务证据底稿

                快照日期：2026-08-17。导航：调研底稿 · 研究方法 · 领域模型 · 编码工作面 · Harness 索引

                本文固定 aider、Cline、OpenHands 与 mini-SWE-agent 的源码版本，研究同一个编码任务怎样经过代码发现、变更应用、命令执行、验证反馈和工作区恢复。结论只描述固定锚点能证明的机制；没有找到直接证据时写 unknown，不把零搜索结果写成 absent。

                快照与检查范围

                Harness 默认分支与研究锚点 许可证 本轮检查范围
                aider main@5dc9490bb35f9729ef2c95d00a19ccd30c26339c Apache-2.0 repomap.py、coder/edit formats、command execution、lint/test、Git commit/undo
                Cline main@8bbdde2a5c1f972864fe1b954f639c21fac61a40 Apache-2.0 sdk/packages/{agents,core,shared}、VS Code diff/diagnostics adapter、SDK guides
                OpenHands Canvas main@0d15c5e79e91a659f238954e1db8a3da289c4801 MIT Canvas 架构、Agent Server adapter、Git/change 与 conversation API
                OpenHands 委托 runtime OpenHands/software-agent-sdk v1.42.1@167c1f924ac8a8acbeb0432bf9b1fcf77d5c2497 MIT Agent loop、terminal、grep/editor/patch、confirmation policy、EventLog 与恢复
                mini-SWE-agent main@a83fcae82d2a08f0ee0c688f9d137b3566c097f8 MIT Default/InteractiveAgent、Local/Docker environments、默认 prompt、trajectory 保存

                OpenHands 当前 canonical repo 是 Agent Canvas，其架构明确不直接执行 Action、也不提供 sandbox；默认 backend 来自官方 software-agent-sdk。两仓库在本研究中组成一个 OpenHands Harness，委托 runtime 不作为独立投票。aider、Cline、OpenHands、mini-SWE-agent 是四个独立机制来源；mini-SWE-agent 与 SWE-agent 的继承关系在扩展语料时仍需去重。

                横向领域模型

                flowchart LR
    Task["任务与当前 workspace"] --> Discover["发现候选代码"]
    Discover --> Context["有预算的代码表示"]
    Context --> Model["模型决策"]
    Model --> Apply["变更协议 / Shell 替代"]
    Apply --> World["Execution World"]
    World --> Verify["lint / test / command observation"]
    Verify -->|可行动失败| Model
    World --> Tx["baseline / checkpoint / commit"]
    Tx --> Artifact["diff / commit / trajectory"]

                四个项目对这条链的切分差异很大：aider 为 Repo Map、edit format、lint 和 Git 提供专用机制；Cline 把 SDK tools、IDE preview、Session artifacts 和 Git checkpoint 组合起来；OpenHands Canvas 委托给拥有持久 terminal 与事件状态的 runtime；mini-SWE-agent 则只给模型 Bash，把搜索、编辑、Git 和验证责任移到模型与外层 environment。

                aider：专用 Repo Map、编辑协议与 Git 事务

                代码库智能：Tree-sitter 图与个性化 PageRank

                aider 的 Repo Map 不是文件清单或 LSP 查询。get_ranked_tags 从 definitions/references 构建 networkx.MultiDiGraph，把 chat files、提及文件和提及 identifier 注入 personalization，再运行 PageRank。implemented / implemented，图构建与排序

                渲染阶段按候选 tag 数量构造 tree，并围绕 max_map_tokens 二分调整保留量；因此 Repo Map 是任务相关且有预算的有损表示，而不是全仓库 AST dump。implemented / implemented，预算裁剪

                本轮没有发现 LSP 参与 Repo Map 的证据，故 LSP 状态为 unknown，不能从“符号与引用”反推语言服务实现。

                变更应用：可替换 edit format 与 dry-run

                aider/coders 为 whole-file、search/replace、unified diff、patch 等格式提供不同 coder。Search/replace 在 apply_edits_dry_run 中调用同一 applicator 而禁止写盘；正式应用尝试 exact/宽松定位，失败 block 被汇总成带文件与原块的反馈，要求模型只修复未匹配部分。implemented / implemented

                Architect 模式把“方案”与“实施”分成两个角色：architect reply 完成后选择 editor model/edit format，创建新的 editor coder，并把方案作为第二次模型调用的输入。implemented / implemented

                执行与验证：宿主 Shell、auto-lint 默认开启

                命令执行使用宿主机 subprocess.Popen(..., shell=True)；这证明它是宿主 Shell 执行，不是通用 sandbox。implemented / implemented

                Coder 默认 auto_lint=True、auto_test=False。编辑后自动 lint；lint 或已配置测试失败时询问用户是否修复，确认后将诊断写入 reflected_message，进入后续模型循环。implemented / implemented

                工作区事务与恢复边界

                默认 auto_commits=True。/undo 只接受当前 coder 记录的最后一个 aider commit；若相关文件又变脏或 commit 已推送，命令拒绝撤销，随后才对限定文件执行恢复并 soft-reset commit。implemented / implemented

                restore_chat_history 能从 Markdown 恢复消息，并在过大时触发 chat summary；没有证据表明它恢复 shell cwd、工具进程或完整工作区状态，因此只算消息历史恢复，不算完整 Checkpoint。alternative / implemented

                Cline：SDK tool runtime、Diff Preview 与 run-level Checkpoint

                搜索：ripgrep 优先，短 TTL 文件列表回退

                Cline 的 search executor 优先调用 ripgrep 并解析 JSON；不可用或失败时，从文件索引逐文件执行正则搜索。implemented / implemented 文件索引默认 TTL 为 15 秒，底层只是 rg --files，失败时递归 walk，并按 cwd 缓存；它没有符号关系或语义排名，不能称为 Repo Map。implemented / implemented · 构建与缓存

                VS Code host 存在读取 vscode.languages.getDiagnostics() 的 API，但本轮未定位它必然被当前 SDK Agent loop 在编辑后调用；LSP/diagnostics 自动注入保持 unknown。implemented 的能力入口

                变更应用：唯一替换与 context patch

                editor 支持 create、按一基行号 insert、唯一 old_text 替换；零匹配和多匹配都在写入前拒绝。implemented / implemented

                apply_patch 支持 add/update/delete/move。它先解析 patch、读取当前文件并用 computePatchChanges 计算内存 change set，再调用 applyChanges 写盘；context fuzz 会在结果中显式报告。implemented / implemented

                VS Code coordinator 在需要批准的 edit 前打开虚拟 diff；自动批准的 edit 只在执行时及写入后短暂展示 preview。源码还说明 preview 是 cosmetic，打开失败不能阻止 approval 或 edit。implemented / implemented · 自动批准路径

                Bash、Policy 与 Plan guard

                Bash executor 每次调用 Node spawn 新建子进程，继承宿主环境，并实现 timeout、AbortSignal 与跨平台进程树清理；它不是持久 shell，也没有由此获得 OS sandbox。implemented / implemented

                当前 SDK 文档明确：未出现在 toolPolicies 中的工具默认 enabled 且 auto-approved；显式 autoApprove:false 才要求批准。implemented / documented Runtime 在需批准但没有 callback 时返回拒绝原因，不会静默执行。implemented / implemented

                Plan mode 的 command guard 是文件修改命令黑名单。源码主动声明它不是 shell interpreter，无法捕获 python -c 或藏在 quoted bash -c 中的所有写入；因此它是行为 guard，不是 security sandbox。implemented / implemented

                Checkpoint 的真实触发与双恢复域

                Checkpoint 不是“每个 tool 后快照”。Hook 在 root run 的第一次 model 调用前识别新的 user run，避免 resume 覆盖原有 pre-run snapshot，再创建 checkpoint 并把 history 写入 Session metadata。implemented / implemented

                底层创建 stash-compatible commit，额外构造第三 parent 保存 untracked 文件，并把对象固定到 refs/cline/checkpoints/{sessionId}/{runCount} 私有 ref，不污染用户的 git stash list。implemented / implemented · 私有 ref

                恢复是破坏性工作树操作，因此 beginWorktreeRestoreTransaction 先为当前状态创建独立 private restore ref；createCheckpointRestorePlan 可以选择是否同时裁剪 messages。工作树恢复与消息恢复是两个正交域。implemented / implemented · 消息裁剪与 plan

                Session metadata 存在 SQLite sessions.db，同时记录 manifest/messages paths；Agent runtime 另有 restore(messages) 与 snapshot()。这说明会话元数据、模型消息状态和 Git snapshot 相关但不相同。implemented / implemented · Agent restore/snapshot

                自动 build/test 策略、SDK loop 是否自动消费 VS Code diagnostics、以及 LSP integration 均为 unknown；命令或 editor error 作为 tool result 回流只能证明 Observation feedback，不能升级为自动 verifier。

                OpenHands：Canvas 委托边界、持久 Terminal 与事件分支

                Canvas 不拥有 Action execution

                固定版本的 docs/architecture.md 明确：Agent Canvas 负责 UI、Agent Server API adapter 和运行呈现；它不直接执行 agent actions，也不提供 sandbox/workspace isolation。implemented / documented

                README 同时区分宿主直跑与 Docker：不使用 sandbox 时 agent-server 直接运行在用户机器上并有完整 filesystem access；Docker 是可选部署边界，agent 仍能访问显式挂载的 PROJECTS_PATH。implemented / documented

                因此本文把 Canvas 的 conversation/API 事实与 software-agent-sdk v1.42.1 的 runtime 事实组合，但每条 Claim 标明所有者。以后若 Canvas 连接任意 ACP backend，不能沿用默认 OpenHands runtime 的 tool、policy 或 terminal 结论。

                代码发现与变更应用

                Runtime 的 grep executor 按 ripgrep → system grep → Python filesystem walk 回退，并把候选限制到最多 100 个文件、按 mtime 排序。它是有上限的文本检索，不是符号图或 LSP。implemented / implemented

                File editor protocol 提供 view/create/str_replace/insert/undo_edit；独立 apply_patch tool 实现 context-based patch 与 fuzz。implemented / implemented，File editor · apply_patch

                undo_edit 使用 editor 自己的文件历史，只覆盖该工具拥有的局部变更；没有证据表明它撤销 terminal、Git 或其他工具的效果，不能称为通用 workspace rollback。

                持久 Terminal：placement 与 process continuity 分开

                Terminal 文档把命令会话定义为持久 shell，cwd、environment variables 与 virtualenv activation 可跨命令保留。implemented / documented Factory 优先选择 tmux，回退到 subprocess PTY；这是 process continuity，不能自动推导 deployment isolation。implemented / implemented

                ConfirmationPolicy 与默认值

                Runtime 把 AlwaysConfirm、NeverConfirm、ConfirmRisky 建模为策略对象。implemented / implemented 固定版本 ConversationState 默认 NeverConfirm()，security analyzer 默认 None；若配置 analyzer 则 Agent 计算风险，否则为 UNKNOWN，需要确认时进入等待状态。implemented / implemented · Agent policy integration

                拒绝产生 UserRejectObservation 并进入事件/模型历史，而不是抛出一个与执行失败相同的异常。这里可以确认 confirmation loop，但不能从策略对象推断 Canvas 的每种部署都启用了 analyzer 或 sandbox。

                Event persistence、fork 与非幂等重放

                Conversation event store 按事件持久化 JSON；事件树通过 parent_id 表达分支，active branch 决定当前投影。implemented / implemented ConversationState.create 能从持久化状态重建并检查 agent/tool 兼容性。implemented / implemented

                Canvas API 支持从指定 event fork conversation。implemented / implemented Runtime 的 rerun_actions 可以重放 Action，但实现与测试明确把非幂等副作用视为风险；它不是工作树 Checkpoint restore。implemented / implemented

                Canvas/Agent Server 还提供 Git changes/diff 与 conversation worktree 入口，但本轮没有定位到覆盖 tracked/untracked 工作树的通用 checkpoint/rollback。因此工作树恢复为 unknown；事件 fork 不能填补这个空白。统一自动 lint/test policy 同样为 unknown。

                mini-SWE-agent：单 Bash、每 Action 新进程

                极简 Agent loop 与 trajectory

                DefaultAgent 将 messages 同时用作模型历史和 trajectory；主循环执行 query → parse/execute actions → append observation，并在每步 finally 中保存 trajectory。implemented / implemented

                默认 mini.yaml 只向模型暴露 Bash，并在 prompt 中明确每条命令运行于新 subshell，cd 与环境变量不会跨 Action 保留。implemented / documented

                sequenceDiagram
    participant A as DefaultAgent
    participant M as Model
    actor U as User（confirm mode）
    participant E as Environment
    participant P as New shell process
    participant J as Trajectory file

    A->>M: current messages
    M-->>A: one Bash Action / final response

    end

    E-->>A: Observation

                Execution environment：容器持久不等于 Shell 持久

                LocalEnvironment._run 当前使用 subprocess.Popen 为每个 Action 创建进程，stdout/stderr 合流；不能继续沿用旧资料中的 subprocess.run 描述。implemented / implemented

                Docker environment 会保留容器和文件系统，但每次 Action 仍调用新的 docker exec ... bash -lc；因此 workspace placement 与 process continuity 是两个独立维度。implemented / implemented

                本地环境默认没有隔离。Docker、Bubblewrap、Singularity 与远端 SWE-ReX 是替代 environment，实际 filesystem/network/credential 边界取决于所选实现和配置。alternative / documented

                审批、编辑、验证与恢复

                InteractiveAgent 默认 confirm，对整条 Bash 命令请求用户确认；--yolo 关闭确认。它没有工具参数级风险分类。implemented / implemented · CLI 入口

                没有专用 Repo Map/LSP 或 edit protocol：模型通过 Bash 选择 find、grep、sed、脚本或 Git。默认 prompt 建议模型自行运行测试，return code 和输出成为下一轮 Observation；核心没有独立自动 verifier。这些都是同一 Situation 的 alternative，不是“不能搜索/编辑/验证”。

                Trajectory 可持续导出，但本轮没有找到从 trajectory 重新构造 Agent 并继续执行的直接路径，因此 resume 为 unknown。Git transaction/checkpoint 也未作为核心 Primitive 实现；模型可用 Bash 调 Git，外层 benchmark runner 可为样本提供独立环境。

                差异、反例与可提炼机制

                专用机制不是完成任务的必要条件

                mini-SWE-agent 证明代码发现、编辑、验证和 Git 可以全部通过 Bash 完成。它没有否定这些 Primitive，而是把状态与错误处理责任从 Harness 专用组件转给模型、Shell 和外层 runner。因此 Primitive 应按谁拥有状态与契约分类，不能按最终能否完成任务勾选。

                Checkpoint 必须带覆盖范围

                Cline checkpoint 覆盖 tracked/untracked 工作树，并可选择裁剪 messages；aider /undo 只撤销满足条件的最后一个 aider commit；OpenHands event fork 保存 conversation 因果但工作树 rollback 为 unknown；mini 的 trajectory 只证明记录可导出。四者不能统一写成“支持恢复”。

                Execution World 至少有两个正交轴

                OpenHands 持久 terminal 与 mini Docker 的对照最清楚：前者可以在宿主机持续 cwd/env，后者可以保留容器文件系统却每次创建新 shell。Wiki 应分别记录 placement/isolation 与 process continuity。

                预览、Policy 与 enforcement 不能合并

                Cline virtual diff 是透明度和交互入口，preview 失败不阻止执行；OpenHands ConfirmationPolicy 决定是否等待用户；Docker/OS boundary 决定允许后的最大效果。三者分别回答“看见什么”“该不该执行”“最多能影响什么”。

                unknown 清单

                Harness 本轮仍不能确认的事项
                aider LSP；通用 sandbox；chat history 之外的进程/工具状态恢复
                Cline 当前 SDK loop 的 LSP/diagnostics 自动注入；自动 lint/build/test policy；所有宿主是否使用同一 checkpoint lifecycle
                OpenHands 通用工作树 checkpoint/rollback；统一自动验证；所有 backend 的 isolation 等价性；Action 重放幂等性
                mini-SWE-agent 从 trajectory resume；核心工作区 checkpoint；专用代码索引与 edit protocol（只能确认替代路径）

                unknown 是证据状态，不是产品缺陷或 absent。只有源码或官方文档明确声明缺席、或检查范围可被穷尽时，才升级为 absent。

                可转写到正文的时序结论

                1. aider：模型 payload → edit dry-run → 写盘 → optional auto-commit → lint/test → 失败经用户确认反射。
                2. Cline：新 user run → checkpoint → model tool call → policy/callback → diff preview → executor → tool result + Session persistence。
                3. OpenHands：ActionEvent → optional risk → ConfirmationPolicy → waiting/approve/reject → persistent tool → ObservationEvent/EventLog。
                4. mini-SWE-agent：model → 单 Bash Action → 新 subshell → merged Observation → trajectory save。

                这些图表达领域事件，不声明四个项目实现共同接口。Interface 至少还需要统一 workspace identity、Action terminal reason、checkpoint coverage 和 Observation schema 的更多证据。
