                调研底稿与证据索引

                导航：首页 · 研究方法 · 机制地图 · Harness 索引

                本目录保存从一手材料到 Wiki 正文之间的证据底稿。底稿允许保留检查范围与未决项；正式 Primitive 和 Harness 页面只引用已经核验并绑定研究锚点的结论。

                底稿 范围 用途
                上游仓库引入清单 68 个 GitHub 仓库的规范地址、默认分支与本地路径 驱动可复现的浅克隆，并记录迁移与核验限制
                Harness 版本锚点注册表 20 个 Corpus 画像、20 个 Git source 与 1 个 external-only 画像 机器可读地区分画像 baseline、Claim/behavior anchor 与当前 gitlink，并拒绝把行为对齐误报成静态画像对齐
                Harness 画像覆盖审计 68 个 gitlink 的 Harness ownership 与画像覆盖 记录本轮五个新增画像的纳入依据、Family 去重与 20/19 计数口径
                Harness 生态与边界 候选发现、纳入边界、语料分层 解释为什么某项目进入 Corpus 或相邻层
                第三方 Harness 仓库全景 独立第三方、IDE/垂直 Harness、控制层、历史与 Family 扩展候选池并防止把编排壳或共享谱系重复计作底层 Harness
                运行内核与组合机制证据 Codex、OpenCode、DeepSeek Harness、Pi Session、压缩、工具、扩展、控制面等 Primitive
                编码工作面证据 aider、Cline、OpenHands、mini-SWE-agent Repo intelligence、编辑、执行、验证、事务等 Primitive
                独立验证样本证据 Gemini CLI、Qwen Code 检验前八个 Harness 中形成的抽象是否过拟合
                Qwen 控制面行为实测 Qwen daemon 的 mediator 与 EventBus 并发审批关联、订阅断线、Session close、cursor 回放与晚到响应的模块级 observed 证据
                恢复边界行为实测 Qwen Code、DeepSeek Harness 丢失 worktree、压缩恢复投影、未知工具终态与不兼容日志拒绝的 observed 证据
                Mistral Vibe 取消与静止边界 固定版本的 legacy app-server 与取消辅助函数 区分取消请求响应、child completion 和有界关闭；实测取消等待超时后 Task 仍可继续产生效果
                Harness 设计独有性深挖 20 个 Corpus Harness、10 组版本漂移、7 个共享抽象 逐项记录独有机制的事实、推断与禁止外推边界，并驱动设计精髓总览与后续 P0/P1 接线

                证据进入正文的条件

                1. 项目、默认分支和 Claim 研究锚点已经确认；当前本地 gitlink 的物化状态另行记录，不能替代研究锚点。
                2. Claim 能回到官方文档、固定 commit 源码或测试。
                3. Fact type 与 Implementation status 分开记录。
                4. 证据限制、谱系关系和 unknown 没有被省略。
                5. 正文同时链接 Harness 画像与相关 Primitive，形成双向路径。

                底稿不是“更多就更真”。同一 README 的多段描述只是一份来源，同一谱系继承的代码也只是一份独立机制证据。
