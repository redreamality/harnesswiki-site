                  主要结论

                  当 Agent 宣称完成时，有三个不同的问题：报告是否可信，报告是否仍对应当前工作，以及结果是否已经合入目标工作区。Refact 为这些问题设置了不同检查，不能把其中一项通过等同于全部通过。

                  编号 触发情境与 Claim 状态 / 事实类型 源码与限制
                  G1 验证期间会话历史改写，旧 verdict 返回 Superseded；验证期间发生 Goal 状态转换，也丢弃旧 verdict implemented + implemented Goal guard；保护会话版本与状态序列，不等于磁盘文件内容新鲜度
                  G2 验证器只读取当前有效历史，排除归档部分；单独调用模型且禁止工具 implemented + implemented 有效历史、请求参数；使用父线程模型，没有证明模型或信任主体独立
                  G3 总评 MET 与单项 UNMET 冲突时，解析结果仍为 Met implemented + observed，仅解析模块 实验结果、解析实现；未运行模型或完整完成流程
                  W1 两次 spawn 争同一卡，锁内重新检查 agent_chat_id，已被占用的请求失败 implemented + implemented spawn 的锁内检查、board 更新；是单进程互斥，不是有到期时间的 item lease
                  W2 旧 Agent 晚到 finish、旧 verifier 晚到报告、旧 cleanup 试图清理新 owner，均有对应身份或指纹保护 implemented + implemented finish、报告写回；未运行并发调度或跨进程实验
                  W3 缺失 Session 或停滞会触发通知/失败；显式 restart 重新绑定身份 alternative + implemented，相对于自动 lease 接管 monitor、restart；没有证实自动续租、过期重领或 fencing token
                  W4 工作区进程租约防止两个 engine 占用同一规范化 root；进程退出后可重新取得 implemented + implemented workspace lease、上游崩溃测试；属于 workspace owner，不是单张任务卡 owner
                  J1 卡片报告、等待结束、依赖解锁与 merge 验证分别处理；没有报告时 merge 的 verifier gate 放行 implemented + implemented 依赖 ready set、merge gate、无报告测试；不能称为所有 join 都强制验收

                  所有静态 Claim 默认绑定本轮 SHA。表中 implemented 表示源码和上游断言已核验，不表示这些上游集成测试已在本机运行。

                  Goal：新鲜度保护到哪一层

                  verify_goal_before_completion 先在 Session 锁内把 Goal 改成 Verifying，记录 ledger 的序号与 trajectory_version，释放锁后调用 verifier。回写时重新持锁，先比较历史版本，再检查序号之后是否有状态变化。入口及提交路径

                  这里的 freshness 是“判断所依据的会话还有效”。历史版本不同会返回 Superseded，若仍在 Verifying 则恢复为 Active；状态序号保护只把 StatusChanged、TransferredOut、TransferredIn 当作失效事件。状态序列过滤 这不是通用的 expected Goal revision CAS，不能只因有递增序号就声称所有需求、criteria 或预算变更均受同一守卫保护。

                  上游 apply_goal_verdict_discards_verdict_when_status_changed_after_epoch 测试在验证期间写入 Stopped，断言旧结果被丢弃、状态保持停止、attempt 数量不变。断言 本轮未运行该测试。verifier_fork_uses_active_history_only 明确断言 verifier 输入含有效证据且不含归档 sentinel；legacy summary 还会被拒绝，而非由 verifier 偷偷迁移。有效历史测试

                  这套机制没有在所查 Goal gate 中对文件、当前 Git HEAD、测试产物或远端状态重新取指纹。外部文件变化但没有对应会话版本变化时，旧证据是否失效仍为 unknown。Card verifier 的指纹有 base commit 和 worktree 路径，却没有在该指纹中加入当前文件内容哈希；不能把它解释为完整工作区快照。

                  Producer 与 verifier 冲突

                  Producer 是完成工作的 Agent；verifier 是检查已有材料的另一次调用。Goal verifier 复制父线程配置，使用同一模型解析路径，设置 ToolChoice::None，并要求只判断是否满足目标。它与 producer 分开执行，但没有建立不同模型、不同账号或经过认证的证据来源边界。请求 最终文本也没有 Qwen 式 typed evidence kinds，因而不能直接迁移为完整的 Goal 证据协议。

                  确定性解析器先读第一行。GOAL: MET 立即返回 Met，不会用后面的 CRITERION ... UNMET 推翻总评。随后提交函数会记录逐项 verdict，但选择 Completed 的分支依据仍是总评。解析 · 提交 本轮实验确认前半段；端到端是否由真实模型产出此种矛盾回复没有测试。由此推断：若此回复进入守卫且版本检查通过，逐项失败不会阻止该分支提交完成。这是 inferred，不是完整 runtime 的 observed。

                  Card verifier 的路径不同。它提取 verification commands，在 worktree 内运行，再读取 diff 并调用 review；失败命令或语义 concern 归为 VerificationFailed，无法启动、策略拒绝或 review 不可用则归为 HumanReview。执行与分类 这避免把“测试没跑成”伪装为“代码测试失败”，也避免直接相信 producer 自报成功。

                  合并时，已有报告必须在总评、classification 和逐条命令 outcome 上一致；force=true 也不能绕过真实失败，只能在满足条件时接受基础设施类问题。上游测试明确拒绝 passed=true 但命令失败的矛盾报告。merge gate · 冲突断言 但没有报告时直接 Ok(None)，且有明确允许测试，因此这不是普遍强制的 verifier barrier。无报告断言

                  Work claim、崩溃与晚到结果

                  Claim 的原子边界

                  update_board_atomic 用进程内、按 task id 索引的 mutex 覆盖 load、updater、rev 增量和 save。spawn 在准备 worktree 前检查卡片，还在此锁内再次检查卡片是否已终结、是否已有 active agent_chat_id；竞争失败会清理未关联 worktree。board 更新 · spawn

                  这足以证明受控的同进程 claim，但不是分布式租约。BoardCard 保存 assignee、agent chat id、heartbeat 和工作区引用，没有在该 schema 中定义每次 claim 的到期时间与 fencing token。schema 更广的跨进程共享 task 目录、非受管 writer 和自动 claim 接管协议仍为 unknown。

                  新版增加的 engine workspace lease 是另一个层次。它对规范化 root 取得文件锁，managed worktree 归到 source workspace 的 root，锁与进程持有的文件句柄同寿命。上游崩溃测试启动子进程持锁，确认第二次获取失败，杀掉子进程，再确认可以重新获取。实现 · 断言 本轮未运行这一进程测试；也没有把 workspace lease 的恢复等同于卡片恢复。

                  崩溃接管的实际路径

                  monitor 每 2 分钟巡检，缺失 Session 等路径使用 20 分钟停滞门槛；流式生成和工具停滞另有 4/8 分钟门槛，先通知 planner，通知次数耗尽或长期无法通知时标记失败。常量 · 检查 因此这些时间是故障检测阈值，不是其他 worker 到期即可取得的租约。

                  mark_agent_as_failed 在更新时再次检查 assignee，避免旧巡检快照把新 owner 标成失败。restart 则支持 fresh 与 resume，先等待旧 Session 停止；超时会拒绝继续。创建新身份后，还在锁内核对原 column、assignee、chat id 和工作区绑定，拒绝覆盖已变化的卡片。失败更新 · restart

                  这证明“检测、通知/失败、显式重启”的恢复方式。机器崩溃后会不会无需 planner 决策就自动重领每一张卡，仍为 unknown。

                  三类晚到写入分别防护

                  晚到动作 拒绝条件 上游断言，均未在本机运行
                  旧 Agent 提交 finish 当前 chat id 或 assignee 已改变；终态卡拒绝重复 finish finish_heartbeat_rejects_restarted_card_owner、finish_failure_cleanup_preserves_restarted_owner，finish 文件
                  旧 verifier 写回 board rev 不能倒退，且 card fingerprint 必须相同 store_verifier_report_noops_when_card_restarted、store_verifier_report_noops_when_report_already_changed，报告测试
                  restart 准备完成后回写 原 owner 与工作区绑定不再匹配 restart_agent_source_guard_rejects_stale_previous_binding，restart 文件

                  注意 ExpectedCardState 采用 board_rev >= expected_rev 加卡片指纹相等，不要求全 board revision 相等。这让别的卡片更新不必废弃当前验证；同一卡的 verifier report 已是指纹一部分，所以先到的不同报告可让后到写入失效。指纹与比较 expected_state 是可选参数，不能将受保护调用链的保证扩展到所有无条件写入。

                  这些保护拒绝的是晚到状态写入。不能据此推断旧 Agent 已执行的工具、文件修改或 Git 操作也会被撤销；这类副作用需要独立的取消与工作区事务证据。

                  Join：结束工作不等于合并验收

                  任务结果汇合至少分为三步。第一步，Agent 提交报告；第二步，planner 收到完成/失败通知，或 wait_agents 等待结束；第三步，选择 worktree 并通过 merge 流程处理组合结果。wait_agents 有 30 至 1800 秒的可选唤醒时间，它只恢复 planner 检查，不证明工作完成。wait 工具

                  依赖 ready set 按前置卡片 column == done 判断，不要求其 verifier report 通过，也不检查变更已经合入目标分支。ready set A/B 任务的两份结果分别保存，第一份返回不会把共享卡片终结，上游有对应断言。A/B 测试 这些是结果收集与调度语义，不能取代工作区 join。

                  merge_agent 支持后置检查和可选自动回退；auto_revert 默认关闭。默认值测试 结合无 verifier report 的允许路径，整体结论只能是“具备检查与回退路径”，不能写成“所有卡片完成后必然组合验证成功”。依赖循环的统一拒绝、任意外部文件变更后的重新验收，以及跨进程 exactly-once join 仍为 unknown。
