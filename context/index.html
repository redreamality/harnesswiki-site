                Harness Wiki 共同语言

                这份术语表固定 Harness Wiki 的领域语言。它只定义概念，不描述任何产品的具体实现；关系、生命周期与例子见领域模型。

                研究对象

                Harness： 围绕模型持续组织上下文、工具、策略、执行环境与运行状态，并把任务推进到可检查结果的运行宿主。 避免使用：Agent、模型、CLI、IDE（这些词分别指行动者、推理能力或承载形态）

                Candidate Harness（候选 Harness）： 已进入发现池，但尚未通过边界、版本与证据核验的项目。 避免使用：Corpus Harness、已支持

                Corpus Harness（语料 Harness）： 已通过纳入标准并绑定研究锚点，可用于比较机制实现的 Harness。 避免使用：候选、热门项目

                Harness Family（Harness 谱系）： 因继承、Fork 或前后代关系而共享大量机制来源的一组 Harness；共同继承的机制只算一份独立设计证据。 避免使用：多个独立实现

                Wiki 研究模型

                Theme（主题）： 把职责相近的机制组织到一起的导航边界，不暗示统一接口或必备能力。 避免使用：能力清单、架构层

                Primitive（机制原语）： 具有独立状态、契约或生命周期，能在多个 Harness 中被具体定位和比较的最小稳定机制单元。 避免使用：Feature、产品卖点、宽泛 Module

                Coordination Guide（协调指南）： 串联多个 Primitive 的组合路径与边界说明，不拥有新的领域状态，也不参与 Primitive 数量或成熟度计数。 避免使用：Primitive、统一大模块

                Situation（情境）： 能够触发 Primitive 并显露实现差异的具体任务、事件或环境条件。 避免使用：功能勾选项、通用测试清单

                Implementation（实现记录）： 某个 Harness 在明确研究锚点下处理一个 Situation 的版本化事实，可记录直接实现、替代机制、明确缺席或未知。 避免使用：无版本的“支持”、产品宣传摘要

                Evidence Claim（证据声明）： 由一手来源支撑的最小可核验陈述，包含对象、研究锚点、事实类型和来源。 避免使用：无来源结论、第三方转述

                Observed Pattern（观察共性）： 至少两个独立 Harness 中出现、但尚未充分反例检验的相似机制。 避免使用：行业标准、Accepted Primitive

                Proposed Abstraction（候选抽象）： 为解释多个 Implementation 而提出，并明确适用边界与反例的统一说法。 避免使用：预设接口、最低公分母

                Accepted Primitive（已验证原语）： 至少解释三个独立 Harness，并经差异 Situation 与反例检验后仍保持稳定的 Primitive。 避免使用：多数产品都有、标准能力

                阅读辅助词

                这些词不是额外的 Primitive，只用于解释状态由谁控制。第一次出现时先按通俗含义理解，再进入具体页面看严格边界。

                Owner（所有者）： 负责保存某项状态并决定其生命周期的对象或组件。这里的“拥有”不是代码文件归属，而是“谁能创建、修改、终止和恢复它”。

                Principal（主体）： 可以被系统识别并承担权限的参与者，例如本地用户、远端客户端、服务账号或 Agent。看到请求的人不一定就是有权回答的人。

                Credential（凭据）： 主体用来证明身份或权限的材料，例如登录会话、token、签名或本机用户身份。客户端自报一个 id 不自动构成凭据。

                Lease（租约）： 带有效期或撤销条件的临时控制权。它常用于避免两个客户端或 worker 同时认为自己拥有同一请求、任务或 Session。

                Projection（投影）： 从更完整的事实源计算出的当前视图，例如从事件日志生成聊天界面，或从 Session 历史生成模型上下文。投影可以丢失细节，不能反过来冒充事实源。

                Provenance / Lineage（来源 / 血缘）： 记录一项摘要、分支、变更或产物由哪些原始事实产生。它让读者能从“现在看到的结果”追到“它替代或继承了什么”。

                Cursor（游标）： 事件流中的已读位置。客户端重连时可用它说明“我已经看到哪里”，但只有游标范围和保留窗口都明确时，才能证明没有漏事件。

                Quiescence（静止）： 相关 actor、工具和进程都不再产生新效果的状态。父 Agent 停止等待，不代表 child 或后台命令已经静止。

                Enforcement（强制执行）： 系统真正阻止越界效果的机制，例如 OS sandbox、容器策略或网络代理。规则文本、风险分类和确认 UI 都可以影响决策，但不自动等于 enforcement。

                Harness 运行模型

                Session（会话）： 跨一次或多次交互保存运行历史、分支关系和恢复身份的连续性边界。 避免使用：单条聊天、进程

                Turn（轮次）： 由一个外部输入或恢复事件开启，直到 Harness 交还控制、暂停或终止的一段运行。 避免使用：单次模型请求

                Step（步骤）： Turn 内一次模型决策及由此产生的零个或多个行动与观察反馈。 避免使用：Turn、用户任务

                Action（行动）： 模型提出、由 Harness 校验并执行的外部效果请求，例如工具调用或文件修改。 避免使用：Observation、模型文本本身

                Action Authorization（Action 授权）： 把规范化 Action、Actor authority 与 policy context 归约为 allow、ask 或 deny，并保存该决策适用范围的边界。 避免使用：审批 UI、审批者身份、执行隔离

                Approval Mediation（审批协调）： 维护 ask 决策产生的待决请求，从呈现、响应到超时、撤回、恢复和单一终态。 避免使用：授权规则本身、弹窗、任意用户输入

                Approver Identity（审批者身份）： 决定哪个 principal 或 credential 有权回答待决请求，以及控制租约、委派和竞争响应怎样生效。 避免使用：看到提示的人、Session owner 字段、审批协调

                Observation（观察）： Harness 将行动结果、环境变化或控制事件规范化后反馈给后续决策的信息。 避免使用：原始日志、Artifact

                Context Snapshot（上下文快照）： 某个 Step 实际提交给模型的有序输入集合，来自指令、会话历史、检索结果、工具反馈与压缩产物。 避免使用：Session 全历史、长期记忆

                Tool Output Retention（工具输出保留）： 决定历史 Observation 以原文、裁剪结果或显式占位符进入后续 Context Snapshot 的投影策略。 避免使用：Transcript 删除、UI 折叠

                Semantic Context Snapshot（语义上下文快照）： 从一段历史提炼出的、带来源范围和有效性状态的模型可见继续状态。 避免使用：事实源、长期记忆

                Context Representation Degradation（上下文表示降级）： 把高成本 Context 节点替换为更便宜且明确标记的表示，并说明原内容能否重新取得。 避免使用：语义摘要、无提示删除

                Context Lineage（上下文血缘）： 模型可见节点与其所替换、裁剪或抽象的原节点之间的来源关系。 避免使用：Session 血缘、代码 provenance

                Long-term Memory（长期记忆）： 由 Harness 选择性写入、跨 Session 召回，并可更正或遗忘的知识状态。 避免使用：项目指令、当前 Session 摘要

                Execution World（执行世界）： 文件系统、进程、终端、语言服务与网络等能力所共同观察和修改的工作环境边界。 避免使用：仅指容器、仅指 Shell

                Execution Placement（执行放置）： Action 与某个宿主机、容器、虚拟机或远端 Execution World 的身份绑定及其可达生命周期。 避免使用：执行隔离、进程连续性

                Execution Isolation（执行隔离）： 对 Execution World 中的文件、进程、网络与凭据效果施加强制边界，并对启动、降级、违规和 teardown 给出可观察终态。 避免使用：Action 授权、容器这一放置标签、远端执行

                Process Continuity（进程连续性）： 多个 Action 是否寻址同一执行会话，以及 cwd、环境、PTY 和进程树跨越哪些边界继续存在。 避免使用：持久文件系统、远端放置

                Checkpoint（检查点）： 可用于比较、回退或恢复的命名运行状态，可能覆盖工作区、会话或两者。 避免使用：自动等同于 Git commit

                Goal Evidence Protocol（Goal 证据协议）： 规定 Goal 何时可以声明 complete 或 blocked、声明必须附带哪些结果与证据，以及预算和外部恢复怎样改变终态。 避免使用：任务清单、主观完成感、任意测试命令

                Work Topology（工作拓扑）： 组织 Work Item 的 identity、dependency、claim/lease、join 与结果归属，不指定由哪个 Actor 或进程执行。 避免使用：Actor 树、Session 分支、后台进程列表

                Actor Delegation（Actor 委派）： 建立 parent/child Actor 身份与血缘，并显式传递 Context、模型、authority、消息、取消和返回边界。 避免使用：Work Item 依赖、普通函数调用、后台 Job

                Background Job Lifecycle（后台 Job 生命周期）： 让发起调用返回后仍运行的工作具有稳定 Job identity、owner、status、output cursor、wait、cancel 与唯一终态。 避免使用：child Actor、Work Item、未等待的匿名进程

                Artifact（产物）： 一次运行对外保留、可检查或可交付的结果，例如 Patch、报告、日志或 Pull Request。 避免使用：Observation、临时工具输出

                Artifact Delivery（产物交付）： 把 Artifact 内容或带 provenance 的稳定引用发布给父 Actor、用户、客户端、CI 或 evaluator 的边界。 避免使用：最终完成声明、临时路径

                Control Plane（控制平面）： 客户端通过命令、事件、会话寻址与取消语义驱动 Harness 内核的协议边界。 避免使用：MCP、UI、Agent Loop

                Durable Transcript（耐久 Transcript）： 由 Session 持久化层确认、跨进程可读并用于重建历史的交互事实源。 避免使用：在线事件流、聊天导出

                Live Event Stream（在线事件流）： 运行中的 Harness 向当前订阅者发布增量状态和明确终态的结构化事件序列。 避免使用：耐久 Transcript、批量日志导出

                Replay Projection（重连投影）： 从事件或快照归约出的有界客户端状态，带覆盖位置、完整性和接入在线流的边界。 避免使用：Action 重执行、模型上下文压缩

                Telemetry Export（遥测导出）： 把运行信号按采样、聚合和脱敏策略发送给 operator 或观测后端的过程。 避免使用：Session 事实源、评测结果

                Evaluation Trajectory（评测 Trajectory）： 把任务、运行锚点、Action/Observation、终态和评分组织成可比较的版本化样本。 避免使用：任意日志、可恢复 Session
