                Harness Wiki

                Harness Wiki 研究 AI 编码 Harness 如何把模型、上下文、工具、策略、执行环境和运行状态组织成可工作的 Agent 系统。核心内容按机制原语组织，不做产品功能排行榜。

                文档站点：Harness Wiki。

                机制地图

                四个 Theme 共包含 35 个正式 Primitive。另有执行环境、放置与连续性、权限、审批与隔离边界、任务、目标与多 Actor 编排和运行记录与回放边界四个协调指南；它们只串联相邻 Primitive，不重复计数。完整逐页入口见机制地图。

                三条互相回链的阅读路径

                第一次阅读先用共同语言和设计精髓总览建立最少术语，再按总览指定的 mini-SWE-agent → aider → Pi → DeepSeek Harness → Loopal 具体路线形成直觉，随后回到同抽象比较并进入 Primitive 或 Situation。Primitive 页解释机制原理、边界和多个实现，Harness 页保存版本化画像和反向索引。所有正文都提供上级导航、关联阅读和对向链接，方便在机制视角与产品视角之间往返。

                一句话边界

                • Harness 是拥有 Agent Loop、上下文、工具执行与运行状态等语义的宿主，不等于模型本身。
                • Primitive 是可以被具体定位和横向比较的最小稳定机制，不等于产品 feature 名。
                • Situation 用具体触发和状态变化显露实现差异，不等于“是否支持”的勾选项。
                • Implementation 必须绑定研究锚点和一手证据；absent 与 unknown 严格分开。

                完整范围、语料策略与阶段门槛见 GOAL.md。

                站点开发与发布

                站点使用 Astro 与 Starlight，根目录和 docs/ 中的 Markdown 是内容源。构建时生成页面、全文搜索与图表，原文的相对链接会转换为站内链接。研究锚点与核验日期继续由每篇文档声明，站点发布时间不改变证据版本。

                pnpm dev 默认监听 127.0.0.1:4321，文档变化会重新生成内容并重启预览。浏览地址为 /harnesswiki-site/。生产构建的搜索和图表通过 pnpm preview 检查；本地浏览器测试使用 Chrome，CI 使用 Playwright Chromium。

                main 的每次推送触发 GitHub Actions。文档、生成内容与浏览器检查通过后，工作流只把 dist/ 发布到独立的 redreamality/harnesswiki-site 仓库；研究源码仓库保持私有。发布使用专用的 PAGES_DEPLOY_KEY，飞书通知使用 FEISHU_WEBHOOK_URL，二者均为 Actions Secret。工作流核对公开站点的 commit 与构建时间后才发送通知；部署或验证失败不会发送成功消息。

                2026-10-24 首次运行时，GitHub 因账号账单或支出额度限制拒绝启动私有仓库的 Actions。此时可在已登录 GitHub 的本机环境中设置 FEISHU_WEBHOOK_URL，运行 pnpm site:publish。该命令要求 main 的已跟踪修改已提交，执行同一套检查，只推送生成文件，并在核对公开版本后发送通知。公开 Pages 的部署已验证可用；解除账号限制前不能把私有仓库工作流视为已运行成功。
