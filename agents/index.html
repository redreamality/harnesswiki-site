全局维护规则

Section titled “全局维护规则”
  • 本文件硬上限为 100 行；每次新增规则前必须先合并同类项、删除重复或过期内容，若将超限则先压缩再写入，禁止只追加不整理。
  • 只保留可复用的“触发条件/根因/正确动作”，具体事件、一次性路径和冗长示例应归并为通用表述。

研究与版本演进

Section titled “研究与版本演进”
  • 开始研究、复核未知机制、分派子 Agent 或迁移版本前，先读研究方法；按并行研究队列认领独立文件，协调者统一维护索引、合并、验证与发布。
  • 每轮先拉最新代码：主仓库在可快进时 git pull --ff-only，相关上游执行 pnpm research:refresh -- <harness-id>，成功后固定本轮 SHA；拉取失败标记 blocked，不用缓存冒充最新。保留旧 Claim/gitlink，迁移必须逐条比较。
  • 更新研究时同步维护 changelog/，区分稳定发布、预发布、默认分支与画像锚点，记录重大迭代的前后契约、源码证据和受影响页面；“大版本”含有证据的架构代际，不只看版本号。

PowerShell、路径与运行时

Section titled “PowerShell、路径与运行时”
  • 读取或检索前先 Test-Path；多 Agent 环境中旧路径快照不可信，读取前需重验。不得向 rg 传不存在的候选目录或未展开的 *；Markdown 用 -g '*.md'。-g 等所有选项必须位于 -- <pattern> 之前，-- 后只放 pattern/path；以 - 开头的 pattern 必须使用该分隔符。look-ahead/look-behind 需加 --pcre2，否则改为两步过滤；Windows 路径过滤兼容 [\\/]。PowerShell 单引号 pattern 不要再按 JavaScript 规则双写反斜杠；多条件优先多个 -e 或 -F，避免过度转义造成未闭合分组。
  • rg/git grep 退出码 1 表示零匹配，git diff --no-index 的 1 表示有差异；“应不存在”类检查必须显式规范化退出码并校验输出，不能把零匹配当故障或充分证据。
  • PowerShell 禁止 foreach (...) { ... } | ...；即使循环内构造的对象属性含 if 表达式也一样。先用 $rows = @(foreach (...) { ... }) 收集，再单独管道输出，发送命令前检查不存在 } |。
  • 含 Markdown 反引号的正则用单引号，逐行正则兼容 CRLF（\r?$）；变量后接冒号写 ${name}:。functions.exec 传 PowerShell 时，普通 JavaScript 字符串中的 Windows 反斜杠必须双写；长命令可用 String.raw，但其中不得直接嵌入 PowerShell 反引号，换行改用 [Environment]::NewLine；需传 ${name} 时避免 template literal 提前插值。
  • 处理 MatchCollection 等复杂对象时在首次显式循环中解析和计数，并设置 $ErrorActionPreference = 'Stop'，避免非终止错误以退出码 0 伪装成功。用 [regex]::Split 按 Markdown 标题分块时会额外返回首个标题前的序言；结构检查优先用 Matches 捕获带标题的完整块，或显式跳过首段，不能把序言当成缺字段的正文块。
  • 根目录相对文件不要把空的 Split-Path -Parent 传给 Join-Path，应从 Get-Item 的绝对 DirectoryName 解析；Copy-Item -LiteralPath '*' 不展开通配符，复制目录内容需先枚举明确路径。
  • 删除源码/配置优先用 apply_patch；物理删除目录前核对绝对目标，再同一 PowerShell 进程调用 [System.IO.Directory]::Delete。删除异常后重新枚举剩余树，诊断前再次 Test-Path；研究临时文件无需为收尾强删，删除被策略拒绝时保留并记录即可。
  • 查询可选进程时先枚举再 Where-Object 过滤；终止进程后重新按 PID/父子关系确认，CIM 旧快照或 not found 不能作为仍存活依据。
  • 调用 python/python3/uv python find 前先确认不是 WindowsApps 占位入口，并对发现过程设有界等待；占位时改用已配置的 uv runtime。
  • Node 26 + Windows 下临时 pnpm dlx 转译链挂起不等于测试失败；有界终止并确认无残留后，可用固定版 tsc --noCheck 编译再由 Node 运行。使用 Node 原生 TypeScript 前先查 node --help；需变换语法时直接用 tsc。

Git、外部仓库与证据

Section titled “Git、外部仓库与证据”
  • 第三方仓库地址、默认分支和迁移状态必须从官网、官方文档或已核验 README 确认，再逐个 git ls-remote；无效旧 slug 只证明地址无效，不能证明项目或机制不存在。
  • 避免并发调用大量未认证 GitHub REST API；优先 raw.githubusercontent.com、认证请求或 Git。API TLS/边缘 403 经多客户端确认后停止循环重试，改用更窄 API、官方仓库源码、release、git ls-tree/git show，并区分网络失败与零证据。
  • 抓取论文或数据文件前先从 canonical 页面核验版本 URL、状态、章节精确标题与下载规模；大文件分批且设置有界等待。JSONL 的 Range 片段未覆盖首个完整换行记录时不得解析，抓取/解析失败只算取证失败，不能据此推断内容不存在。
  • 检索外部仓库前先用 rg --files 或 git ls-tree -r --name-only <commit> 定位精确路径，不得按生态、模块名猜 manifest 或源码路径；根树枚举不要传空 pathspec。
  • --filter=blob:none partial clone 禁止对全仓执行 git grep；先列路径，再逐个 git show <commit>:<path>。clone/checkout 返回 session_id 时持续轮询到终态；远程物化失败（如连接重置）后不得继续枚举目标目录，只有命令成功且重新 Test-Path 通过才能读取。
  • submodule 检查先区分 .git 目录与 gitfile；仅缺 registration 时 git submodule init。比较 .gitmodules 与 origin 前规范化末尾 .git//，并分别核对 HEAD/gitlink 与 shallow 状态。
  • 浅克隆读取旧提交前用 git cat-file -e <sha>^{commit} 验证，缺失时只定向 shallow fetch。文档固定 SHA 必须从 gitlink/仓库机器读取并验证，不得手抄。
  • gh repo view 探测预期可能不存在的仓库时，应识别 Could not resolve to a Repository 并把该分支规范化为成功。
  • .git/index.lock 可能由 Codex 状态扫描持有；不得删除仍被 Git 使用的锁。对显式路径的 git add/非交互 git commit 仅在明确锁竞争时有界重试，其他错误立即停止，不能把 Test-Path 预检查当原子保证。
  • 大量 submodule 导致 status 进程堆积时，不要无限延长等待：按完整命令行识别只读 status，设置本仓库 diff.ignoreSubmodules dirty，仅终止精确匹配进程；系统无 git.exe 且 0 字节锁时间戳稳定后才可判定 stale lock。
  • git update-index --refresh 因 CRLF/filter 报 needs update 时，先比较工作树、index、HEAD hash；三者一致可对明确文件执行普通 git add 刷新 stat，并确认 staged diff 为空。

编辑与项目校验

Section titled “编辑与项目校验”
  • apply_patch 不得在同一 patch 对同一路径同时 Delete/Add；整文件替换用 Update，确需重建则拆开。多文件 patch 不留空 @@；并行编辑导致上下文失效时重读并缩小 hunk，不得用旧上下文整文件覆盖。
  • Markdown 不用行尾双空格强制换行，改用 <br>；新建或整文件替换只保留一个终止换行，提交前运行 git diff --cached --check。临时文件用 git diff --no-index 检查时先规范化 0/1，再匹配具体 whitespace 错误。
  • Primitive 新增 Harness Implementation 时，同步更新 Harness 画像反向索引；双向约束只适用于本地 Corpus 画像，external-only 实现不要求 backlink。
  • Wiki 新增根级非 Markdown 链接时同步更新 scripts/check-wiki.test.mjs fixture 复制清单；新增全局 checker/Corpus 画像时同一步修复全量关系与 fixture，并从 staged index 隔离运行 pnpm wiki:test，不能只跑 pnpm wiki:check。新增测试先单跑定位自身失败；多 Agent 共享工作树的全量失败按文件归属区分，等待相关编辑落盘后再最终复验。
  • 结构校验只检查稳定字段、链接关系和章节契约，不要把自由文本措辞硬编码为唯一合法表达。
  • TypeScript 7 + Vite 的 CSS side-effect 导入需在 src/vite-env.d.ts 引用 vite/client 并声明 *.css；Node 配置的 allowImportingTsExtensions 仅与 noEmit、emitDeclarationOnly 或 rewriteRelativeImportExtensions 配套。
  • 升级 lucide-react 后先查当前类型声明中的实际导出，不得沿用记忆中的旧图标名。
  • Playwright 控件可访问名称随状态变化时，操作后按新名称重新定位并断言 aria-expanded；修改交互细节必须增加对应 e2e 测试。
  • read_thread 的 turnLimit 最大为 10；更多历史使用 cursor 分页。
