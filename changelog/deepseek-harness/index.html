第二轮：旧行为到当前默认分支

Section titled “第二轮：旧行为到当前默认分支”

比较 99f6f02fecdb7dff40c3fbc9470f5907c29f74ca 与 22ddee3792402c3e70ec5f86a63c3e3e895a2f60。新 commit 时间为 2026-10-23T19:48:59+08:00。git ls-tree 确认三个路径仍存在，逐项 diff 和 blob 见新源码证据。

机制 旧行为版本 当前源码契约与迁移代价
未完成工具恢复 单个 interruptedTurnClosers 扫描日志 抽出 ToolCallRecovery 与支持 interrupted/forked 的 openTurnClosers；step 关闭时清除 pending，只有同 turn/step 的 append result 才消除 pending。fork 文案明确父会话可能已在分叉后执行，不能据缺少 call 直接盲重试
合成工具结果格式 role: user，content 内嵌 tool-result 块 role: tool，toolCallId/isError 位于 message，content 直接保存文本；新旧真实恢复输出均核实此变化，消费旧块结构的读取器需要迁移
模型投影 replacement 采用 start/end，基础消息派生 改为 startSeq/endSeq；增加插件 message projection 与 projectedMessages、内容代际；重放需要相应解释器。来源仍须覆盖全部被遮蔽节点
压缩输入 从 header 读取 system，直接读取 events 从首个 system/message 构造摘要输入；自动选区跳过 system head；经 seq/eventAt 读日志，旧 Session 适配器必须补接口
摘要失败与计价 单次 summarize；使用 tokens 记录及判断缩减 失败先检查选区稳定性，再调用 recover，成功时重新准备后重试；记录 heuristicTokens，缩减判断用 route tokens，旧 meter 需补字段
异步提交保护 selected-span 与 whole-surface 分开 两种检查仍在等待后、提交前执行；恢复重试新增一次稳定性检查。此结论为 implemented，不把旧版候选实测自动迁移

当前固定来源：repair、surface、region。这是两个端点的机制差异，不宣称已经找出每项首次引入的 commit 或 release。

第二轮执行 node scripts/research/deepseek-boundary-probe.mjs --latest，独立运行证据保存新 SHA 的外部效果计数、真实恢复与投影重载结果。旧输出未覆盖。压缩加载受新版依赖阻塞，未执行新 SHA 的异步摘要或两次压缩；没有用替身替换该模块后宣称通过。部分修复仍是完整记录前缀真实落盘、重读、补齐，不是第二次杀进程。

第二轮发布核验

Section titled “第二轮发布核验”

一次官方 releases?per_page=5 查询成功，返回首项 dsh-v0.2.1-rc.3，发布时间 2026-10-23T15:26:39Z，prerelease=true；后续为 rc.2、rc.1、alpha.5、alpha.4，均为预发布。原始响应字段与发布说明保存在新源码证据中。协调者随后在 2026-10-24 独立查询官方 tag ref，确认类型为 commit，目标为 1f81c047fc48fa190a683e469daa699857e9afe8。它不同于本轮默认分支 SHA；没有在该 release SHA 运行探针，也没有遍历完整稳定版历史。

rc.1 发布说明提及极简模式自动压缩与 /compact，这属于发布方 documented 声明；不据此为上表每个内部机制指定首次发布版本。旧 rc.7 的 tag/commit 证据仍单独保留。

已落地的三个机制节点

Section titled “已落地的三个机制节点”

以下日期是固定提交中官方设计记录的主题日期，不是精确首次合并日期或 release 日期。记录内容可能在主题建立后继续维护；“此前问题”采用官方记录的叙述，没有假装实跑更早版本。这三个节点均早于旧画像锚点。

设计节点 官方记录中的此前问题 固定源码确认的机制 收益与代价
2026-06-18：日志与模型投影分开 插件依赖监听器顺序改写请求，没有统一耐久记录说明替换了什么 surfaceOp 以当前位置替换区间，sourceEventSeqs 覆盖被遮蔽节点；原记录保留 可重建模型历史、追溯替换；原日志大小不会随上下文预算一起缩小，模型仍看不到被遮蔽原文
2026-07-21：语义持久化边界与未知终态分类 只有 turn 末尾 checkpoint，长调用中断可能丢失执行意图；统一中断错误无法区分是否开始 checkpoint policy 在工具体前 flush call；修复区分 TOOL_NOT_STARTED 与 TOOL_OUTCOME_UNKNOWN 保留调用意图，避免将未知解释为可直接重试；增加 flush 边界，外部效果仍需查询或业务幂等键
2026-07-30：手动压缩与统一耐久锁 摘要等待期间用户输入可能唤醒 loop，进程内布尔锁难以解释崩溃日志 runMaintenance 保留 idle 维护边界；事务先写 start，再 await、复核、提交、end；手动选区与自动全投影稳定性分开 失败尝试可审计，手动压缩允许选区外注入；多出 busy/changed/summary/commit/persistence 等失败处理，不能把摘要完成等同于可提交

各节点的一手来源与本轮支持范围：

  1. Session surface 官方记录和 surface.ts支持 implemented。本轮两次压缩、磁盘重载和缺血缘拒绝为 observed。关联上下文血缘与耐久 Transcript。
  2. Semantic session checkpoints 官方记录、checkpoint policy与 repair.ts支持机制。新探针只实跑修复函数及可控外部写入，不冒充 policy 的端到端覆盖。关联状态持久化与恢复及旧实验。
  3. Queued manual compaction 官方记录、region.ts与入口参数选择支持机制。本轮真实事务的三种候选结果为 observed，维护期间真实用户输入排队仍未实跑。关联上下文压缩。

这些是改变状态归属、恢复协议和并发提交条件的机制演进，不是三个 major release，也不是 rc.7 才引入三个机制的证明。

本轮增加的行为证据

Section titled “本轮增加的行为证据”

最终探针退出码 0，机器证据保存实际执行时间、环境、源文件 blob 和断言结果。

  • 外部服务已确认写入，日志生产进程被杀后只有 call 无 result。真实修复函数产生 unknown，完整及部分修复重复执行不重复生成 result；服务计数维持 1，故意盲重试后为 2。
