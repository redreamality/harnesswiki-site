                  Mistral Vibe 版本差异

                  导航：Changelog 索引 · 画像 · 本轮取消与 checkpoint 研究

                  核验日期：2026-10-24。本页比较旧画像 SHA 与本轮抓取的 main SHA，不将默认分支实验写成 release 实测。

                  版本与发布核验

                  角色 固定版本 日期与核验来源
                  旧画像 baseline / 保留的 checkout v2.24.2，5e6aa0f6beb3454454f4c1de74a7652ba577ab05 本地 refs/tags/v2.24.2、HEAD 与画像一致；画像快照日期为 2026-08-19，不将它冒充 GitHub 发布时刻。
                  本轮官方最新正式 release v3.0.2，36f7b3a4e10440e90f98080492530b8f4d46960d 官方 GitHub releases/latest 返回 published_at=2026-10-22T15:34:08Z、draft=false、prerelease=false；官方 tag ref 的 object.type=commit 且 SHA 一致。
                  本轮默认分支行为锚点 main，63d0e8f17e2c1f0d9e1d6f4399ab2dc10fbdf477 refresh 成功记录 fetchedAt=2026-10-24T05:10:07.403Z；提交时间为 2026-10-22T22:42:29+02:00。

                  发布来源：官方 release、latest API、tag ref API。API 的 latest 是会变化的发现入口；上表保留了本轮响应值，release commit 固定为 36f7b3a…。本轮 main 的 pyproject.toml 虽同样声明 3.0.2，SHA 并不相同。

                  刷新首次连接失败，唯一一次重试成功。另一次 ls-remote --tags 连接失败，release/tag 核验改用上述官方 API 成功响应；没有把失败解释为不存在 release。未 checkout release，也未修改旧画像或 gitlink。

                  三项关键迭代

                  1. 旧 turn controller 已被 Unified session 路径取代

                  旧画像的 _turns.py 以 active task 管理 turn；旧 _sessions.py 在 subagent runner 的取消分支中断 child 并等 completion。本轮固定树已删除这两个文件，新入口由 adapter 转给 Unified session。

                  新 session 校验目标 turn、持有生命周期锁，并在提交 runtime interrupt 前取消活动工作。其取消逻辑存在等待任务和已终态任务转入 settling 集合两种分支。因此旧画像的取消返回时序需要逐 Claim 重新验证。

                  版本背景为固定 main 中的 官方 CHANGELOG：3.0.0 条目日期为 2026-10-15，并记录 Unified execution 的配置变化。路径迁移由两端源码和树比较证明，不把所有删除都归因于某个未经 bisect 核实的单一 release。

                  2. 子代理命令与等待接口分开，并增加可恢复回执

                  旧路径通过 runner 等待 child completion；新 controller 为 interrupt 保存目标 turn/generation 与命令回执，调用 child 后确认并记录结果。批量中断入口明确不等待所有 child settled，不能把回执完成等同于所有资源静止。

                  同一固定 SHA 的 CHANGELOG记录：3.0.0 将 subagent.* 工具命名迁到 agents.*，3.0.1 增加 experimental session/subagents/wait、interrupt、read，3.0.2 增加并发数量配置。具体兼容分支仍可在 controller 的分发代码核对；这不是旧 Task tool 接口的简单改名。

                  3. 文件快照改由 Unified effect/history 驱动，恢复仍是逐文件尽力执行

                  旧 recorder.py 已删除。新版 RewindFileSnapshots观察公开状态与文件 effect，重建文件改动前的内容，再由 checkpointer 生成恢复计划。in-place rewind先裁剪会话，再恢复文件并返回逐文件结果。

                  两端 FileStore 旧版与新版的 Git diff 为空。此次发现的部分恢复和并发覆盖窗口，不能描述成 3.0 新引入的回归；变化主要在快照采集和上层调用链。

                  验证范围

                  本轮在 main SHA 上运行真实取消辅助函数、进程树终止函数与 checkpoint 文件恢复模块，结果和复现命令见研究稿。没有执行 release SHA，也没有完整构建或启动 Unified 会话。父子取消端到端、所有 background process 的静止、跨文件恢复事务与崩溃一致性仍未闭合。
