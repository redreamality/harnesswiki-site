OpenCode 谱系与 owner 迁移边界

Section titled “OpenCode 谱系与 owner 迁移边界”

本轮固定 README明确称 Kilo CLI 为 OpenCode fork。旧 v7.4.22 发布说明记录吸收 OpenCode v1.17.13 → v1.18.0，以及 v1.18.1 至 v1.18.13 的更新。这是共享核心演进的一手谱系证据；本轮没有逐提交重建更晚的全部上游同步区间，也没有把它外推到旧 VS Code 扩展的历史。

当前记忆文件、索引和删除由 packages/kilo-memory 拥有；CLI adapter 负责项目 context、事件和模型接入，Session prompt 层拥有 pinned cache。执行隔离由 CLI policy 调用独立 packages/kilo-sandbox，持久进程仍由 CLI kilocode/background-process 拥有。具体接线见研究页 owner 表。

这些 package 边界在旧 baseline 已存在。本轮不声称完成了“从 OpenCode 全部迁出”的新架构代际；继承的基础核心继续归同一 Family。下面只记录两个固定 SHA 之间实际改变的契约，均为 implemented 静态比较，不声称某项首次出现于 v7.8.17，也不把 7.4 → 7.8 写成官方 major release。

Windows 持久进程从进程表追踪增加 Job Object owner

Section titled “Windows 持久进程从进程表追踪增加 Job Object owner”

旧 runner依赖进程表遍历，stop 使用 taskkill /t。新版先让 runner 加入 Windows Job Object，再创建命令，后代进程从出生起属于该 Job；只有 Job 不可用时才降级为进程表追踪。新增 Windows owner · 新版启动与降级

新版降级遍历将 PID 和创建时间一起核验，避免把复用 PID 的无关进程认作后代；降级 stop 只处理已核验对象，不再把未经校验的子树交给 /t。Job 已分配后的 query/kill 故障则保留 Job owner，不临时换成遍历。创建时间核验 · Job 与 fallback 收尾

收益是 detached grandchild 与 PID 重用有了更明确的归属依据。代价是平台 native API、状态探测和失败收尾更复杂；fallback 30 秒仍无法确认时报告失败，不能保证没有遗留后代。上游新增 Job 故障测试和 PID 重用测试。本轮未运行这些测试。

同一模块还把普通进程的完成判断改成优先等 stdio close，exit 后设置 500ms drain 上限，避免丢失尾部输出或被继承管道的后代无限拖住。这是记录终态的变化，不是“500ms 后所有后代已死”。新版退出处理

Sandbox 对 Git 状态修改的分类更细

Section titled “Sandbox 对 Git 状态修改的分类更细”

旧 Git 分类器对 branch/tag 主要依赖是否出现若干读取参数；stash 被整体归为修改。新版明确列出读写 flag、消费参数值、展开短参数组合，并分别处理 remote、stash、worktree、reflog、notes。新版分类器

例如 git stash list 与创建 stash 走不同分类，git worktree list 与修改 worktree 也被区分。收益是更准确地区分只读查询与需升级权限的 Git 状态修改；代价是维护 Git 命令参数语义。分类器并非完整 shell 安全证明：直接 mutates 遇到复合 shell 字符会返回 false。实际 Shell 调用方从语法树枚举 command node 后逐个分类，在 sandbox 路径发现 Git mutation 时请求 sandbox_escalation；执行阶段再消费批准标记。Shell 授权调用 · 执行入口 · 上游分类测试

本轮未执行 Git escalation 或安全攻击测试。相关 profile 还新增 browser broker URL/token 环境过滤，属于凭据暴露面的收紧，不能外推为“所有凭据安全”。环境过滤

没有变化但补足的证据

Section titled “没有变化但补足的证据”

新旧 memory.ts、storage/paths.ts、capture/operations.ts、storage/fs.ts 与 sandbox backend.ts 的 Git blob 相同。因此本轮的“跨 worktree 共享”“correct 不撤销所有旧事实”“forget 保留旧 digest”“启用 sandbox 后 backend 不可用则拒绝执行”，是对既有机制的补充核验，不是这段版本区间的新功能。

运行 bun scripts/research/kilo-memory-probe.mjs，八项无模型模块实验全部通过：实际验证项目 scope、纠正并存、精确删除后的摘要残留、自动 remove 过滤、同 key 更新、索引失效和两种 purge 归属情况。完整环境、输入与限制见本轮实验。

记忆采集 adapter 在此区间新增了 sessionID 向模型调用的传递；它不改变上述存储契约，也不足以称作记忆 scope 迁移。模型 port · 采集调用

本轮只比较旧画像与刷新后的默认分支，并核对相关目录与最新 release 的关系。没有归档全部历史 release、定位每项改动的首次发布、验证发布二进制，或重跑完整 CLI/IDE 测试。共享核心不能作为独立 Family 重复计票。
