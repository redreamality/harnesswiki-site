                  Harness 版本演进

                  导航：首页 · 研究方法 · 并行研究队列 · Harness 画像

                  这里研究各 Harness 怎样迭代运行机制。关注一次升级怎样改变状态归属、失败行为、恢复协议和使用代价，而不是复制功能更新清单。

                  记录范围

                  每篇时间线区分旧画像锚点、本轮拉取的默认分支、官方稳定发布和预发布。默认分支 SHA 是观察时的源码状态，不能自动视为已发布产品。官方 major release 与没有主版本号的架构代际分开标注。

                  首次并行研究覆盖 Qwen Code、Mistral Vibe、DeepSeek Harness、Stakpak Agent、Refact 与 Kilo Code。六组均取得本轮默认分支 SHA。DeepSeek 首轮直连失败后，协调者确认系统代理未被 Git 使用，换用已验证连接方式完成新一轮刷新；历史失败与旧版本实验仍分别保留。

                  阅读版本记录

                  Harness 本轮版本比较 研究入口
                  Qwen Code 旧画像到刷新主干的控制面拆分、按 prompt 取消与慢消费者表示降级 审批竞争与回放边界
                  Mistral Vibe 2.x legacy 到 3.x Unified 的取消命令、回执和快照采集变化 取消、进程静止与 checkpoint
                  Stakpak Agent 画像与本次主干相同；另比较稳定 tag 到主干的调度与通知变化 暂停恢复与 Skill 重载
                  Refact 有效历史、verifier 分类、merge override 与 workspace lease 的迭代 Goal 证据和任务所有权
                  Kilo Code Windows Job Object owner 与 Git 修改分类变化；区分没有变化的记忆存储契约 记忆遗忘与执行隔离
                  DeepSeek Harness 历史设计节点与当前恢复、工具消息、投影字段和压缩重试的变化 新旧锚点恢复、投影与压缩研究

                  先看锚点表，确认两个版本是否可比较；再看前后契约、源码证据和已运行实验。每篇都应指出本轮没有覆盖的历史区间。全量 tag 清单不能替代机制比较，也不要求每次研究遍历所有历史 release。

                  研究方法中的版本演进记录规定持续维护方式；当前任务与验收状态见并行研究队列。
