                  发布文案与实现分开

                  documented：v0.26.0 发布说明写明没有已知 breaking changes，并列出 Session 定向 Skill/Extension refresh 等功能。这是该 release 的发布方描述，不是本轮探针结果，也不能证明后续 main 的全部行为兼容。

                  下面三项为旧画像提交与新默认分支提交的源码对照，类型为 implemented。没有逐个审计中间 release，因而不声称某项首次出现在 v0.26.0。

                  三项已确认变化

                  控制面主体从 bridge 入口分离

                  旧版 bridge.ts直接构造 mediator，订阅包装也在同一文件。新版 bridge.ts只把 createSessionControlPlane 与 createChannelHarness 组装起来，并保留旧工厂名的兼容别名。

                  当前审批接线在 session-control-plane.ts，snapshot 与 replay 的衔接在同文件订阅入口。这是实现组织和组合边界的变化；本轮没有据此推断新增了进程隔离或强身份认证。

                  审批新增按 prompt 取消

                  旧 mediator 的Session 级取消会取消该 Session 的全部 pending。新版保留此入口，另增加 cancelForPrompt(sessionId, promptId)，只筛选匹配二元组的请求，结果是 agent_cancelled。

                  收益是后台通知 Turn 收尾时不必连带取消同 Session 的用户审批；代价是请求的 prompt 归属必须正确。当前 BridgeClient将归属写入 request record。本轮探针观察到取消后台 prompt 后，用户请求仍可批准；没有运行完整后台通知流程。

                  慢消费者可先丢弃 MCP App HTML

                  旧 EventBus fan-out直接将原事件交给队列。新版为 queue push 增加降级函数：当已有 live 积压、下一帧将超出字节预算时，若它是带非空 fallbackText 的 MCP App，则尝试清空可选 HTML、保留文字。具体筛选见 mcpAppTextFallback。

                  降级后仍要通过字节上限；帧数上限也不取消。健康消费者直接接收与 ring 历史仍保留原事件，因此同一 id 的 live 慢端表示与 replay 表示可能不同。空 live 队列允许第一帧超预算且不降级，见队列分支。本项只有 implemented，没有冒充 HTML 降级实测。

                  实验与未决项

                  执行 node scripts/research/qwen-boundary-probe.mjs，12 组通过，退出码 0。真实 mediator 在六种 vote/timeout/close 顺序下各产生一个终态；真实 EventBus 在 ring 缺口后继续提供 live，历史 forced 帧不占用 live 配额，慢端 eviction 不阻塞健康端。完整输入、输出摘要和环境见研究页。

                  本轮只做两个提交的局部比较。中间 release 的首次引入时间、真实网络竞争、完整 SDK resync、字节超限降级和 daemon 重启仍未验证。旧画像与旧行为实验保持原锚点，不能把本页新结果倒填为旧版本事实。
